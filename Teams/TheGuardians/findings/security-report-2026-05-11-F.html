⛔ Grade F — Confirmed Critical Breach. The compliance pass rate is ~19% against OWASP-ASVS L2 and SOC2-Type2, far below the 60% floor required even for a grade C. This codebase must not be exposed on a shared or externally reachable network until authentication and authorization are implemented.

2. Consolidated Findings

Critical Findings (3)

CF-001 No Authentication or Authorization on Any API Endpoint Critical Confirmed (Live Exploit)
Sources: SAST-001 · COMP-001 · COMP-002 · PEN-001 · PEN-002 → Confirmed by RED-001, RED-002, RED-003

app.ts registers all routes with no authentication or authorization middleware. Every endpoint — including POST /api/work-items/:id/approve, /reject, /dispatch, /route, and all intake webhooks — accepts requests from any unauthenticated caller with full privilege. CWE-306 · OWASP-ASVS V4.1.3 (deny-by-default) · SOC2 CC6.1, CC6.2, CC6.3. The red-teamer confirmed this is the root cause enabling all critical chains.

Remediation: Implement JWT bearer-token authentication as the first app.use() call before any route registration. Introduce RBAC with roles viewer, triage-agent, approver, dispatcher, admin. Unauthenticated requests must receive HTTP 401; insufficient-role requests must receive HTTP 403. Machine callers (intake, CI) must use a distinct API-key mechanism.
CF-002 Unrestricted overrideRoute: fast-track Bypasses Entire Assessment Pipeline Critical Confirmed (Live Exploit)
Sources: PEN-003 → Confirmed by RED-001

POST /api/work-items/:id/route accepts a caller-supplied overrideRoute: "fast-track" parameter that causes classifyRoute() to return WorkItemStatus.Approved unconditionally — the assessment pod is never invoked, assessments array remains empty. Red-team confirmed: 3 unauthenticated requests advance any item from backlog → approved → in-progress. CWE-284 · OWASP-ASVS V4.1.2 · OWASP A01.

Remediation: After authentication (CF-001), gate overrideRoute to an ops-manager role. Require that all route overrides emit a mandatory audit event with the approver's identity. Consider removing the escape hatch from the public API surface entirely and implementing a separate privileged override workflow.
CF-003 Unauthorized Cascade Auto-Dispatch via Dependency Injection Critical Confirmed (Live Exploit)
Sources: PEN-007 → Confirmed by RED-003

Any caller can (1) add an attacker-controlled blocker to an approved victim item, (2) reject the blocker, triggering onItemResolved(), which auto-dispatches the victim to in-progress via cascade-dispatcher — bypassing the explicit /dispatch endpoint entirely. Red-team confirmed via changeHistory: agent=cascade-dispatcher | reason: Auto-dispatched after blocker WI-006 resolved. Prometheus counter dispatch_gating_events_total{event="cascade_dispatched"} 1 confirmed. CWE-284 · OWASP-ASVS V4.1.2.

Remediation: After authentication, restrict POST /dependencies (add blocker) to ops-manager role for approved items. Make onItemResolved cascade dispatch emit a notification/approval event rather than directly mutating state. Consider a confirmation step (2-phase commit) before auto-dispatch.

High Findings (3)

CF-004 Intake Webhooks — No HMAC Signature + Enum Injection + Stored XSS High Confirmed (Live Exploit)
Sources: SAST-002 · COMP-003 · PEN-005 · PEN-006 → Confirmed by RED-004

POST /api/intake/zendesk and /api/intake/automated accept arbitrary POSTs with no HMAC-SHA256 signature check. Additionally, type and priority fields are not validated against enum values (unlike the main POST /api/work-items endpoint). Red-team stored priority: "<img src=x onerror=alert(document.cookie)>" and type: "INVALID_ENUM_TYPE" verbatim. If the frontend renders priority without escaping, this is a stored XSS. CWE-345 · CWE-79 · OWASP A03 · ASVS V4.2.2.

Remediation: Verify X-Zendesk-Webhook-Signature HMAC-SHA256 against a shared secret stored in an env variable; use crypto.timingSafeEqual(). Add an API-key header check to /automated. Validate type and priority against their respective enums in both intake routes, returning HTTP 400 for invalid values.
CF-005 Unbounded Pagination Enables Full Dataset Exfiltration High Confirmed (Live Exploit)
Sources: SAST-006 · COMP-008 · PEN-004 · PEN-008 · PEN-010 → Confirmed by RED-002

GET /api/work-items?limit=999999 returns all records with full changeHistory and assessments in a single response. GET /api/dashboard/queue dumps all items across all status buckets with no pagination at all. GET /api/dashboard/activity?limit=999999 returns the full audit trail. Red-team also confirmed edge cases: limit=0 returns all items, limit=-1 returns N-1 items due to JavaScript slice behavior. CWE-400 · ASVS V4.2.1.

Remediation: Cap limit server-side: const limit = Math.min(Math.max(parseInt(q) || 20, 1), 100). Validate !isNaN(limit) and reject negative/zero values with HTTP 400. Add pagination to GET /dashboard/queue. Require authentication before any list endpoint.
CF-006 Missing Required Audit Events + No Authenticated Actor Identity High Theoretical
Sources: COMP-004 · COMP-005

security.config.yml requires login_attempt, permission_denied, state_transition, and data_export audit events. Of these, zero are emitted as structured log events with a consistent eventType field. State transitions are captured only in-memory in WorkItem.changeHistory with generic strings ('user', 'system', 'manual-override') — not authenticated identities. SOC2 CC7.1 · ASVS V7.1.2.

Remediation: After CF-001 (auth), extract authenticated user ID from request context and pass it as agent to buildChangeEntry(). Emit structured log entries with eventType field on every state-mutating operation. For data_export, emit an audit event on bulk data returns. Persist audit logs to an append-only store.

Medium Findings (8)

CF-007 Soft-Deleted Item UUID Disclosure via Readiness Check Medium Confirmed (Live Exploit)
Sources: PEN-009 → Confirmed by RED-005

GET /api/work-items/:id/ready returns unresolvedBlockers including raw DependencyLink objects for soft-deleted blockers (since store.findById() returns undefined for deleted items, which are treated as unresolved). Red-team confirmed: deleted UUID and docId disclosed verbatim. Secondary impact: a soft-deleted blocker permanently strands the dependent item (DoS vector). CWE-200.

Remediation: On soft-delete, automatically remove the item from all dependent blockedBy arrays. Replace blocker UUIDs in the readiness response with an anonymized indicator ("blockerDeleted": true).
CF-008 NeedsClarification Assessment Verdict Silently Bypasses Dispatch Gating Medium Confirmed (Live Exploit)
Sources: PEN-012 → Confirmed by RED-006

runAssessmentPod() maps all non-Approve verdicts (including NeedsClarification) to WorkItemStatus.Rejected. Since Rejected is in RESOLVED_STATUSES, dependents are unblocked — but onItemResolved() is NOT called from assessWorkItem, so the cascade does not trigger. Red-team confirmed: dispatch succeeded on a target with hasUnresolvedBlockers: true after the blocker was assessed to NeedsClarification (stored as rejected). CWE-436.

Remediation: Map NeedsClarification to a distinct status (e.g., needs-clarification). Exclude this status from RESOLVED_STATUSES. Make dispatch gating re-compute live blocker states rather than relying on the cached hasUnresolvedBlockers flag.
CF-009 Missing HTTP Security Headers (helmet not installed) Medium Theoretical
Sources: SAST-003 · COMP-006

No security headers are set on any response: missing Content-Security-Policy, X-Frame-Options, Strict-Transport-Security, X-Content-Type-Options, Referrer-Policy. CWE-693 · ASVS V14.4.1 / V14.4.3 / V14.4.6.

Remediation: npm install helmet and add app.use(helmet()) as the first middleware call. Tune CSP for API context.
CF-010 No CORS Policy Configured Medium Theoretical
Sources: SAST-004 · COMP-007

No CORS middleware is present. Without an explicit allowlist, browsers apply default cross-origin deny — but if a wildcard cors() is added without review, all origins gain access to authenticated routes. CWE-942 · ASVS V14.4.8.

Remediation: npm install cors; configure app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') ?? [] })).
CF-011 Unauthenticated Prometheus /metrics Endpoint Medium Theoretical
Sources: SAST-005 · COMP-009 · PEN-011

GET /metrics exposes Node.js process metrics and custom business counters (workflow_items_created_total, dispatch_gating_events_total, etc.) to any unauthenticated caller. Provides operational intelligence for attack planning. CWE-200 · ASVS V4.1.1 · SOC2 CC6.3.

Remediation: Restrict to localhost (check req.ip), add a bearer token, or bind a separate internal-only metrics port.
CF-012 No Rate Limiting on Any Endpoint Medium Theoretical
Sources: SAST-007 · COMP-012

No rate-limit middleware is present. Unlimited requests per second can exhaust in-memory store capacity and allow brute-force attacks. CWE-770 · ASVS V11.1.4.

Remediation: npm install express-rate-limit. Apply a global 100 req/min/IP; stricter limits on mutation endpoints. Return HTTP 429 with Retry-After.
CF-013 No TLS/HTTPS Enforcement at Application Level Medium Theoretical
Sources: COMP-010

No HTTPS redirect middleware or HSTS header. All future authentication tokens will transit unencrypted unless a reverse proxy enforces TLS. ASVS V9.1.1 / V9.1.2.

Remediation: Enforce TLS at reverse proxy/load balancer. Add HTTP→HTTPS redirect middleware when NODE_ENV=production. Configure HSTS via CF-009 (helmet). Document TLS termination topology.
CF-014 In-Memory Store — No Persistence or Encryption at Rest Medium Theoretical
Sources: COMP-011

All state lives in a JavaScript Map; data is lost on restart and is not encrypted at rest. The in-memory model also makes changeHistory mutable in-place. ASVS V8.1.1 · SOC2 CC6.1.

Remediation: Replace with a persistent database (PostgreSQL recommended). Enable disk-level encryption at rest. Keep the in-memory store only for development/testing.

Low Findings (7)

CF-015 Raw Exception Messages Exposed in Error Responses Low Confirmed (Live Exploit)
Sources: PEN-014 → Confirmed by RED-007

Route-level catch blocks in workflow.ts return err.message directly, pre-empting the generic errorHandler. Red-team confirmed: POST /api/work-items/nonexistent-uuid/route returns {"error":"Work item nonexistent-uuid not found"} — echoes input parameter. CWE-209.

Remediation: Replace route-level catch blocks with next(err) to defer to the global error handler. Return generic HTTP 404 {"error":"Not found"} without echoing the ID.
CF-016 Predictable Sequential Document IDs Enable Enumeration Low Confirmed (Live Exploit)
Sources: PEN-013 → Confirmed by RED-008

generateDocId() uses a module-level counter (WI-001, WI-002, …). Red-team confirmed gaps reveal soft-deletion events and restart history. CWE-330.

Remediation: Use ULID or UUID-derived short codes. Persist counter across restarts if sequential order is required.
CF-017 Debug Portal iframe Missing sandbox Attribute Low Theoretical
Sources: SAST-008

DebugPortalPage.tsx embeds the portal in an unsandboxed iframe. If the portal URL is pointed at an untrusted origin or the portal is compromised, it has full DOM access. Default URL uses http:// — mixed-content risk. CWE-1021.

Remediation: Add sandbox="allow-scripts allow-same-origin allow-forms". Validate portalUrl against an allowlist.
CF-018 Sensitive Field Values Emitted in Change History Logs Low Theoretical
Sources: SAST-009

changeHistory.ts logs oldValue and newValue (typed unknown) at INFO level. Large text blobs or PII-containing fields will be indexed by log aggregators indefinitely. CWE-532.

Remediation: Truncate strings to 100 chars before logging. For fields in security.config.yml sensitive_fields, mask or omit the value.
CF-019 No Input Length Validation + No Explicit Body Size Limit Low Theoretical
Sources: SAST-010 · COMP-013

Presence checks (!body.title) do not enforce max length. A 50 MB title passes validation. Express default body size limit (100 KB) is not explicitly documented or tuned. CWE-20 · ASVS V13.2.1.

Remediation: Add title.length <= 500, description.length <= 10000 checks. Set app.use(express.json({ limit: '10kb' })).
CF-020 Audit Log Lacks Tamper-Evidence (Mutable In-Memory History) Low Theoretical
Sources: COMP-014

WorkItem.changeHistory is overwritten via updateWorkItem() in multiple workflow routes. There is no append-only audit store. ASVS V7.3.1 · SOC2 CC7.1.

Remediation: Move audit events to a separate append-only log store. Remove the ability to overwrite changeHistory through the normal update API. In a database implementation, enforce no UPDATE/DELETE on the audit log table.
CF-021 No OpenTelemetry Instrumentation Despite Architecture Mandate Low Theoretical
Sources: COMP-015

CLAUDE.md mandates OpenTelemetry with W3C traceparent propagation and trace/span ID injection into logs. No OTel packages are present; logs contain no traceId/spanId. SOC2 CC7.1 (monitoring).

Remediation: Install @opentelemetry/sdk-node and @opentelemetry/auto-instrumentations-node. Initialize SDK before Express app. Inject trace/span IDs into logger context.
