1. Executive Summary

Risk Statement: The application has zero authentication, zero authorization, and zero input validation. An unauthenticated attacker can create, approve, deny, dispatch, and permanently destroy every record in the system with no credentials. All four red-team objectives were confirmed in a live ephemeral environment. Grade: F.

Objectives Breached

Top 3 Risks

  1. Zero authentication — Every endpoint publicly accessible. Any attacker reads, creates, modifies, approves, or permanently deletes all records with no credentials. Root cause of 9 of 11 confirmed exploits.
  2. State machine and voting bypass — Three unauthenticated calls push any Feature Request to approved skipping all AI voting, human review, and assessment gates. Vote retrigger farming manufactures desired AI outcomes.
  3. Permanent data destruction + dependency DoS — Unauthenticated DELETE destroys records with sequential ID reuse. Deleting a blocker permanently strands all dependents with no recovery path.

2. Consolidated Findings

Deduplicated across all four specialists. PEN-IDs confirmed by RED-IDs are merged. Confirmed (Live Exploit) = red-team confirmed. Theoretical = static/logic analysis only.

Critical (3)
C-001 Complete Unauthenticated API Access Critical Confirmed (Live Exploit)
Sources: SAST-001 · PEN-001 · COMP-001 · RED-001 | CWE-306 | OWASP-ASVS V2.1.1, V2.2.1 · SOC2 CC6.1, CC6.2

Zero authentication middleware. Every route — CRUD, workflow transitions, intake, Prometheus — accessible to any unauthenticated HTTP client. Live: GET /api/feature-requests → HTTP 200 full dataset; DELETE /api/feature-requests/FR-0059 → HTTP 204. No credentials required.

Remediation: Implement global requireAuth middleware before all route mounts in index.ts/app.ts. Use JWT Bearer tokens with short expiry. This single fix neutralises C-001 through H-005.
C-002 Force-Approve Bypasses Entire Voting Gate (State Machine Bypass) Critical Confirmed (Live Exploit)
Sources: PEN-004 · PEN-005 · COMP-002 · RED-002 | CWE-285 | OWASP-ASVS V4.1.1, V4.2.1 · SOC2 CC6.3

POST /force-approve transitions any item to approved skipping all AI voting and human review. Live: FR with 2/3 DENY majority force-approved via unauthenticated call; human_approval_approved_at set with zero legitimate process.

Remediation: Gate /force-approve and route override behind authenticated HUMAN_REVIEWER role. Log force-approve to immutable audit trail. Require minimum vote threshold even for manual overrides.
C-003 Unauthenticated Hard Delete — Permanent Data Destruction + Sequential ID Reuse Critical Confirmed (Live Exploit)
Sources: RED-005 | CWE-285 · CWE-330

DELETE endpoints permanently destroy records with no auth and no confirmation gate. Sequential IDs reused after deletion — attacker-created records replace deleted ones, hijacking stale references. Live: HTTP 204 → 404 → ID reused by new create.

Remediation: Require authentication (prerequisite). Default to soft-delete (deleted_at); reserve hard delete for elevated admin role. Require ?confirm=true for permanent deletion. Consider UUIDs for externally visible IDs.
High (9)
H-001 Unbounded Pagination — Full Dataset Dump High Confirmed (Live Exploit)
Sources: SAST-003 · PEN-003 · COMP-007 · RED-007 | CWE-20/770

?limit=999999, ?limit=0, and omitting limit all return the entire dataset. Live: 55 FRs returned in a single unauthenticated request including full vote records.

Remediation: const limit = Math.min(parsed, 100) in all list routes. Default 20. HTTP 400 if requested limit exceeds max. Apply to all list endpoints.
H-002 Vote Retrigger Farming — Unlimited Re-Roll (Assessment Bypass) High Confirmed (Live Exploit)
Sources: RED-003 | CWE-799

POST /retrigger re-runs AI voting with no auth, no rate limit, no retrigger cap. Round 1: 2-3 DENY. Round 2: 3-2 APPROVE. Round 3: 5-0 unanimous approve. Attacker loops until desired outcome, then calls /approve.

Remediation: Require auth for retrigger. Rate-limit to max 1 retrigger/FR/hour. Record full vote history across all rounds to detect manipulation. Consider deterministic vote seeding per FR ID.
H-003 Dependency DoS — Deleted Blocker Permanently Locks Dependent High Confirmed (Live Exploit)
Sources: PEN-008 · RED-004 | CWE-672

computeHasUnresolvedBlockers() treats missing (deleted) blocker as unresolved — permanently blocking dependent dispatch. No recovery path. Deleted item's ID leaked via readiness endpoint.

Remediation: On blocker delete, cascade-remove stale dependency links or set deleted items to a resolved sentinel. Fix computeHasUnresolvedBlockers() to treat undefined (not found) as resolved.
H-004 Deny Feature Request Without Voting (Skip Entire Review) High Confirmed (Live Exploit)
Sources: RED-006 · PEN-005 | CWE-285

POST /deny transitions FR directly from potential → denied without voting phase. No auth, no audit record. Live: FR-0060 immediately denied with arbitrary comment.

Remediation: Restrict /deny to authenticated HUMAN_REVIEWER role. Require explicit override flag + audit event for denial from potential. Require at least one vote round before human denial.
H-005 Stored XSS + Unvalidated Enum Input High Confirmed (Live Exploit)
Sources: SAST-002 · PEN-010 · RED-009 | CWE-79 · CWE-20

Title/description fields store raw HTML including <script>, <img onerror>, <svg/onload> verbatim. Intake endpoints accept arbitrary strings for type/priority, poisoning Prometheus label cardinality.

Remediation: Apply server-side HTML sanitization (DOMPurify node or sanitize-html) on all user-controlled text before persistence. Apply enum validation to intake routes. Frontend must use text content, not innerHTML.
H-006 Unauthenticated Intake Webhooks — No HMAC Signature Verification High Theoretical
Sources: PEN-006 · COMP-004 | CWE-306 · CWE-345 | OWASP-ASVS V2.3.1, V4.2.1 · SOC2 CC6.2

Zendesk and automated intake endpoints accept arbitrary payloads without HMAC verification. Any caller can forge Zendesk events or flood the work item queue. Portal analogues confirmed unauthenticated via RED-001.

Remediation: Verify X-Zendesk-Webhook-Signature-256 via pre-shared secret env var. Require bearer token for /api/intake/automated. Enforce rate limits (5 req/min).
H-007 Rejection Cascade Auto-Dispatches Dependents (Business Logic Flaw) High Theoretical
Sources: PEN-007 | CWE-840

DISPATCH_TRIGGER_STATUSES includes Rejected — rejecting a blocker auto-dispatches approved dependents to in-progress even though the prerequisite failed.

Remediation: Remove Rejected from DISPATCH_TRIGGER_STATUSES. Rejected blockers should move dependents to blocked/pending-review, not dispatch them. Separate resolved vs dispatch-trigger status sets.
H-008 Missing Required Audit Log Events High Theoretical
Sources: COMP-003 | CWE-778 | OWASP-ASVS V7.3.1, V7.3.2 · SOC2 CC7.1

Three of four required events absent: login_attempt, permission_denied, data_export. state_transition partially captured in changeHistory but lacks actor identity, source IP, and correlation ID — inadmissible as SOC2 evidence.

Remediation: Implement auditLog() helper with event, actor, resource, sourceIp, traceId, outcome fields. Emit from all workflow handlers. Once auth exists, emit login/permission events.
H-009 No TLS/HTTPS Enforcement High Theoretical
Sources: COMP-005 | CWE-319 | OWASP-ASVS V9.1.1, V9.1.2

Application listens on plain HTTP. No TLS, no HTTPS redirect, no HSTS. Any future credential tokens would be transmitted in cleartext.

Remediation: Configure TLS termination at reverse proxy (nginx/Caddy). Add helmet() with HSTS. Enforce X-Forwarded-Proto: https check.
Medium (8)
M-001 Unauthenticated Prometheus Metrics Disclosure Medium Confirmed (Live Exploit)
Sources: SAST-006 · PEN-014 · COMP-010 · RED-010 | CWE-200 | OWASP-ASVS V4.2.1 · SOC2 CC6.1

GET /metrics returns 78 metric lines including status transition counts, AI voting invocation counts, heap size, GC stats, event loop lag — to any unauthenticated caller. Full technology fingerprint exposed.

Remediation: Restrict /metrics to internal network via reverse proxy allow-list or require static Bearer token. Never expose runtime internals to unauthenticated clients.
M-002 Search Empty Query Returns Full Dataset Medium Confirmed (Live Exploit)
Sources: PEN-012 · RED-008 | CWE-20

GET /api/search?q= and GET /api/search (no param) return 20 items each. Entire dataset walkable via empty-query pagination with no auth.

Remediation: Return HTTP 400 for missing or empty q. Enforce minimum query length of 2 characters. Apply authentication. Test ?q=.* for ReDoS risk when implemented.
M-003 CI/CD Workflow inputs.focus Free-Text Shell Injection Risk Medium Theoretical
Sources: SAST-007 | CWE-78

inputs.focus workflow_dispatch parameter injected into YAML before shell execution in run-guardians.yml and peers. Combined with --dangerously-skip-permissions on Claude Code invocations, crafted value could alter prompt file and instruct unintended operations.

Remediation: Validate inputs.focus against an explicit allowlist before use. Tighten --allowedTools on Claude Code invocations.
M-004 Docker Containers Run as Root Medium Theoretical
Sources: SAST-005 | CWE-250

All three Dockerfiles lack USER directives. Worker container runs Claude Code with --dangerously-skip-permissions and mounts Docker socket — root compromise gives host Docker daemon access.

Remediation: Add non-root user: RUN groupadd -r appuser && useradd -r -g appuser appuser && USER appuser to each Dockerfile.
M-005 Missing HTTP Security Headers + No CORS Policy Medium Theoretical
Sources: SAST-004 · COMP-008 · COMP-009 | CWE-693 | OWASP-ASVS V14.4.1, V14.4.7

No helmet middleware — missing CSP, X-Frame-Options, X-Content-Type-Options, HSTS, Referrer-Policy. No CORS — any web page can make cross-origin requests; future cookie auth immediately CSRF-exploitable.

Remediation: npm install helmet cors; add before all routes: app.use(helmet()); app.use(cors({ origin: ['http://localhost:5173'], credentials: true })).
M-006 Negative Page Parameter Reads Unexpected Data Positions Medium Theoretical
Sources: PEN-009 | CWE-20

Negative page values produce negative offsets passed to Array.slice(), returning data from unexpected positions. ?page=-1 → slice(-40,-20) returns items near end of list. ?limit=-1 returns all items except the last.

Remediation: Validate page >= 1 and limit >= 1 at route layer; return HTTP 400 otherwise.
M-007 No Rate Limiting on Any Endpoint Medium Theoretical
Sources: PEN-011 · SAST-008 · COMP-006 | CWE-770 | OWASP-ASVS V2.2.1

No rate-limit middleware. All endpoints callable at unlimited frequency. Confirmed: retrigger farming (RED-003) looped with no throttling encountered.

Remediation: Add express-rate-limit with tiered limits: 100/min general, 20/min workflow mutations, 5/min intake webhooks, 1/hr for retrigger.
M-008 No GDPR Right to Erasure (Hard Delete Path Missing) Medium Theoretical
Sources: COMP-012 | GDPR Art. 17

DELETE performs soft-delete only — sets deleted: true but retains record. No hard delete or purge path. When a database is added, PII in title/description will persist indefinitely.

Remediation: Implement purgeWorkItem() with DELETE /api/work-items/:id?permanent=true requiring elevated auth. Document data retention policy with purge schedule.
Low (5)
L-001 Internal Orchestrator URL Disclosed in Error Response Low Confirmed (Live Exploit)
Sources: RED-011 (new finding) | CWE-209

GET /api/orchestrator/test → HTTP 502 with body {"error":"Orchestrator unreachable at http://localhost:8080"}. Internal network topology disclosed to unauthenticated callers.

Remediation: Return generic {"error":"Service temporarily unavailable"}. Log actual target URL server-side only.
L-002 Predictable Sequential DocIDs Enable Enumeration Low Theoretical
Sources: PEN-013 · RED-005 | CWE-330

Sequential WI-NNN/FR-NNNN docIds reveal total usage, activity rates, and enable cross-referencing of soft-deleted IDs from dependency records. ID reuse confirmed (RED-005).

Remediation: Use UUIDs or cryptographically random ID segments for externally visible IDs.
L-003 No CORS / No CSRF Protection Low Theoretical
Sources: PEN-015 · PEN-016 | CWE-352 · CWE-942

No explicit CORS policy, no CSRF token mechanism. Not directly exploitable now (no session to hijack), but any cookie-based auth addition without these controls is immediately exploitable from any web origin.

Remediation: See M-005 for CORS. Add csurf or SameSite=Strict cookie policy once session auth is introduced.
L-004 Raw Exception Messages Forwarded to Clients Low Theoretical
Sources: COMP-011 | CWE-209 | OWASP-ASVS V7.4.1

Individual route catch blocks forward err.message directly to clients. Global errorHandler correctly returns generic messages — this is a per-route inconsistency that may leak implementation details.

Remediation: Standardize all route catches to return generic user-facing messages. Only propagate pre-approved UserError subclasses. Log full errors server-side.
L-005 No Data Retention Policy / No Scheduled Purge Low Theoretical
Sources: COMP-013 | GDPR Art. 5(1)(e) · SOC2 CC6.5

Soft-deleted items accumulate in-memory indefinitely. When persistence is added, all records including any PII in descriptions will be retained forever without a retention policy.

Remediation: Define retention policy (soft-deleted purged after 90 days, completed archived after 1 year). Implement scheduled purge job.
