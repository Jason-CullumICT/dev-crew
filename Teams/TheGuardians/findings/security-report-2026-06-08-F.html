2. Consolidated Findings

⛔ Critical

SEC-001 Complete Authentication & Authorization Bypass — All Endpoints Critical Confirmed (Live Exploit)

Source IDs: SAST-001, PEN-001, PEN-002, COMP-001, COMP-002, RED-001

Description: Zero authentication or authorization middleware exists on either codebase. Every endpoint — work-item creation, state transitions (approve/reject/dispatch/force-approve/deny), intake webhooks, and read operations — is accessible without credentials. The red-teamer confirmed write access (HTTP 201/200) on all state-changing operations anonymously against the live portal service. All 4 configured red-team objectives were achieved through this single root vulnerability.

Confirmed Exploit (RED-001): POST /api/feature-requests/FR-0021/force-approve with zero credentials → HTTP 200, status=approved. POST /api/bugs → HTTP 201. Every endpoint returned success without any Authorization header.

Objectives breached: (1) State machine bypass ✅ (2) Phantom blocker ✅ (3) Malformed verdict bypass ✅ (4) Full enumeration without pagination ✅

Remediation: Add authentication middleware (JWT/session) as the first middleware after body-parsing in both Source/Backend/src/app.ts and portal/Backend/src/index.ts. Apply RBAC — state-changing operations (approve, reject, dispatch, force-approve) require elevated roles. This single fix unblocks 7 compliance controls simultaneously.

SEC-002 Docker Socket Mounted Into Orchestrator Container — Host Escape Vector Critical Theoretical (Platform)

Source IDs: SAST-006

File: platform/docker-compose.yml:24

Description: /var/run/docker.sock is bind-mounted into the orchestrator container. This grants full Docker daemon access — equivalent to root on the host. Any code running inside the orchestrator (including injected prompts processed by Claude Code) can spin up privileged containers, escape to the host filesystem, or exfiltrate secrets. This is a deliberate architectural trade-off but represents the highest-risk single component in the entire system.

Compounding factor: SAST-005 (root user) and SAST-007 (credentials mount) compound the blast radius.

Remediation: Accept as architectural trade-off but document explicitly. Mitigate by: (1) add non-root USER to all Dockerfiles (SAST-005), (2) restrict orchestrator network access, (3) run orchestrator on a dedicated hardened host isolated from production. Consider Docker socket proxy (e.g., docker-socket-proxy) to scope API access.

🔴 High — Confirmed Live Exploits

SEC-003 Phantom Blocker — Permanent Dispatch Block via Hard Delete Without FK Cascade High Confirmed (Live Exploit)

Source IDs: PEN-005, RED-002

Objective: "Access or modify a soft-deleted work item via direct ID reference" — ✅ Achieved

Description: deleteFeatureRequest() hard-deletes the row but leaves the dependencies table row intact. After deletion the LEFT JOIN returns status=null/unknown (not in RESOLVED_STATUSES), permanently locking the dependent item in pending_dependencies. No automatic cleanup or recovery path exists — the item is stuck forever without manual DB intervention.

Confirmed (RED-002): FR-0024 confirmed stuck in pending_dependencies after its blocker FR-0023 was hard-deleted. GET /ready reports {"ready":false,"unresolved_blockers":[{"status":"unknown"}]}.

Remediation: Add DELETE FROM dependencies WHERE blocker_item_id = :id OR blocked_item_id = :id inside the delete transaction. Add ON DELETE CASCADE to the FK constraint. Apply the same fix to Source/Backend soft-delete paths.
pen-testerred-teamer
SEC-004 'denied' Missing from RESOLVED_STATUSES — Cascade Never Fires on Denial High Confirmed (Live Exploit)

Source IDs: PEN-008, PEN-012, RED-003

Objective: "Submit a malformed assessment verdict that bypasses routing logic" — ✅ Achieved

Description: denyFeatureRequest() does not call onItemCompleted(), and 'denied' is absent from RESOLVED_STATUSES = ['completed','resolved','closed','duplicate','deprecated']. When a blocker is denied, dependents remain in pending_dependencies forever. The same pattern exists in Source/Backend where NeedsClarification verdict maps to Rejected with no clarification loop.

Confirmed (RED-003): FR-0026 permanently stuck after blocker FR-0025 was denied. Attempt to advance to in_development returns "Invalid status transition: pending_dependencies → in_development".

Remediation: Add 'denied' (and 'rejected') to RESOLVED_STATUSES, OR make denyFeatureRequest() explicitly call onItemCompleted(). In Source/Backend, fix the assessment verdict mapping so NeedsClarification enters a reviewing clarification state rather than mapping to Rejected.
pen-testerred-teamer
SEC-005 Stored XSS — HTML/Script Payloads Stored Verbatim in Database High Confirmed (Live Exploit)

Source IDs: RED-006 (new finding — not in pen-tester map)

Description: No server-side input sanitization exists. <script>alert(document.cookie)</script>, <img src=x onerror=...>, and <svg onload=fetch(...)> payloads were stored verbatim (FR-0027) and returned in API responses. Any frontend rendering title or description as raw HTML will execute the payload, enabling session hijacking and data exfiltration.

Confirmed (RED-006): POST /api/feature-requests with XSS payload → HTTP 201. GET /api/feature-requests/FR-0027 returns raw payload in response JSON.

Remediation: Sanitize all string inputs server-side on write using DOMPurify (server-side) or encode HTML entities. Add Content-Security-Policy headers as a defense-in-depth layer. Apply to both Source/Backend and portal/Backend.

SEC-006 State Machine Bypass via overrideRoute: "fast-track" — Instant Approval High Theoretical

Source IDs: PEN-003

Description: POST /api/work-items/:id/route with {"overrideRoute":"fast-track"} unconditionally returns targetStatus: Approved, bypassing the entire assessment pod. Combined with no auth (SEC-001), any caller can promote any backlog item to approved in a single unauthenticated request.

Remediation: Remove overrideRoute entirely or restrict it to admin role with full audit logging. If retained, validate against WorkItemRoute enum.
pen-tester
SEC-007 routing → approved Transition Skips Assessment Pod High Theoretical

Source IDs: PEN-009

Description: VALID_STATUS_TRANSITIONS[routing] includes Approved as a valid target. The approve endpoint's guard only checks isValidTransition(item.status, Approved). If an item is left in routing transient state, a direct POST /:id/approve succeeds and bypasses the assessment pod entirely.

Remediation: Remove Approved from the valid transitions for routing status, or add an additional guard requiring the item to have passed assessment before allowing the approve endpoint.
pen-tester
SEC-008 Intake Webhooks — No HMAC Signature Verification High Theoretical

Source IDs: SAST-002, PEN-004, COMP-007

Files: Source/Backend/src/routes/intake.ts:11–55

Description: /api/intake/zendesk and /api/intake/automated accept POST requests without verifying the X-Zendesk-Webhook-Signature header. Any actor can spoof Zendesk and inject arbitrary work items. Enum validation for type and priority is also absent.

Remediation: Implement HMAC-SHA256 verification against a shared secret from env vars. Reject requests with absent or invalid signature header.

SEC-009 Dockerfiles — All Containers Run As Root (No USER Directive) High Theoretical (Platform)

Source IDs: SAST-005

Files: platform/Dockerfile.orchestrator, platform/Dockerfile.worker, portal/Dockerfile

Description: All three Dockerfiles run as UID 0 (root). Combined with the Docker socket mount (SEC-002), a compromised container has root-level access to mounted volumes and the host daemon.

Remediation: Add RUN addgroup --system appgroup && adduser --system --ingroup appgroup appuser and USER appuser before CMD in each Dockerfile.

SEC-011 No TLS/HTTPS Enforcement High Theoretical

Source IDs: COMP-004

Description: All services run over HTTP. No TLS termination, no HSTS header, no redirect from HTTP to HTTPS. SOC2-Type2 CC6.1 requires encryption in transit for all sensitive data flows.

Remediation: Terminate TLS at the load balancer or reverse proxy (nginx/Caddy). Add Strict-Transport-Security header. Add HTTP→HTTPS redirect.
