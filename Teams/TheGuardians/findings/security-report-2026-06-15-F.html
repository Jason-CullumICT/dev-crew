⛔ Automatic Grade F — Confirmed Red-Team Breach of Critical Objectives

All four pentest objectives from security.config.yml were achieved via live exploitation against the ephemeral test environment. Two Critical-severity exploits (unauthenticated full API access and state machine bypass) were confirmed with working payloads. Per the grading rubric, a confirmed red-team breach of a critical objective results in an automatic Grade F regardless of all other counts. Operator decision required before any merge to a shared environment.

1. Executive Summary

The dev-crew Source App backend has no authentication system whatsoever. All 15+ API endpoints — including destructive operations (approve, reject, dispatch, delete) — are fully accessible to any HTTP client with network reach. The red-team confirmed this is actively exploitable: every endpoint was exercised with zero credentials, the state machine was bypassed by calling a privileged force-approve endpoint, the full dataset was enumerated in a single unauthenticated request, and internal infrastructure URLs were leaked via an open Prometheus metrics endpoint. All four pentest objectives were achieved.

The compliance picture is equally stark: 16 of 17 checked controls fail. The SOC2 CC6 series (authentication, authorization, access control) is entirely unimplemented. Audit logging captures state transitions but omits actor identity, making it non-compliant with CC7.1 and ASVS V7.2.1. The single passing control is UUID v4 usage for identifiers.

Top 3 Risks:

  • 1. Zero authentication on all endpoints (CRIT-1) — Any network-accessible caller can create, modify, approve, reject, and delete work items. Root cause of 7 of the 7 confirmed red-team findings. Single fix (JWT middleware on /api/*) eliminates the majority of the attack surface.
  • 2. State machine bypass via force-approve (CRIT-2) — A dedicated /force-approve endpoint circumvents the AI voting pipeline entirely, promoting items to Approved with zero votes. Confirmed live with explicit exploit chain.
  • 3. Docker socket host-escape vector (HIGH-4) — The orchestrator container mounts /var/run/docker.sock, granting any process inside a full-privilege escape to the host OS. Unconfirmed by red-team but static-confirmed; impact is Critical if reached.

Critical

CRIT-1 Complete Absence of Authentication on All API Endpoints
Critical Confirmed (Live Exploit)
Source Findings
PEN-001 · RED-001 · SAST-001 · COMP-001 · COMP-002
Specialists
pen-tester, red-teamer, static-analyzer, compliance-auditor
Description
No authentication middleware is registered anywhere in the application. Every endpoint — POST /approve, POST /dispatch, DELETE /:id, and all others — responds to unauthenticated HTTP requests. The red-teamer created, updated, deleted, approved, and dispatched items using zero credentials. There is no concept of caller identity in the codebase. This single root cause is responsible for RED-001 through RED-007.
Evidence (RED-001)
curl -X POST http://localhost:3001/api/feature-requests -d '{"title":"Injected"}' → HTTP 201
Remediation
Implement JWT-based authentication middleware (e.g., express-jwt) as a gate before all /api/* routes. Reject any request without a valid token with HTTP 401. Layer RBAC on top to distinguish read, write, and admin roles for state-transition endpoints. This single change eliminates the root cause of CRIT-1, CRIT-2, HIGH-1 through HIGH-3, MED-1, and MED-2.
CRIT-2 State Machine Bypass via Unauthenticated Force-Approve
Critical Confirmed (Live Exploit)
Source Findings
PEN-002 · RED-002 · SAST-001 (auth root cause)
Specialists
pen-tester, red-teamer
Description
A POST /force-approve endpoint bypasses the AI voting pipeline entirely. The red-teamer confirmed: a feature request was created, moved to voting status, then force-approved via a single unauthenticated call — resulting in status: "approved" with votes: []. In a further test, force-approve was used to override an explicit AI deny-majority, demonstrating that the endpoint nullifies the AI review process. Pen-tester also identified a related issue: overrideRoute: "fast-track" in the Source/Backend skips the full routing pipeline.
Evidence (RED-002)
POST /api/feature-requests/FR-0020/force-approve (no credentials) → HTTP 200, {"status":"approved","votes":[]}
Remediation
Require admin-level authenticated token for /force-approve. Add audit log entry on every force-approve call (actor, item ID, timestamp). Add runtime validation of overrideRoute against the WorkItemRoute enum in Source/Backend. Consider removing force-approve entirely if the AI pipeline is the intended gate.

High

HIGH-1 Orphaned Dependency Link Exposes Deleted Item ID and Creates Permanent Block
High Confirmed (Live Exploit)
Source Findings
PEN-003 · RED-003
Specialists
pen-tester, red-teamer
Description
When a blocker item is deleted, its ID is retained in the blocked_by[] array of surviving dependents. The deleted ID is exposed in API responses and the dependent becomes permanently stuck in pending_dependencies because the system treats a missing blocker as unresolved. RED-003 confirmed: FR-0013 deleted → FR-0014's response still contains blocked_by: [{"item_id":"FR-0013","status":"unknown"}], and FR-0014's approval is permanently gated.
Remediation
On item deletion, cascade-delete all dependency_links rows that reference the deleted item as a blocker. Alternatively, treat a link to a non-existent item as resolved rather than unresolved in computeHasUnresolvedBlockers().
HIGH-2 Full Dataset Enumeration — No Server-Side Pagination Implemented
High Confirmed (Live Exploit)
Source Findings
PEN-005 · RED-004 · SAST-005 · COMP-011
Specialists
pen-tester, red-teamer, static-analyzer, compliance-auditor
Description
The portal backend has no pagination at all — the ?limit parameter is entirely ignored. GET /api/feature-requests?limit=1 returns the same full dataset as an unparameterised call. The Source/Backend has pagination but without an upper-bound cap, allowing ?limit=999999999 to return the entire store. RED-004 confirmed the full dataset was extracted in a single request.
Remediation
Implement LIMIT/OFFSET in all SQLite queries. Cap limit at 100 server-side. Return PaginatedResponse<T> with {data, total, page, limit, totalPages}. Validate limit and page as positive integers with isNaN guard.
HIGH-3 Unauthenticated Metrics Endpoint Leaks Operational Intelligence and Internal URLs
High Confirmed (Live Exploit)
Source Findings
PEN-009 · RED-005 · SAST-007 · COMP-008
Specialists
pen-tester, red-teamer, static-analyzer, compliance-auditor
Description
GET /metrics returns 572 lines of Prometheus data (status transitions, assessment verdicts, team dispatches) with zero authentication. RED-005 additionally found that when the orchestrator is unreachable, the error response leaks the internal service URL: {"error":"Orchestrator unreachable at http://localhost:8080"}.
Remediation
Restrict /metrics to localhost or an internal network (nginx IP allowlist or Express bind to 127.0.0.1). Remove internal service URLs from user-facing error messages; use a generic "service unavailable" message and log the detail server-side.
HIGH-4 Docker Socket Mounted in Orchestrator Container — Full Host Escape Vector
High Theoretical
Source Findings
SAST-002 (CWE-250)
Specialists
static-analyzer
Description
The orchestrator's Docker Compose configuration mounts /var/run/docker.sock into the container. Any process — or attacker — with code execution inside that container can use the Docker socket to create privileged containers, mount host filesystem paths, and achieve a full host escape. Combined with the absent authentication (CRIT-1), code execution inside the container is a realistic downstream step.
Remediation
Remove the /var/run/docker.sock volume mount. If the orchestrator genuinely needs to manage containers, use Docker API over TLS with certificates and a dedicated service account with minimum privilege. Consider Rootless Docker or a dedicated container management API (Podman socket, BuildKit) that does not grant host-level access.
HIGH-5 No Authorization / RBAC — Privileged Operations Callable by Any Identity
High Confirmed (Live Exploit)
Source Findings
COMP-002 · RED-001 (SOC2 CC6.3, CC8.1 · ASVS V4.1.x)
Specialists
compliance-auditor, red-teamer
Description
Beyond the missing authentication gate, there is no role-based access control layer. Once authentication is added, every caller (regardless of role) would still be able to approve, dispatch, and delete items. The red-team confirmed all privileged operations via RED-001. Fails SOC2 CC6.3 (logical access controls) and CC8.1 (change management authorization).
Remediation
Define roles: viewer, operator, admin. Gate /approve, /reject, /dispatch, /force-approve behind operator or admin role checks. Implement role middleware that reads from the JWT claims after authentication is in place.
HIGH-6 Intake Webhooks — No HMAC Verification and Unvalidated Enum Injection
High Theoretical
Source Findings
PEN-004 · SAST-006 · COMP-006
Specialists
pen-tester, static-analyzer, compliance-auditor
Description
POST /api/intake/zendesk and /api/intake/automated accept any request without validating HMAC-SHA256 signatures. Any party can inject work items claiming to be Zendesk. Additionally, body.type and body.priority pass through without enum validation, allowing arbitrary strings to be stored as valid-looking work items that pollute routing and assessment logic downstream.
Remediation
Validate X-Zendesk-Webhook-Signature HMAC-SHA256 (shared secret in env var). Add explicit enum validation for type and priority in intake handlers (same pattern as the main POST /api/work-items route).
HIGH-7 No TLS Enforcement — Application Served Over HTTP Only, No HSTS
High Theoretical
Source Findings
COMP-004
Specialists
compliance-auditor
Description
The application serves over plain HTTP with no TLS termination configured. HSTS is absent. API tokens, session data, and all work-item content are transmitted in plaintext, vulnerable to interception on any non-loopback network path. Fails SOC2 CC6.1 (encryption in transit) and ASVS V9.
Remediation
Configure TLS termination at the reverse proxy (nginx, ALB, or Caddy). Redirect all HTTP to HTTPS. Add Strict-Transport-Security: max-age=31536000; includeSubDomains header. Use helmet() to set HSTS automatically.
HIGH-8 No Session Management — No Token Expiry or Revocation
High Theoretical
Source Findings
COMP-009
Specialists
compliance-auditor
Description
There is no session management system: no token TTL, no idle timeout, no token revocation list. Once authentication is implemented, stolen tokens would remain valid indefinitely. Fails ASVS V3.3.1 (session timeout) and CC6.2 (credential management).
Remediation
Implement JWT with short access token TTL (15 min) and a rolling refresh token (7 days). Maintain a token revocation list (Redis or DB). Enforce idle session timeout server-side.
HIGH-9 Audit Events Missing — No Actor Identity in Compliance Logs
High Theoretical
Source Findings
COMP-003 (SOC2 CC7.1 · ASVS V7.2.1)
Specialists
compliance-auditor
Description
The four required audit events (login_attempt, permission_denied, state_transition, data_export) are either absent or incomplete. state_transition is logged at info level but without actor identity. The other three events do not exist at all. Without actor-linked audit trails, the system cannot satisfy SOC2 CC7.1 (security event monitoring) in a Type 2 audit.
Remediation
Implement structured audit logging middleware that captures actor ID (from JWT claims), action, resource ID, outcome, and timestamp for all four required event types. Store audit logs in a durable, tamper-evident store (separate from application logs).
HIGH-10 Re-Assessment Race Condition — Concurrent Requests Corrupt Change History
High Theoretical
Source Findings
PEN-007
Specialists
pen-tester
Description
Two concurrent POST /api/work-items/:id/assess requests against a proposed item both fetch the same object (by reference from the in-memory Map), both mutate item.changeHistory, and both write back — last write wins but history has double entries. This can result in duplicate assessment records and corrupt state.
Remediation
Store items by value in the Map (deep-clone on read). Add optimistic locking: include a version field; reject updates where the stored version > the version in the request.
HIGH-11 Malformed overrideRoute Value Persisted as Invalid Enum
High Theoretical
Source Findings
PEN-008
Specialists
pen-tester
Description
overrideRoute in POST /api/work-items/:id/route is typed as WorkItemRoute but TypeScript types are erased at runtime. An arbitrary string (e.g. "MALFORMED") passes the truthy check, enters the override branch, and the attacker-supplied string is persisted as the item's route field — storing an invalid enum value that breaks downstream switch-case logic.
Remediation
Add runtime validation: if (overrideRoute && !Object.values(WorkItemRoute).includes(overrideRoute)) return res.status(400).json(...); before calling classifyRoute().

Medium Theoretical
Source Findings

Description
PATCH /api/work-items/:id accepts blockedBy: string[] with no maximum length. Each element triggers a BFS cycle-detection over the entire dependency graph.
