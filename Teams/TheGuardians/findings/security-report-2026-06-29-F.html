⚠ Top 3 Risks

  1. M-001 + M-002: Every API endpoint is unauthenticated and the state machine can be bypassed with a single PATCH request — any anonymous caller can approve any work item, defeating the entire AI-voting workflow.
  2. M-003: A cross-origin CSRF exploit (form-encoded body, no credentials) lets a malicious page approve any item in one HTTP call from a victim's browser.
  3. Compliance collapse: 22% pass rate (4 / 18 controls) — no authentication, no TLS, no RBAC, 3 of 4 required audit events missing. SOC2 full-pass rate is 0%.

The application is a workflow-item tracking platform with a Node.js/Express backend and React frontend. It demonstrates good engineering practices in structured JSON logging, Prometheus metrics, input validation on the main create endpoint, and change-history tracking. However, the absence of an authentication layer is a systemic, architecture-level gap that cascades into every other security domain. The red-teamer confirmed live exploitation of the complete API, state machine, CSRF surface, and data enumeration endpoints. Remediation must begin with M-001 (authentication) as the foundational blocker before most other controls can meaningfully be evaluated.

🔴 Critical (3)

M-001
Complete API Authentication Absence — All Endpoints Public
Critical Confirmed (Live Exploit) CWE-306 SOC2 CC6.1/CC6.2 OWASP-ASVS 2.1.1, 4.1.2
Sources: SAST-001 · PEN-001 · COMP-001 · RED-001  |  Specialists: static-analyzer, pen-tester, compliance-auditor, red-teamer
Description

Every API endpoint is unauthenticated. No JWT validation, session check, API-key requirement, or any middleware gates access to /api/work-items, /api/workflow, /api/dashboard, /api/intake, or /metrics. Any caller with network access to port 3001 can create, update, approve, reject, or dispatch work items. The red-teamer confirmed baseline exploitation in a single HTTP request without credentials.

Remediation

Add authentication middleware (express-jwt or similar) globally in app.ts before all route groups. Implement a login endpoint that issues short-lived JWTs (exp ≤ 3600s). Require auth on all routes except /health. See also M-007 (RBAC) and M-023 (session timeout) which build on this fix.

M-002
State Machine Bypass — PATCH Direct Status Override + Fast-Track Route
Critical Confirmed (Live Exploit) CWE-284 OWASP-ASVS 4.1.3
Sources: PEN-002 · PEN-003 · RED-002 · RED-003  |  Specialists: pen-tester, red-teamer
Description

Two separate bypass paths were confirmed live: (1) PATCH /api/work-items/:id {"status":"approved"} overrides vote-count guards and approves items regardless of AI assessment outcome, even against a deny majority; (2) POST /:id/route {"overrideRoute":"fast-track"} skips the entire assessment pod and immediately sets status to approved. Both paths are unauthenticated. The red-teamer used these to achieve pentest objective 1.

Remediation

Remove the PATCH status override or gate it behind an admin role. Restrict fast-track override to admin roles only. Centralise all status transitions through the state machine validator — no direct status writes from route handlers without passing through the full transition guard chain.

M-003
CSRF via Form-Encoded Body — Anonymous Approval via Single HTTP Request
Critical Confirmed (Live Exploit) CWE-352 OWASP-ASVS 4.2.2 OWASP-ASVS 14.4.1
Sources: SAST-006 · RED-009  |  Specialists: static-analyzer, red-teamer
Description

The PATCH endpoint accepts application/x-www-form-urlencoded bodies, bypassing both the JSON Content-Type assumption and the vote-count guard in the dedicated /approve handler. No CSRF token, no credentials, no authentication required. The most dangerous chain confirmed by the red-teamer:

curl -X PATCH http://localhost:3001/api/feature-requests/<id> \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "status=approved"

Any cross-origin page can trigger this on a victim's browser with a <form> POST — no JavaScript required.

Remediation

Enforce strict Content-Type: application/json for all mutation endpoints; reject form-encoded bodies with 415. Add helmet (sets X-Frame-Options and other CSRF-mitigation headers). Implement SameSite cookie policy once auth is added. See M-010 for the full security headers gap.

🟠 High (8)

M-004
Unauthenticated Dashboard — Full Business Intelligence Disclosure
High Confirmed (Live Exploit) CWE-200 SOC2 CC6.1
Sources: RED-008  |  Specialists: red-teamer
Description

GET /api/dashboard returns aggregate business metrics — item counts per team, throughput rates, dispatch volumes — to any anonymous caller. Red-teamer confirmed full extraction including operational patterns usable for competitive intelligence or targeted attacks.

Remediation

Require authentication for /api/dashboard. Scope results to the authenticated user's team/role. Apply after M-001 is resolved.

M-005
Ghost Dependency After Soft-Delete — Permanently Stalled Downstream Items
High Partially Confirmed CWE-672 OWASP-ASVS 8.3.4
Sources: PEN-008 · RED-004  |  Specialists: pen-tester, red-teamer
Description

computeHasUnresolvedBlockers() treats findById() returning undefined (for a deleted item) as an unresolved blocker. Soft-deleting a blocker item permanently freezes all dependent items. Red-teamer partially confirmed: the ghost dependency persists post-deletion and blocks dispatch. Also causes audit trail corruption: changeHistory is mutated before updateWorkItem() completes, creating a race window with concurrent DELETE.

Remediation

In computeHasUnresolvedBlockers(), treat a missing/deleted blocker as resolved. On soft-delete, remove the deleted item's ID from all other items' blocker lists. Mutate changeHistory only after updateWorkItem() succeeds.

M-006
Stored XSS via Free-Text Fields — Payloads Persist in Store
High Partially Confirmed CWE-79 OWASP-ASVS 5.2.1 OWASP-ASVS 5.3.3
Sources: COMP-010 · RED-005  |  Specialists: compliance-auditor, red-teamer
Description

title and description fields accept arbitrary HTML/script content without server-side sanitisation. Payloads are stored verbatim (confirmed by red-teamer). React escapes by default but the backend must not rely on the rendering layer — any email template, PDF renderer, or admin panel consuming this data would execute stored payloads.

Remediation

Add server-side sanitisation via DOMPurify (server-side) or enforce plain-text via zod/joi schema validation. Enforce maximum field lengths (title ≤ 255, description ≤ 10,000 chars).

M-007
No Role-Based Access Control
High Theoretical CWE-285 SOC2 CC6.3 OWASP-ASVS 4.1.2, 4.1.3, 4.3.1
Sources: COMP-002  |  Specialists: compliance-auditor
Description

Even if authentication is added (M-001), there is no authorisation layer. No roles, no permission checks, no least-privilege enforcement. Any authenticated user could perform any action (approve, reject, dispatch) on any work item.

Remediation

Define roles (viewer, operator, admin). Add a requireRole() middleware. Gate /approve, /reject, /dispatch behind operator or admin roles. Implement after M-001.

M-008
Missing Required Audit Log Events — 3 of 4 Not Emitted
High Theoretical CWE-778 SOC2 CC7.1, CC8.1 OWASP-ASVS 7.2.1, 7.2.2
Sources: COMP-003  |  Specialists: compliance-auditor
Description

Required audit events per security.config.yml: login_attempt ❌ (no auth system), permission_denied ❌ (no authz), state_transition ⚠️ partial (logged but lacks structured event_type field), data_export ❌ (feature nonexistent). The structured logger (utils/logger.ts) is well-built but emits no audit-specific stream or discriminator.

Remediation

Introduce auditLog(eventType, actorId, resourceId, metadata) writing to a separate append-only stream. Emit state_transition with structured fields from all service functions that change WorkItem.status. Add login_attempt and permission_denied once M-001 and M-007 are implemented.

M-009
No TLS / HTTPS Enforcement — All Traffic Unencrypted
High Theoretical CWE-319 OWASP-ASVS 9.1.1, 9.1.2, 9.2.2 SOC2 CC6.1
Sources: COMP-004  |  Specialists: compliance-auditor
Description

Backend listens on plain HTTP (port 3001). Frontend dev proxy forwards to http://localhost:3001. No TLS configuration, no HTTPS redirect, no HSTS header. Any future credentials or tokens added post-M-001 would traverse an unencrypted channel.

Remediation

Terminate TLS at a reverse proxy (nginx/Caddy) with a valid certificate. Configure Strict-Transport-Security: max-age=31536000; includeSubDomains. Document that TLS is required before staging/production deployment.

M-010
Missing HTTP Security Headers and CORS Configuration
High Theoretical CWE-693 OWASP-ASVS 14.4.1, 14.4.2, 14.5.1 SOC2 CC6.1
Sources: SAST-006 · COMP-005  |  Specialists: static-analyzer, compliance-auditor
Description

Express sets no security headers. Missing: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options: nosniff, Strict-Transport-Security, Referrer-Policy, Permissions-Policy, Access-Control-Allow-Origin (CORS unconfigured). The absence of security headers directly enabled the confirmed CSRF exploit (M-003).

Remediation

Install and apply helmet as first middleware: app.use(helmet()). Configure CORS explicitly via the cors package with a trusted-origin allowlist. Review and tune CSP directives for the frontend's API usage patterns.

M-011
Intake Webhooks — No HMAC Signature Verification
High Theoretical CWE-345 SOC2 CC6.3 OWASP-ASVS 10.3.1, 10.3.2
Sources: SAST-003 · PEN-004 · COMP-006  |  Specialists: static-analyzer, pen-tester, compliance-auditor
Description

POST /api/intake/zendesk and /api/intake/automated accept payloads with no source verification. Zendesk signs payloads with HMAC-SHA256; this endpoint ignores the signature header. Any caller who discovers the URL can inject arbitrary work items into the workflow engine. Enum fields (type, priority) are not validated on intake routes, enabling additional enum injection (see M-015).

Remediation

Validate X-Zendesk-Webhook-Signature via HMAC-SHA256 with a shared secret in an env var. For /automated, require a Bearer token in the Authorization header. Reject failures with 401 and emit a permission_denied audit event.
