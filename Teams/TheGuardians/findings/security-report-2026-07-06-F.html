1. Executive Summary

Overall Risk Statement

The dev-crew Source App (Backend + Frontend) has a catastrophic authentication and authorization gap: every API endpoint is publicly accessible with zero identity verification. This single root-cause finding enables all other exploits. A red-team engagement against an ephemeral environment confirmed 9 live breaches, including 2 fully-achieved critical objectives. The application is not production-ready in its current state.

2. Consolidated Findings

🔴 Critical (2)

SEC-001 Critical Confirmed (Live Exploit) Complete Absence of Authentication & Authorization
📁 Source/Backend/src/app.ts:11-44 CWE-306, CWE-862 SOC2: CC6.1, CC6.2 · ASVS: V2.1.1, V4.1.1
The Express application mounts every route — including all state-changing operations (approve, reject, dispatch, delete, fast-track) — without any authentication or authorization middleware. No JWT, session, API-key, or IP-restriction exists at any layer. RED-001 confirmed: GET /api/work-items with zero headers returns HTTP 200 with full data; POST /api/work-items returns HTTP 201 with no authorization. Every subsequent exploit chain in this engagement was executed without a single credential. This is the universal root-cause finding.
Remediation (Priority 1): Add authentication middleware (JWT bearer or API-key) before all /api/* routes. This is the single highest-priority fix — without it, every other mitigation is trivially bypassed.
Sources: SAST-001 · COMP-001 · COMP-002 (partial) · PEN-001 · RED-001
SEC-002 Critical Confirmed (Live Exploit) Objective Achieved Fast-Track Override Bypasses State Machine
📁 Source/Backend/src/routes/workflow.ts:57 / Source/Backend/src/services/router.ts:66-75 CWE-862, CWE-20
POST /api/work-items/:id/route accepts overrideRoute:"fast-track" with no privilege gate. RED-002 confirmed: 3 unauthenticated HTTP calls (create → route with fast-track → dispatch) moved item WI-002 from backlog to in-progress with assessments:[] and no assessment-pod entries in changeHistory. Change history reads "Fast-tracked: bypasses assessment pod." Red-team objective ACHIEVED: "Bypass work item state machine to reach an invalid status."
Remediation (Priority 2): Remove overrideRoute from the public API entirely. If internal fast-track is needed, gate it behind a privilege-checked admin role and validate the value against Object.values(WorkItemRoute).
Sources: SAST-002 · PEN-002 · RED-002

🟠 High (8)

SEC-003 High Confirmed (Live Exploit) Direct /approve Endpoint Bypasses Mandatory Assessment Pod
📁 Source/Backend/src/routes/workflow.ts:94-142CWE-862
RED-003 confirmed: POST /api/work-items/:id/approve moves a Proposed item to Approved with empty assessments[]. Change history shows agent "manual-override" with no assessment-pod entries. The full workflow (proposed → assess → reviewing → approved) is completely skipped.
Remediation (Priority 3): Require assessments.length >= 4 (one per required role) before allowing approval, or remove the manual approve endpoint and only permit approval through the automated assessment pod.
Sources: PEN-003 · RED-003
SEC-004 High Confirmed (Live Exploit) Objective Achieved Unlimited Pagination — Full Dataset Enumeration
📁 Source/Backend/src/routes/workItems.ts:69-70CWE-20, CWE-770
RED-004 confirmed: ?limit=9999999 returned all 8 items in one response (data.length == total). Also confirmed: limit=-1 returns N-1 items via slice behavior; limit=abc silently falls back to 20 with no error. Full changeHistory of all items dumped via /api/dashboard/activity?limit=9999999. Red-team objective ACHIEVED: "Enumerate all work items without pagination limit enforcement."
Remediation (Priority 4): Add MAX_PAGE_SIZE = 100. Enforce: limit = Math.min(Math.max(1, parseInt(limit) || 20), MAX_PAGE_SIZE). Return 400 for non-positive or non-numeric values.
Sources: SAST-005 · PEN-004 · RED-004
SEC-005 High Confirmed (Live Exploit) Cascade Auto-Dispatch Hijack via Reject
📁 Source/Backend/src/services/dependency.ts:251-315CWE-862
RED-006 confirmed: Rejecting item A triggered onItemResolved() which auto-dispatched dependents B and C to in-progress with assignedTeam:"TheATeam" — no explicit /dispatch call on B or C. Prometheus metric confirmed: dispatch_gating_events_total{event="cascade_dispatched"} 2. An attacker can chain this to hijack the dispatch queue by rejecting strategically.
Remediation (Priority 6): Remove automatic cascade dispatch from onItemResolved. It should only unblock items (remove the blocker link). Dispatch must always be an explicit action through the /dispatch endpoint.
Sources: PEN-006 · RED-006
SEC-006 High Confirmed (Live Exploit) Intake Webhooks — No Auth, No Signature Verification, Enum Injection
📁 Source/Backend/src/routes/intake.ts:11-54CWE-290, CWE-346, CWE-20SOC2: CC8.1 · ASVS: V8.3.4
RED-007 confirmed: POST /api/intake/zendesk with type:"MALICIOUS_VALUE" and no X-Zendesk-Webhook-Signature header → HTTP 201. Items WI-016 and WI-017 stored with invalid enum values. Prometheus confirmed: workflow_items_created_total{source="zendesk",type="MALICIOUS_VALUE"} 1. Contrast: main POST /api/work-items correctly rejects invalid enums with 400.
Remediation (Priority 7): (1) Implement HMAC-SHA256 signature verification using ZENDESK_WEBHOOK_SECRET env var. (2) Add enum validation matching POST /api/work-items. (3) Require API key or IP allowlist for /api/intake/*.
Sources: SAST-003 · SAST-004 · COMP-005 · PEN-005 · RED-007
SEC-007 High Confirmed (Partial) Ghost Blocker Permanent DoS via Soft-Delete
📁 Source/Backend/src/services/dependency.ts:64-75CWE-841
RED-005 confirmed: Soft-deleting blocker C made dependent D permanently undispatchable. Dispatch error body exposes deleted item's UUID and docId (unresolvedBlockers:[{blockerItemId:"669abd07-..."). computeHasUnresolvedBlockers treats findById returning undefined as an unresolved blocker. Can be weaponized offensively: create dependency, delete blocker, lock a legitimate work item forever.
Remediation (Priority 5): Treat findById returning undefined as "blocker resolved, not blocking." On soft-delete, cascade-remove all dependency links where the deleted item is a blocker.
Sources: PEN-007 · RED-005
SEC-008 High Theoretical Missing HTTP Security Headers — No helmet Middleware
📁 Source/Backend/src/app.ts:11CWE-16, CWE-1021ASVS: V14.4.1–V14.4.6
No helmet or manual security headers. Absent: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options: nosniff, Strict-Transport-Security, Permissions-Policy. X-Powered-By: Express still sent, advertising the framework. This single fix unlocks 6 ASVS L2 controls and is the quickest-impact compliance improvement (5 minutes).
Remediation (Priority 8): npm install helmet and add app.use(helmet()) as the first middleware in app.ts.
Sources: SAST-007 · COMP-004
SEC-009 High Theoretical No Role-Based Access Control — Principle of Least Privilege Absent
📁 Source/Backend/src/routes/workflow.tsCWE-862SOC2: CC6.3 · ASVS: V4.1.1–V4.1.3
Once SEC-001 (authentication) is fixed, there is still no RBAC layer. Any authenticated caller can approve, reject, dispatch, or delete. A Zendesk webhook caller should not be able to approve items. The trackUpdates service hardcodes 'user' as the actor string, losing identity in all audit trails.
Remediation (Priority 10): Define roles (viewer, editor, approver, admin, service-account). Apply role-guard middleware per route. Emit permission_denied audit events on rejection.
Sources: COMP-002
SEC-010 High Theoretical Required Compliance Audit Events Absent from Logging Layer
📁 Source/Backend/src/ (all route handlers)CWE-778SOC2: CC7.1 · ASVS: V7.1.2

Remediation (Priority 11): Create a dedicated auditLogger module emitting structured events with: event_type, actor, resource_type, resource_id, outcome, timestamp. Ship to an immutable sink.
Sources: COMP-003
