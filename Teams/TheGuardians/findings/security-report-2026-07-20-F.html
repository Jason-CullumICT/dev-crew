1. Executive Summary

The dev-crew Source App received an automatic F grade due to a confirmed red-team breach of a critical config objective. The dominant root cause — zero authentication and zero authorization across every API endpoint — elevates every other finding from theoretical to trivially exploitable, and enabled the red-team to achieve full pipeline traversal in four unauthenticated HTTP calls.

A secondary architectural flaw — a raw SQL UPDATE in the cascade dependency service that bypasses all approval guards — was also confirmed as a live exploit (RED-006), providing a second path to reach approved status with zero votes and no human approval.

Top 3 risks that must be addressed before any deployment:

  1. F-001 — Complete absence of authentication and authorization. Every endpoint is open to any caller.
  2. F-004 — Cascade auto-dispatch issues raw DB writes, bypassing the entire approval voting pipeline.
  3. F-003 — Stored XSS: HTML/script payloads stored verbatim and returned in all API responses.

Compliance posture is critically weak: 22% pass rate (4 pass / 1 partial / 14 fail) across OWASP ASVS L2 and SOC2 Type 2. The application was architected as an internal tooling API without a threat model for external exposure. Remediation of F-001 (authentication + RBAC) will unblock roughly 70% of the failing compliance controls.

2. Consolidated Findings

🔴 Critical — 1 finding
F-001 Complete Authentication & Authorization Absence + State Machine Bypass Critical Confirmed (Live Exploit)
Merged from: PEN-001PEN-002SAST-01COMP-001RED-001  ·  CWE-306, CWE-862  ·  OWASP A01, A07
Zero authentication middleware exists anywhere in the Express application. Every endpoint — including privileged state-transition actions (/approve, /reject, /dispatch, /force-approve) — is freely accessible to any unauthenticated caller. Additionally, the /route endpoint accepts overrideRoute: "fast-track" which bypasses the entire assessment pod and approves items directly.

Red-team confirmed: Full pipeline traversal (potential → completed) in 4 unauthenticated HTTP calls — zero votes cast, zero AI review, no authentication challenge on any step. FR-0003 reached completed status with votes: [] and a human_approval_approved_at timestamp despite no voting process.
Remediation: (1) Add JWT bearer-token middleware globally before all route registrations in app.ts. (2) Implement RBAC: restrict /approve, /reject, /dispatch, /force-approve to explicit admin roles. (3) Gate or remove the overrideRoute fast-track bypass — if retained, require elevated privilege. (4) Apply authentication to /metrics separately.
🟠 High — 5 findings (3 Confirmed, 2 Theoretical)
F-002 Dependency Deadlock via Soft-Delete of Blocker High Confirmed (Live Exploit)
Merged from: PEN-003RED-002  ·  CWE-841  ·  OWASP A08
When a blocker work item is deleted, all dependent items in pending_dependencies become permanently non-dispatchable. The readiness check treats a missing (deleted) blocker as unresolved (status: "unknown"), returning has_unresolved_blockers: true indefinitely. No remediation path exists without direct DB access.

Red-team confirmed: FR-0005 permanently stuck in pending_dependencies after FR-0004 (blocker) was deleted. GET /ready returns ready: false referencing a ghost blocker with status: "unknown".
Remediation: When a blocker is deleted, automatically cascade-delete all outgoing dependency links, OR treat a deleted/missing blocker as resolved in the readiness check. Add an admin endpoint to manually clear stale blocker references as a recovery path.
F-003 Stored XSS via Unsanitized Free-Text Fields High Confirmed (Live Exploit)
Merged from: PEN-005RED-003  ·  CWE-79  ·  OWASP A03
HTML/script payloads in title, description, and reason fields are stored verbatim and returned in all list, detail, and search API responses without any server-side sanitization.

Red-team confirmed: <img src=x onerror=alert(document.cookie)> and <svg/onload=alert(1)> stored and returned verbatim across /api/feature-requests and /api/bugs. Any frontend component rendering these fields via innerHTML or dangerouslySetInnerHTML will execute attacker JavaScript in victim browsers.
Remediation: (1) Sanitize all free-text fields server-side before storage (use a DOMPurify-equivalent for Node.js). (2) Ensure all frontend components render user-controlled strings as text nodes, never as HTML. (3) Add Content-Security-Policy via helmet() as a defense-in-depth layer (see F-005).
F-004 Cascade Auto-Dispatch Bypasses Approval Voting High Confirmed (Live Exploit)
Merged from: PEN-009RED-006  ·  CWE-284, CWE-841  ·  OWASP A08
The onItemCompleted/onItemResolved cascade in the dependency service issues a raw SQL UPDATE ... SET status='approved' directly against the database, bypassing all service-layer approval guards, vote-majority checks, and human approval requirements.

Red-team confirmed: FR-0020 reached approved status with votes: [] via cascade from completing FR-0019. The raw SQL write skips all approval pipeline checks, providing a second path to bypass the vote majority requirement.
Remediation: Replace the raw SQL UPDATE in the cascade with a call to the proper approveFeatureRequest() service function (which includes its guards). Alternatively, cascade should only advance to a ready state and require a separate human confirmation before approved.
F-005 Missing HTTP Security Headers and CORS Policy High Theoretical
Merged from: SAST-02COMP-002COMP-003  ·  CWE-693, CWE-1021  ·  OWASP A05
No security headers are set on any response: no Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Strict-Transport-Security, or Referrer-Policy. No CORS policy is configured — any web origin can issue credentialed cross-origin requests and read responses. ASVS V14.4 and SOC2 CC6.1 FAIL.
Remediation: npm install helmet cors. Add app.use(helmet()) as the first middleware. Add app.use(cors({ origin: [...allowedOrigins] })). Tune CSP to actual asset origins.
F-006 Intake Webhooks Accept Unsigned and Unauthenticated Requests High Theoretical
Merged from: SAST-03COMP-011PEN-004  ·  CWE-306, CWE-345, CWE-20  ·  OWASP A07
POST /api/intake/zendesk and /api/intake/automated accept any request without verifying the Zendesk HMAC-SHA256 signature (X-Zendesk-Webhook-Signature). Any actor can forge a Zendesk webhook and inject arbitrary work items. Neither endpoint validates type or priority enum values — strings like "ADMIN_OVERRIDE" pass through and corrupt the work item store, breaking downstream routing logic.
Remediation: (1) Verify HMAC-SHA256 signature on Zendesk endpoint using ZENDESK_WEBHOOK_SECRET env var; reject 401 on mismatch. (2) Require bearer token on /automated endpoint. (3) Add same enum validation as the main POST /api/work-items route; return 400 on invalid enum values.
🟡 Medium — 8 findings (2 Confirmed, 6 Theoretical)
F-007 Unbounded Pagination Enables Full Data Enumeration and Memory-Pressure DoS Medium Confirmed (Live Exploit)
Merged from: SAST-04PEN-006RED-004  ·  CWE-400  ·  OWASP A01
The limit query parameter is not capped server-side. Red-team confirmed: ?limit=999999 returns the entire dataset in one response. ?limit=-1 and ?limit=2 also return all items. No server-side pagination metadata returned. Unauthenticated callers can enumerate the full dataset with one request (amplified by F-001).
Remediation: const limit = Math.min(parseInt(req.query.limit) || 20, 100). Apply to all list endpoints. Return total, page, limit, totalPages in every list response.
F-008 Prometheus /metrics Exposed Without Authentication + Technology Fingerprinting Medium Confirmed (Live Exploit)
Merged from: SAST-08COMP-005PEN-007RED-005  ·  CWE-497  ·  OWASP A02
Red-team confirmed: Full Prometheus output returned unauthenticated, revealing process CPU/memory, heap stats, event-loop lag, and business counters. X-Powered-By: Express header present on every response, enabling technology fingerprinting for known Express/Node.js CVEs.
Remediation: (1) Move /metrics to a separate internal-only port. (2) If public exposure required, add bearer-token check from METRICS_TOKEN env var. (3) app.disable('x-powered-by') (also covered by helmet() in F-005).
F-009 No Rate Limiting on Any Endpoint Medium Theoretical
Merged from: SAST-07COMP-004  ·  CWE-400  ·  OWASP A05
No rate-limiting middleware is applied. Combined with F-001 (no auth), any unauthenticated caller can issue unlimited concurrent requests to any endpoint, enabling automated attacks against state-transition endpoints and DoS amplification.
Remediation: Apply express-rate-limit globally (200 req/15 min per IP baseline). Apply stricter limits on state-transition and intake endpoints (20 req/min).
F-010 Raw Error Messages Returned to Clients in 500 Responses Medium Theoretical
Merged from: SAST-06  ·  CWE-209  ·  OWASP A05
Every route catch block in workflow.ts forwards the raw exception message to the HTTP client as the error field of the 500 response, bypassing the global errorHandler middleware that correctly returns a generic message. Internal stack fragments or file paths may surface in unexpected error conditions.
Remediation: Log the full message (already done) but return { error: 'Internal server error' } to the client in all catch blocks. Re-throw domain errors as typed classes with client-safe messages if specific feedback is needed.
F-011 Race Condition on Repeated Assessment Allows State Bloat Medium Theoretical
Merged from: PEN-008  ·  CWE-362  ·  OWASP A08
The /assess endpoint allows assessment when item status is either proposed OR reviewing. Concurrent POSTs can trigger two simultaneous assessment pod runs on the same item, doubling the assessments array length and causing state oscillation.
Remediation: Add an optimistic-locking or per-item mutex guard on the assessment transition. Only allow assessment when status is exactly proposed — reject reviewing with 409.
F-012 Missing Required Audit Events for SOC2 Compliance Medium Theoretical
Merged from: COMP-007COMP-008COMP-009COMP-010  ·  CWE-778  ·  OWASP A09
Four required audit events are absent: login_attempt (impossible without auth system), permission_denied (impossible without RBAC), state_transition (logged operationally but lacks event_type discriminator and durable store), data_export (bulk reads not audited). No tamper-evident, append-only audit store exists. SOC2 CC7.1 and ASVS V7.1 FAIL.
Remediation: (1) Implement auth (F-001) to enable login_attempt and permission_denied events. (2) Add event_type discriminator to all transition log entries. (3) Route audit events to a durable append-only store separate from operational stdout. (4) Define data export thresholds and emit data_export events at those thresholds.
F-013 No TLS/HTTPS Enforcement Medium Theoretical
Merged from: COMP-006  ·  CWE-319  ·  OWASP A02
Backend listens on plain HTTP. No HSTS header is emitted. If no TLS-terminating reverse proxy is deployed in production, all API traffic (state-transition actions, webhook payloads) travels in cleartext. ASVS V9.1 FAILS.
Remediation: Deploy behind a TLS-terminating load balancer or reverse proxy in all non-local environments. Add Strict-Transport-Security via helmet(). Document TLS topology in architecture specs.
F-014 In-Memory Store — No Persistence and No GDPR Hard-Erasure Path Medium Theoretical
Merged from: COMP-013  ·  CWE-312  ·  GDPR Art. 17
All data lives in a JavaScript Map. Soft-delete keeps records in memory — no GDPR Art. 17 hard-erasure mechanism. Data is lost entirely on restart. Mitigating factor: current WorkItem model contains no PII fields. This becomes critical if the model expands to include user identity.
Remediation: Migrate to a persistent store with encryption at rest. Implement hard-delete or field-scrubbing path for GDPR erasure requests. Document data retention periods in a Data Processing Agreement.
