Executive Summary

The dev-crew Source App (portal/Backend + Source/Backend) is in pre-production security posture. The application ships with zero authentication, zero authorization, and zero compliance controls. Every API endpoint — including state-transition, deletion, force-approval, and operational metrics — is fully accessible to any unauthenticated caller on the network.


The red-teamer confirmed all four objectives from security.config.yml against the live portal/Backend service:


✅ Bypass state machine
Force-approved a feature request with zero AI votes (RED-003)
✅ Access/modify soft-deleted item
IDOR delete on any resource (RED-002); orphaned blocker link survives deletion (RED-004)
✅ Submit malformed verdict
Force-approve accepted an empty vote set, bypassing all 5 AI review agents (RED-003)
✅ Enumerate all items
Full dataset returned on every unauthenticated GET, pagination ignored (RED-005)

Scope note: The pen-tester performed white-box analysis of Source/Backend (work-items engine). The red-teamer's live target was portal/Backend (feature-request/bug/cycle portal) served by docker-compose.test.yml. Equivalent vulnerability classes were confirmed on both surfaces; all four pentest objectives were re-derived and confirmed against the live service.

Consolidated Findings — Critical

Confirmed (Live Exploit) = RED-team execution confirmed | Theoretical = static/white-box only

F-001 — Zero Authentication & Authorization on All Endpoints
Critical Confirmed (Live Exploit) SAST-001 PEN-001 COMP-001 COMP-002 RED-001

The Express application registers zero authentication or authorization middleware. Every API endpoint — resource CRUD, all state transitions (route, assess, approve, force-approve, reject, dispatch), dashboard data, Prometheus metrics, and intake webhooks — is fully accessible to any unauthenticated caller. The red-teamer confirmed HTTP 200/201 on all nine route groups with zero credentials.

curl -X POST http://localhost:3001/api/feature-requests \ -d '{"title":"Attacker","description":"No auth"}' => HTTP 201 (no credential sent)
Remediation: Add authentication middleware (JWT bearer via express-jwt + JWKS, or API-key guard) as the first app.use() call. Add identity context (req.user). Define roles (operator, reviewer, admin) and add route-level authorization middleware. Exempt only /health.
F-002 — State Machine Bypass via Force-Approve (Zero AI Votes) ★ PRIMARY OBJECTIVE
Critical Confirmed (Live Exploit) PEN-003 PEN-006 RED-003

POST /api/feature-requests/:id/force-approve accepts any caller and approves an item regardless of vote count. An item moves from potential → voting → approved with zero AI agent votes, bypassing all five review agents (TechFeasibilityAgent, ResourceCostAgent, UserImpactAgent, BusinessValueAgent, SecurityReviewAgent). In Source/Backend, POST /route with {"overrideRoute":"fast-track"} skips the assessment pod entirely.

POST /force-approve on FR-0002 => {"status":"approved", "votes":[], "human_approval_approved_at":"2026-07-27T06:43:19.743Z"}
Remediation: Require authentication + elevated role (admin) on force-approve and all manual-override endpoints. Enforce a minimum vote count before force-approve is callable. Add audit logging for all override decisions.

Consolidated Findings — High

F-003 — IDOR on All Resource Endpoints
High Confirmed (Live Exploit) PEN-004 RED-002

Every endpoint accepting a resource ID fetches the record using only the ID with no ownership or role check. Any caller that knows or enumerates an ID can read, modify, or delete any item regardless of who created it.

PATCH /api/feature-requests/FR-0001 {"status":"voting"} => HTTP 200 DELETE /api/feature-requests/FR-0002 => HTTP 204 (no credential, no ownership check)
Remediation: After adding authentication (F-001), add resource-level ownership validation: only the creator or an authorized role may modify/delete a resource.
F-004 — Deleted Blocker Permanently Blocks Victim + ID Recycling Inherits Orphan Links
High Confirmed (Live Exploit) PEN-007 RED-004 RED-008

When a blocking item is deleted, isReady() treats findById => undefined (deleted item) as "unresolved" rather than "resolved." The victim's blockedBy list retains the stale link, permanently setting ready: false. Compounding: sequential ID generators recycle deleted IDs — a new item created after deletion automatically inherits the orphaned blocking relationship. Cross-type blocking (Bug → Feature Request) is equally exploitable.

After deleting FR-0005: GET /api/feature-requests/FR-0004 => {has_unresolved_blockers: true, ready: false} New FR-0005 created: {blocks: [{item_id: "FR-0004"}]} (inherited orphan link)
Remediation: (1) Cascade-delete or nullify dependency links when a blocker is deleted. (2) Treat missing/deleted blocker as resolved in isReady(). (3) Replace sequential IDs with UUIDs.
F-005 — Full Dataset Enumeration — Pagination Not Enforced
High Confirmed (Live Exploit) SAST-007 PEN-005 RED-005

List endpoints return the full dataset in every response; limit and page params are silently ignored. Source/Backend parses limit via parseInt with no NaN guard and no maximum cap. Both surfaces satisfy the pentest objective "Enumerate all items without pagination limit enforcement."

GET /api/feature-requests => 9 items (always; limit=999999 ignored, page=1&limit=1 ignored)
Remediation: Enforce server-side pagination: max page size = 100, return {data, page, limit, total, totalPages}. Add isNaN guard and Math.min(limit, 100) cap in Source/Backend.
F-006 — Intake Webhooks — No HMAC Verification + Unvalidated Enum Fields
High Theoretical SAST-004 PEN-002 COMP-008

Both /api/intake/zendesk and /api/intake/automated accept any POST body with no HMAC signature verification, no API key, and no origin allowlist. body.type and body.priority are stored without enum validation, enabling injection of arbitrary strings into Prometheus metric labels (cardinality bomb).

Remediation: Verify Zendesk HMAC-SHA256 via X-Zendesk-Webhook-Signature. Require Bearer token on automated endpoint. Validate enum fields against Object.values(WorkItemType/Priority).
F-007 — No CORS Policy
High Theoretical SAST-002 COMP-005

No CORS middleware configured. Any webpage on any origin can make cross-origin requests to the API from a browser. Security boundary is entirely browser-enforced (bypassed trivially by non-browser clients).

Remediation: Install cors package; apply app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') })). Configure ALLOWED_ORIGINS per environment.
F-008 — No HTTP Security Headers
High Theoretical SAST-003 COMP-006

No security headers set: CSP (XSS escalation), X-Frame-Options (clickjacking), HSTS (protocol downgrade), X-Content-Type-Options (MIME sniffing), Referrer-Policy (URL leakage). No helmet() import anywhere in the source tree.

Remediation: import helmet from 'helmet'; app.use(helmet()); as first middleware in app.ts. Tune CSP to match actual frontend sources.
F-009 — No Rate Limiting on Any Endpoint
High Theoretical SAST-010 COMP-007

No rate-limiting middleware exists. All state-mutation endpoints and intake webhooks can be called at unlimited frequency, enabling resource exhaustion and operational abuse.

Remediation: Add express-rate-limit globally (e.g., 100 req/min per IP) with stricter limits on state-mutation and intake endpoints.
F-010 — Required Audit Events Not Emitted
High Theoretical COMP-003

security.config.yml mandates four audit event types: login_attempt, permission_denied, state_transition, data_export. None are emitted. Domain-object changeHistory is not a security audit log.

Remediation: Add auditLog() helper emitting {event_type, actor, target_id, timestamp, outcome}. Emit state_transition, permission_denied, and login_attempt from appropriate layers.
F-011 — No TLS / HTTPS Enforcement
High Theoretical COMP-004

Server binds to plain HTTP (app.listen(PORT)). No TLS configuration, no HTTPS server, no HTTP→HTTPS redirect. All data transits in cleartext.

Remediation: Terminate TLS at reverse-proxy/load-balancer (nginx/ALB); add HSTS header; document that http://localhost:3001 is dev-only.
F-012 — In-Memory Store — No Persistence / Encryption at Rest
High Theoretical COMP-010

All data lives in a process-local JavaScript Map. On restart, all data is lost. No database, no disk persistence, no encryption at rest.

Remediation: Replace in-memory store with PostgreSQL; enable database-level encryption at rest; encrypt backups.

Consolidated Findings — Medium

F-013 — Prometheus /metrics Unauthenticated
Medium Confirmed (Live Exploit) SAST-006 PEN-010 COMP-009 RED-006

GET /metrics returns 41KB Prometheus exposition with no credentials: full API route map, per-route request counts, latency histograms, Node.js heap/CPU/event-loop stats, and attacker-injectable counter labels (via F-006).

Remediation: Guard with a Bearer token (METRICS_TOKEN env var) or bind to a private port not exposed externally.
F-014 — Error Messages Leak Internal State Machine Details
Medium Confirmed (Live Exploit) SAST-005 PEN-011 RED-007

Error responses expose the full STATUS_TRANSITIONS graph, internal ID formats (BUG-XXXX/FR-XXXX), current item status, all allowed transitions, and raw exception messages. Seven catch blocks in workflow.ts return raw err.message to clients, bypassing the correct generic handler in errorHandler.ts.

Remediation: Return {error: "Internal server error"} from all route-level catch blocks. Log full message server-side. Reserve detailed transition errors for authenticated admin callers only.
F-015 — No Hard Deletion / Right to Erasure (GDPR Art. 17)
Medium Theoretical COMP-012

Only soft-delete exists. No mechanism to permanently erase a work item and its change history, which may contain user-supplied PII in free-text fields.

Remediation: Add purgeWorkItem() function; expose DELETE /api/work-items/:id/purge restricted to admin; document DSAR process.
F-016 — Re-assessment Idempotency Flaw
Medium Theoretical PEN-008

assessWorkItem() permits re-assessment of items already in reviewing status, appending unbounded duplicate change entries and assessment records.

Remediation: Guard the assess route: reject re-assessment if item is already in reviewing status; return HTTP 409 Conflict.
F-017 — Missing Input Length Validation Enables Memory Bloat
Medium Theoretical PEN-012

title and description fields have no maximum length enforcement. Megabyte-length strings are stored and returned in every list response, enabling memory exhaustion.

Remediation: Add MAX_TITLE_LEN = 200 and MAX_DESC_LEN = 10000 guards on all POST/PATCH routes.
F-018 — Circular Dependency Guard Frontend-Only (1-hop)
Medium Theoretical PEN-009

The frontend DependencyPicker guards only direct (1-hop) cycles; transitive cycles of depth ≥2 are backend-only. Backend BFS must be verified against stale blocks arrays after concurrent removals.

Remediation: Add backend integration tests covering transitive cycles (depth 3+). Remove the frontend-only cycle guard and rely solely on server-side BFS validation.

Consolidated Findings — Low

F-019 — Body Parser Returns 500 Instead of 413 on Oversized Payloads
Low Confirmed (Live Exploit) RED-009

A POST body exceeding 16KB that bypasses field-level length checks returns HTTP 500 instead of 413 because PayloadTooLargeError is not handled by the error handler.

Remediation: In errorHandler.ts, detect err.type === 'entity.too.large' and return HTTP 413.
F-020 — Debug Portal <iframe> Missing sandbox Attribute
Low Theoretical SAST-009 PEN-014

The iframe embedding the debug portal runs with full browser privileges. If VITE_PORTAL_URL is misconfigured, the embedded page could exfiltrate session data.

Remediation: Add sandbox="allow-scripts allow-same-origin" to the iframe element.
F-021 — Query Filter Parameters Cast Without Runtime Enum Validation
Low Theoretical SAST-008

TypeScript as WorkItemStatus casts are compile-time only; invalid ?status=INJECTED values are silently accepted and passed to store.findAll().

Remediation: Validate each filter value against Object.values(Enum) and return HTTP 400 for invalid values.
F-022 — Sequential docId Reveals Historical Item Count
Low Theoretical PEN-013

Monotonically incrementing WI-NNN / FR-XXXX IDs reveal total items ever created (including deleted). Also root cause of F-004 ID-recycling.

Remediation: Use UUIDs for public IDs (also fixes F-004 ID-recycling).
F-023 — No Data Retention Policy Enforcement
Low Theoretical COMP-013

Data accumulates indefinitely; violates GDPR Art. 5(1)(e) storage-limitation principle once a persistence layer is added.

Remediation: Define DATA_RETENTION_DAYS env var; implement a scheduled cleanup job.
F-024 — Logger Lacks Sensitive-Field Redaction
Low Theoretical COMP-014

Custom hand-rolled logger does not redact sensitive fields. pino (with fast-redact) is a declared dependency but unused. Once auth is added, tokens and emails will enter log context.

Remediation: Switch to pino with redact: ['req.headers.authorization', 'body.password', 'body.token'].
