1. Executive Summary

⛔ The application has no authentication, no role-based access control, and no input validation on file uploads. The red-team confirmed six live breaches against the ephemeral environment: any anonymous actor can bypass the entire AI assessment pipeline via a three-request chain, exfiltrate arbitrary files (including /etc/passwd and arbitrary PHP shells), permanently destroy feature requests with no recovery path, dump the entire dataset in one request, and read full operational telemetry. All four pentest objectives were achieved with zero credentials. The application is not suitable for production deployment in any form until the Critical and High findings are resolved.

Top 3 Risks

MERGED: SAST-001 · PEN-001 · COMP-001 · RED-001
No Authentication — AI Assessment Pipeline Completely Bypassed (Confirmed)
Any caller can create, approve, reject, or dispatch work items with zero credentials. The entire AI voting pipeline was skipped in a three-request exploit chain confirmed live.
RED-002 (Net New)
Arbitrary File Upload + Public Exfiltration — /etc/passwd Confirmed Live (Confirmed)
The multer file handler trusts the attacker-controlled Content-Type header. Any file — system files, PHP shells — can be uploaded and is immediately served publicly at a predictable URL.
MERGED: SAST-002 · PEN-003 · COMP-008
Webhook Intake — No Signature Verification + No Enum Validation (Theoretical)
Any actor can POST to /api/intake/zendesk or /api/intake/automated without proving origin. Arbitrary type/priority strings can be injected into the work-item store.

2. Consolidated Findings

Critical

2 Findings — Both Confirmed (Live Exploit)

MERGED-C01 No Authentication on Any Endpoint — AI Assessment Pipeline Bypass Critical Confirmed (Live Exploit)
Sources: SAST-001PEN-001COMP-001RED-001
Live Exploit Chain (RED-001): POST /api/feature-requests → create item PATCH /:id {"status":"voting"} → move to voting POST /:id/force-approve → approved — zero agent votes, no auth Red-team result: human_approval_approved_at set; entire AI pipeline skipped.
Zero authentication or authorization middleware is applied anywhere in the Express application. Every endpoint — create, approve, reject, dispatch, override, delete — accepts requests from any anonymous caller on the network. There is no JWT validation, no session check, no API-key gate, and no RBAC. The overrideRoute: 'fast-track' parameter bypasses assessment entirely, promoting any item straight to approved without any vote. Confirmed by red-team against the live ephemeral environment.
Remediation: Add a JWT/API-key authentication middleware in Source/Backend/src/app.ts before all route registrations. Define roles (viewer, operator, admin) and enforce role checks on every state-mutation endpoint (/route, /assess, /approve, /reject, /dispatch, /force-approve). Consider express-jwt + jsonwebtoken or a dedicated identity provider.
RED-002 Arbitrary File Upload + Public Exfiltration (Net New Critical) Critical Confirmed (Live Exploit)
Sources: RED-002 (not predicted by pen-tester — net new)
Live Exploit Chain (RED-002): Upload /etc/passwd with Content-Type: image/jpeg → HTTP 200, file stored GET http://localhost:3001/uploads/6939ae6b…jpg → /etc/passwd contents returned live Upload <?php system($_GET["cmd"]); ?> with Content-Type: image/jpeg → PHP shell at public URL
The multer file handler validates only file.mimetype, which is the Content-Type header value supplied by the attacker in the multipart request — not the actual file magic bytes. Any file content can be uploaded. All uploaded files are served publicly at /uploads/<uuid> with no authentication gate. This allows exfiltration of server filesystem files and, in environments where PHP or other runtimes process /uploads/, remote code execution.
Remediation: (1) Use file-type or magic-bytes NPM package to validate actual file magic bytes, not the client-supplied MIME type. (2) Store uploaded files outside the web root and serve through an authenticated proxy endpoint. (3) Enforce an allowlist of valid MIME types (image/jpeg, image/png, etc.) verified against real bytes. (4) Gate the upload endpoint and the /uploads/ serve path behind authentication.
High

9 Findings — 3 Confirmed, 6 Theoretical

MERGED-H01 No Pagination Limit Cap — Full Dataset Enumeration in One Request High Confirmed (Live Exploit)
Sources: SAST-004PEN-005COMP-004RED-005
The limit query parameter is passed directly to the store layer with no upper bound. Red-team confirmed: GET /api/feature-requests?limit=999999 and GET /api/dashboard/activity?limit=999999 returned the entire dataset in a single unauthenticated response, bypassing all pagination intent and serving as a DoS vector as data grows.
Remediation: Clamp the parsed limit to a maximum of 100: const limit = Math.min(parseInt(req.query.limit as string, 10) || 20, 100); in workItems.ts and dashboard.ts. Apply the same cap in dashboard activity endpoint.
MERGED-H02 Ghost Dependency Permanent DoS — Soft-Delete Orphans Dependents High Confirmed (Live Exploit)
Sources: PEN-009RED-003
Adding an item as a blocker then soft-deleting it leaves the dependent item permanently stuck in pending_dependencies with no API recovery path. Red-team also confirmed that GET /:id/ready responses leak soft-deleted item IDs in unresolved_blockers, exposing internal IDs of deleted data.
Remediation: On soft-delete of a blocker, automatically resolve or remove the dependency. Add an API path to manually clear stale blocker references. Filter soft-deleted IDs from unresolved_blockers in API responses.
MERGED-H03 Unauthenticated Approve/Deny Sabotage — Terminal State Manipulation High Confirmed (Live Exploit)
Sources: PEN-007RED-004
Any anonymous actor can call POST /api/feature-requests/:id/deny to permanently kill a feature request in the voting pipeline. denied is a terminal state with no recovery path. Red-team confirmed: feature FR-0008 killed with the comment "DENIED BY UNAUTHORIZED SABOTEUR" — no credentials required.
Remediation: Resolve as part of MERGED-C01 (add authentication). Deny/approve actions must require an admin or operator role. Additionally, consider an "undo deny" grace-period window before the state becomes truly terminal.
PEN-002 Fast-Track Override Bypasses Entire Assessment Pod High Theoretical
Sources: PEN-002
POST /api/work-items/:id/route with body {"overrideRoute":"fast-track"} directly transitions any item to approved status, bypassing the assessment pod entirely. No role check. Three requests — create, fast-track, dispatch — are sufficient to fully promote any item. (Red-team tested the portal domain; this path remains unconfirmed live in the work-items domain but is structurally identical to RED-001.)
Remediation: Remove or gate the overrideRoute parameter behind an admin-only role. Require explicit justification logged to the audit trail when the fast-track path is used.
MERGED-H05 Webhook Spoofing — No Signature Verification + No Enum Validation High Theoretical
Sources: SAST-002PEN-003PEN-004COMP-008
/api/intake/zendesk and /api/intake/automated accept any POST without verifying the request origin. No X-Zendesk-Webhook-Signature HMAC check. Additionally, type and priority fields accept arbitrary strings (unlike POST /api/work-items which validates against enums), allowing invalid values to enter the store and poison downstream processing.
Remediation: (1) Validate X-Zendesk-Webhook-Signature with crypto.timingSafeEqual(HMAC-SHA256(body, ZENDESK_WEBHOOK_SECRET)). (2) Validate body.type and body.priority against Object.values(WorkItemType/WorkItemPriority). (3) Require Authorization: Bearer <INTAKE_API_KEY> on the automated endpoint.
PEN-006 Cascade Auto-Dispatch on Rejection — Logic Manipulation High Theoretical
Sources: PEN-006
The rejection logic auto-dispatches dependent items when a blocker is rejected. An attacker can create a blocker item targeting an approved item, then reject the blocker, triggering an automatic dispatch of the target item — bypassing the intended queue ordering without any role check.
Remediation: Require operator-role authentication for all rejection actions (resolved by MERGED-C01). Add explicit validation that auto-dispatch actions do not skip required assessment states.
COMP-002 No TLS / HTTPS Enforcement High Theoretical
Sources: COMP-002 · OWASP-ASVS 9.1.1, 9.1.2 · SOC2 CC6.1
The Express server binds to plain HTTP with no TLS context. The frontend Vite proxy targets http://localhost:3001. In any non-localhost deployment, all data including work item descriptions, state transitions, and operational telemetry travels in plaintext, violating ASVS 9.1.1.
Remediation: Terminate TLS at the server or a reverse proxy (nginx/Caddy). Set Strict-Transport-Security: max-age=63072000; includeSubDomains. Add HTTP→HTTPS redirect. Provision certificates via Let's Encrypt or org PKI.
COMP-005 Required Audit Events Not Emitted High Theoretical
Sources: COMP-005 · SOC2 CC7.1
The four audit events required by security.config.yml are absent or partial: login_attempt (impossible — no auth), permission_denied (impossible — no access control), state_transition (only in-memory changeHistory, no structured audit log), data_export (not logged). SOC2 CC7.1 evidence collection requires durable, structured audit records.
Remediation: Implement auditLog(event_type, actor_id, resource_id, outcome, timestamp, source_ip) in utils/logger.ts. Emit on every state transition. Add login_attempt and permission_denied events once auth is in place.
COMP-004 No Rate Limiting on Any Endpoint High Theoretical
Sources: COMP-004 · OWASP-ASVS 4.2.2, 13.1.1 · SOC2 CC6.1
All endpoints are unrestricted. An actor can flood any endpoint at arbitrary request rates, enabling DoS, credential-stuffing (after auth is added), and brute-force enumeration of work-item IDs.
Remediation: Apply express-rate-limit globally (e.g., 100 req/min per IP) with stricter limits on state-mutation endpoints.

7 Findings — 1 Confirmed, 6 Theoretical

MERGED-M01 Unauthenticated Prometheus /metrics Endpoint Medium Confirmed (Live Exploit)
Sources: SAST-007PEN-008COMP-007RED-006
Red-team confirmed: GET /metrics returns full operational telemetry — transition rates, voting invocations, upload counts, process memory/CPU — with no authentication. Exposes intelligence for targeted attacks and capacity planning by adversaries.
Remediation: Move metrics to an internal-only port bound to 127.0.0.1, or gate with a bearer-token check (Authorization: Bearer <METRICS_TOKEN>).
MERGED-M02 Internal Error Messages Forwarded to HTTP Clients Medium Theoretical
Sources: SAST-003COMP-012 · CWE-209 · OWASP-ASVS 7.4.1
Every catch block in workflow.ts (lines 60, 87, 140, 207, 294, 350, 370) forwards the raw err.message to the HTTP client in the 500 response, bypassing the global errorHandler.ts which correctly returns a generic message.
Remediation: Replace res.status(500).json({ error: message }) with res.status(500).json({ error: 'Internal server error' }) in all catch blocks in workflow.ts.
MERGED-M03 Missing HTTP Security Headers (CSP, HSTS, X-Frame-Options, CORS) Medium Theoretical
Sources: SAST-005COMP-003COMP-006PEN-010 · OWASP-ASVS 14.4.1–14.4.6, 14.5.3
No security headers middleware is registered. Missing: Content-Security-Policy, X-Frame-Options: DENY, Strict-Transport-Security, X-Content-Type-Options: nosniff, Referrer-Policy, Permissions-Policy. No CORS policy — any origin can make cross-origin requests.
Remediation: npm install helmet cors → app.use(helmet()) + app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') })) before route registrations. Never use wildcard * with credentials.
SAST-006 Unsandboxed <iframe> in DebugPortalPage Medium Theoretical
Sources: SAST-006 · CWE-1021
The debug portal iframe in DebugPortalPage.tsx has no sandbox attribute. The embedded document inherits full script execution and can access window.parent, make same-origin requests, and read cookies. URL is configurable via VITE_PORTAL_URL.
Remediation: Add sandbox="allow-scripts allow-same-origin allow-forms". If portal origin differs from app origin, remove allow-same-origin. Restrict with a CSP frame-src directive.
COMP-009 Audit Logs Lack Caller Identity and Request Correlation IDs Medium Theoretical
Sources: COMP-009 · SOC2 CC7.1 · OWASP-ASVS 7.1.1, 7.1.2
Structured logs emit timestamp, level, and message but never actor_id, per-request correlation ID, or client IP. Incident investigation and SOC2 evidence collection are impossible without "who did what when."
Remediation: Generate a UUID requestId per request in the logging middleware. Use AsyncLocalStorage to propagate it. Once auth exists, inject actor_id into every log call.
COMP-010 Audit Logs Not Durably Persisted or Tamper-Protected Medium Theoretical
Sources: COMP-010 · SOC2 CC7.1 · ISO27001 A.12.4.1, A.12.4.2
All log output goes to process.stdout only. In the containerised setup logs are ephemeral and lost on container restart. SOC2 Type 2 requires durable, queryable audit records retained for at least 12 months.
Remediation: Forward logs to a durable destination (CloudWatch Logs, Datadog, Elasticsearch). Configure 13-month retention. Use an append-only log store or WORM-bucket for tamper protection.

softDelete() sets deleted = true but retains all data. No hard-delete API exists. Must be resolved before PII-containing fields (e.g., Zendesk submitter details) are stored.
Remediation: Implement hardDelete(id) in the store and an admin-only DELETE /api/work-items/:id/purge endpoint.
PEN-011 Negative Pagination Parameters Cause Unexpected Slice Behavior Low Theoretical
Sources: PEN-011
Negative values for page or limit produce unexpected JavaScript array slice behavior, potentially returning unintended data ranges.
Remediation: Validate that page >= 1 and limit >= 1; return 400 on invalid values.
PEN-012 No Length Limits on Free-Text Fields — Memory Inflation Risk Low Theoretical
Sources: PEN-012
Free-text fields (title, description, comment) have no length limits. In a reject-cycle, an attacker can inject megabyte strings per cycle iteration, inflating in-memory store size over time.
Remediation: Enforce max lengths in validation schemas (e.g., title: 200 chars, description: 5000 chars).
PEN-013 Missing /api/search Endpoint Referenced by Frontend Low Theoretical
Sources: PEN-013
The frontend references a /api/search endpoint that does not exist in the backend. This returns 404 and could cause user-facing errors. The unimplemented surface area may be added later without security review.
Remediation: Implement the endpoint with proper auth and input sanitization, or remove the frontend reference if the feature is not planned.
