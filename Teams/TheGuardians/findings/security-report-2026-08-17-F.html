1. Executive Summary

⛔ Grade F — Confirmed Breach of Critical Security Objectives

The dev-crew Source Application has no authentication layer whatsoever. Every API endpoint is publicly accessible to unauthenticated callers. The red-team confirmed two critical-objective breaches in a live ephemeral environment: (1) full unauthenticated API access to all operations, and (2) a three-step state-machine bypass that moves any work item to Approved without human or AI review. The application is not safe to deploy in any environment with real data or network exposure.

Top 3 Risks

  1. C-001 — Zero Authentication: All endpoints — CRUD, state transitions, intake, metrics — are publicly writable with no credentials required. (SAST-01 · COMP-001 · PEN-001 · RED-001 — Confirmed)
  2. C-002 — State Machine Bypass: Any caller can bypass the assessment pod entirely and move a work item to Approved in three HTTP requests using overrideRoute: "fast-track". (SAST-09 · PEN-003 · RED-002 — Confirmed)
  3. H-001 — Full Data Enumeration: Pagination parameters are silently ignored; a single GET /api/bugs?limit=1 returns the entire dataset. (SAST-05 · COMP-011 · PEN-002 · RED-003 — Confirmed)

2. Consolidated Findings
🔴 Critical — Confirmed Live Exploit (2)
C-001 Complete Absence of Authentication & Authorization Critical Confirmed (Live Exploit)
Sources: SAST-01 · COMP-001 · PEN-001 · RED-001 | Specialists: static-analyzer · compliance-auditor · pen-tester · red-teamer
The Express application registers zero authentication or authorization middleware. Every endpoint — GET/POST/PATCH/DELETE /api/work-items, all state transitions (approve, reject, dispatch, route), /api/dashboard, and /api/intake — is publicly accessible with no credentials. The red-team confirmed this live: unauthenticated HTTP requests to approve, reject, and dispatch work items all succeeded. CWE-306. Violates SOC2 CC6.1/CC6.2/CC6.3 and OWASP-ASVS L2 V2.1, V3.1, V4.1.
Remediation Add an authentication middleware (JWT bearer tokens, express-jwt, or equivalent) before all app.use('/api/...') mounts in Source/Backend/src/app.ts. Define roles (viewer · operator · admin). Protect state-mutation endpoints with at minimum operator role via RBAC middleware. This single fix unlocks compliance controls CC6.1–CC6.3, ASVS V2.x, V3.x, V4.x.
C-002 State Machine Bypass — Unauthorized Approval Without Review Critical Confirmed (Live Exploit)
Sources: SAST-09 · PEN-003 · RED-002 | Specialists: static-analyzer · pen-tester · red-teamer
Any caller can include {"overrideRoute": "fast-track"} in the route POST body to bypass the assessment pod and move a work item directly to Approved. The red-team achieved this in three steps against the live environment: PATCH to voting (0 votes) → force-approve → approved, with zero human or AI review required. Pentest objective #1 (bypass state machine) was fully achieved. CWE-285. Amplified by C-001 (any unauthenticated caller can trigger this).
Remediation In Source/Backend/src/routes/workflow.ts, add a role-based guard before processing overrideRoute: reject with HTTP 403 unless the authenticated user holds a router:override or admin permission. As a secondary control, log all overrideRoute usages as a security audit event regardless of authorization outcome.
🟠 High — Confirmed Live Exploit (3)
H-001 Full Dataset Enumeration — Pagination Parameters Silently Ignored High Confirmed (Live Exploit)
Sources: SAST-05 · COMP-011 · PEN-002 · RED-003 | Specialists: static-analyzer · compliance-auditor · pen-tester · red-teamer
The limit query parameter accepts any integer with no maximum enforced, and in the live portal the params were silently ignored entirely — GET /api/bugs?limit=1&page=1 returned all 13 records. As the store grows this enables trivial bulk exfiltration of the entire dataset in a single request. Pentest objective #4 (enumerate all items without pagination) was fully achieved. CWE-400 / CWE-200.
Remediation In Source/Backend/src/routes/workItems.ts and dashboard.ts: enforce a hard cap — const limit = Math.min(parseInt(req.query.limit as string, 10) || 20, 100);. Add NaN guard: isNaN(parsedLimit) ? 20 : parsedLimit. Verify the portal backend applies the same fix.
H-002 Cascade Auto-Promotion — Unauthorized State Transition via Blocker Rejection High Confirmed (Live Exploit)
Sources: PEN-006 · RED-004 | Specialists: pen-tester · red-teamer
Completing a blocking work item automatically promotes all dependent items in the live environment. An attacker who can manipulate any upstream blocker (via the unauthenticated API) can trigger cascading, unauthorized state changes across all dependent items simultaneously. Pentest objective #3 (unauthorized state change via dependency) was fully achieved.
Remediation Cascade promotions must be gated behind the same authorization as manual transitions — verify that the initiating actor has permission to transition all affected items before executing any cascade. Consider making auto-promotion an async job rather than synchronous side-effect, with explicit audit logging of each cascaded transition.
H-003 Ghost Dependency DoS — Soft-Deleted Blocker Permanently Freezes Dependents High Confirmed (Live Exploit)
Sources: PEN-005 · RED-005 | Specialists: pen-tester · red-teamer
Soft-deleting (or hard-deleting in the portal) a blocking work item leaves its dependency links in place. Any work item that referenced the now-deleted blocker enters a permanent dispatch freeze — it can never be dispatched because it will always appear to have an outstanding blocker. Pentest objective #2 (access/affect soft-deleted item via direct reference) was fully achieved. An attacker can permanently disable high-value work items by deleting their blockers.
Remediation On soft/hard delete of a work item, cascade to remove or nullify all blockedBy/blocks references in linked items. Alternatively, add a validation step in the dispatch logic that filters out deleted blockers before evaluating block status. Add an index/query to detect orphaned dependency links.
🟠 High — Theoretical (6)
H-004 Internal Error Messages Leaked to API Clients High Theoretical
Sources: SAST-02 · COMP-009 | Specialists: static-analyzer · compliance-auditor
Every catch block in Source/Backend/src/routes/workflow.ts returns err.message verbatim to the caller (7 locations). When a future database or external service layer throws, internal stack trace fragments, file paths, or configuration details will be exposed. The global errorHandler.ts is bypassed because route handlers send the response before reaching it. CWE-209. Violates OWASP-ASVS L2 V7.4.1.
Remediation Replace all res.status(500).json({ error: message }) calls in workflow.ts with next(err) to route errors through the central errorHandler. The raw message is already logged server-side; clients should receive only { error: 'Internal server error' }.
H-005 Intake Webhook — No HMAC Signature Verification High Theoretical
Sources: SAST-03 · COMP-008 | Specialists: static-analyzer · compliance-auditor
POST /api/intake/zendesk and POST /api/intake/automated accept any payload with no caller authentication and no HMAC-SHA256 signature check. Any external party can inject arbitrary work items into the workflow engine. CWE-345. Violates OWASP-ASVS L2 V4.1.1 and SOC2 CC6.2.
Remediation For /zendesk: verify X-Zendesk-Webhook-Signature using a shared HMAC secret from process.env.ZENDESK_WEBHOOK_SECRET. For /automated: require a pre-shared API key in the Authorization header. Store all secrets in .env.
H-006 No TLS / HTTPS Enforcement High Theoretical
Sources: COMP-002 | Specialists: compliance-auditor
The application binds to plain HTTP with no TLS termination, no HTTP→HTTPS redirect, and no HSTS header. All API traffic — including any credentials once authentication is added — will transit in cleartext. Violates OWASP-ASVS L2 V9.1.1, V9.1.2 and SOC2 CC6.1 (data in transit).
Remediation Terminate TLS at the reverse proxy layer (nginx/Caddy/ALB) in any non-local environment. Configure HTTP→HTTPS redirect. Add Strict-Transport-Security: max-age=31536000; includeSubDomains header (also addressed by H-007 / helmet).
H-007 Missing HTTP Security Headers — No Helmet High Theoretical
Sources: SAST-06 · COMP-003 | Specialists: static-analyzer · compliance-auditor
No security-oriented HTTP response headers are set: missing Content-Security-Policy, X-Content-Type-Options, X-Frame-Options, Strict-Transport-Security, Referrer-Policy, Permissions-Policy. Enables clickjacking, MIME sniffing, and CSP bypass. CWE-693. Violates OWASP-ASVS L2 V14.4.1–V14.4.6. This is a one-line fix with high compliance return.
Remediation Add helmet as the first middleware in app.ts: import helmet from 'helmet'; app.use(helmet());. Tune the CSP for the API's specific needs. Estimated effort: 15 minutes.
H-008 Required Audit Events Missing — login_attempt, permission_denied, data_export High Theoretical
Sources: COMP-004 | Specialists: compliance-auditor
Three of four mandatory audit events from security.config.yml are absent: login_attempt, permission_denied, data_export. Only state_transition is partially covered by changeHistory. Without these events, the SOC2 CC7.1 audit trail is materially incomplete. Note: login_attempt and permission_denied are blocked by the absence of auth (C-001).
Remediation Implement auth first (C-001). Then add a dedicated auditLog() function emitting structured events with event_type, actor, resource_id, outcome, timestamp. Emit data_export on bulk reads; permission_denied in every auth guard rejection.
H-009 No Session Management — No Timeout, Binding, or Invalidation High Theoretical
Sources: COMP-005 | Specialists: compliance-auditor
No session management exists. When authentication is added, OWASP-ASVS L2 V3.1–V3.3 requires: session tokens expire after idle periods, absolute session lifetime enforced, re-authentication on privilege escalation, and new tokens issued on privilege change. These controls must be designed in from the start.
Remediation Use short-lived JWT access tokens (≤15 min) with refresh-token rotation, or server-side sessions with idle timeout. Enforce absolute session lifetime and re-authentication for high-privilege actions (approve, dispatch).

M-002 No Rate Limiting on Any Endpoint Medium Confirmed (Live Exploit)
Sources: SAST-07 · COMP-007 · PEN-012 · RED-008 | Specialists: all
No rate limiting applies to any route. State-transition endpoints, intake webhooks, and read endpoints can all be called at unlimited frequency. Enables denial-of-service by flooding the in-memory store and, once auth is added, brute-force attacks on login. CWE-770. Violates OWASP-ASVS L2 V4.2.2.
Remediation Add express-rate-limit: strict limits (5–10 req/min) on state-mutation and future auth endpoints; moderate limits (100 req/min) on reads. Apply a global baseline. Configure in app.ts before route mounts.

M-003 NeedsClarification Verdict Silently Maps to Rejected Status Medium Theoretical
Sources: PEN-007 | Specialists: pen-tester
When an assessment verdict of NeedsClarification is submitted, the routing logic silently maps it to Rejected status with no indication to the caller or any audit event. This is a silent semantic error: operators expecting a "pending clarification" hold will instead see the item as rejected. Could mask business logic errors and mislead operators.
Remediation Either add a distinct PendingClarification status to the state machine, or explicitly return an error if NeedsClarification is submitted without a clarification handler. Log the silent mapping as a warning audit event in the interim.
M-004 No Request Body Size Limits — Memory Exhaustion DoS Medium Theoretical
Sources: PEN-009 | Specialists: pen-tester
Source/Backend applies no body size limit to Express's json() parser. A sufficiently large JSON payload could exhaust Node.js heap memory, crashing the process. Note: the portal backend has a 16 KB cap but returns 500 instead of 413 on overflow — both backends need this addressed.
Remediation Set a body size limit: app.use(express.json({ limit: '1mb' })). Fix the portal backend's error code to return 413 (Payload Too Large) rather than 500.
M-005 Intake Webhooks Accept Unvalidated Enum Fields Medium Theoretical
Sources: PEN-004 | Specialists: pen-tester
The intake endpoints do not validate enum-type fields in the request body (e.g., priority, type). Arbitrary string values can be injected and persist in the store, potentially breaking downstream routing logic that pattern-matches on these fields. The portal backend mitigates this at the service layer; Source/Backend does not.
Remediation Add enum validation at the route or service layer for all controlled-vocabulary fields. Use a validation library (e.g., zod, joi) to define and enforce input schemas on all intake endpoints.
M-006 Audit Log Actor Identity Is Anonymous Medium Theoretical
Sources: COMP-010 | Specialists: compliance-auditor
The trackUpdates function is called with the literal string 'user' as the actor. All change history records show agent: 'user' with no real identity. Without actor identity, audit logs cannot support forensic investigations or SOC2 CC7.1 compliance. Blocked by C-001 (no auth = no identity).
Remediation After implementing auth (C-001), thread the authenticated user ID from req.user into trackUpdates and all buildChangeEntry calls. Add actorId and actorRole as first-class fields on ChangeHistoryEntry.
M-007 No CORS Policy Configured on Backend Medium Theoretical
Sources: COMP-012 · PEN-011 | Specialists: compliance-auditor · pen-tester
No CORS middleware is applied to the Express backend. In production the backend accepts cross-origin requests from any origin. The Vite proxy only applies during local development. Violates OWASP-ASVS L2 V14.5.1, V14.5.3. Note: the portal backend mitigates this by restricting to localhost:5173.
Remediation Add cors middleware early in app.ts: app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') ?? [] }));. Set ALLOWED_ORIGINS in .env per environment.
