Consolidated Findings

🔴 Critical — Confirmed Live Exploit

CRIT-001 No Authentication on Any Endpoint — Full Anonymous CRUD Critical Confirmed

Merged from: SAST-001 · PEN-001 · RED-001 · COMP-001 · COMP-002-ref

Specialists: static-analyzer, pen-tester, red-teamer, compliance-auditor

The Express application registers no authentication middleware of any kind. Every endpoint — create, read, update, delete, approve, reject, dispatch, and all workflow transitions — is callable by any unauthenticated caller with network access. The red-teamer confirmed full CRUD (create/read/delete) without credentials against the live environment.

CWE: CWE-306 (Missing Authentication for Critical Function)

Remediation:

  1. Add JWT authentication middleware (express-jwt) before all /api/* routes in app.ts.
  2. Implement RBAC — at minimum distinguish read consumers from write/dispatch/approve operators.
  3. Add HMAC signature validation (X-Hub-Signature-256) to both intake endpoints.
  4. Protect /metrics with IP allowlist or HTTP Basic auth.
CRIT-002 State Machine Bypass via Unauthenticated Force-Approve Critical Confirmed

Merged from: PEN-003 · RED-003 · PEN-002 (related)

Specialists: pen-tester, red-teamer

The POST /api/feature-requests/:id/force-approve endpoint requires no authentication, no minimum vote count, and performs no state-machine pre-condition checks. The red-teamer confirmed: a work item at any status can be instantly moved to Approved with zero votes. Additionally, PEN-002 identified that overrideRoute: "fast-track" bypasses the assessment pod entirely in the Source backend.

Exploit:

POST /api/feature-requests/:id/force-approve   (no auth, no body required)
→ HTTP 200: item status = "approved" with 0 votes

Remediation: Require admin RBAC on this endpoint. Validate item is in a state that permits approval. Enforce minimum vote threshold. Remove or gate the overrideRoute parameter behind an admin privilege check.

CRIT-003 Unauthenticated Pipeline Injection — Full Pipeline Takeover Critical Confirmed

Source: RED-007

Specialists: red-teamer

POST /api/cycles requires no authentication and immediately triggers a live development pipeline run. Combined with CRIT-001 and CRIT-002, an anonymous attacker can take a feature request from creation to active pipeline execution in four unauthenticated HTTP calls:

1. POST /api/feature-requests          → Create FR (no auth)
2. PATCH /api/feature-requests/:id     → Move to "voting" (no auth)
3. POST /api/feature-requests/:id/force-approve  → Approve with 0 votes (no auth)
4. POST /api/cycles                    → Inject dev cycle → live pipeline triggered (no auth)

Remediation: Require authentication + admin authorization on POST /api/cycles. Validate the referenced work item is in a legitimate approved state before cycle creation. Add an allowlist of items that can be included in a cycle.

🟠 High — Confirmed Live Exploit

HIGH-001 No Pagination Ceiling — Full Dataset Enumeration in One Request High Confirmed

Merged from: SAST-003 · PEN-004 · RED-004

Specialists: static-analyzer, pen-tester, red-teamer

The limit query parameter is accepted without an upper bound. GET /api/work-items?limit=9999999 and GET /api/bugs?limit=-1 both return the entire dataset. The red-teamer confirmed full enumeration of all items in a single response.

Remediation: Add const safeLimit = Math.min(parseInt(req.query.limit) || 20, 100) in all list route handlers. Reject non-positive values. Return X-Total-Count header for legitimate pagination.

HIGH-002 Soft-Delete IDOR — Deleted Item UUID Leaks, Victim Permanently Blocked High Confirmed

Merged from: PEN-007 · RED-005

Specialists: pen-tester, red-teamer

When a work item with dependents is soft-deleted, its UUID continues to appear in dependent items' blocked_by[] arrays via the /ready endpoint. The deleted item can still be referenced by ID and blocks dispatch of the dependent item permanently. Confirmed live by red-teamer.

Remediation: On soft-delete, clean all blocked_by references to the deleted item across dependent work items. Alternatively implement cascade-to-blocked-state logic. Add a separate purgeWorkItem operation for hard deletion.

HIGH-003 Stored XSS — Script Payloads Stored Verbatim High Confirmed

Source: RED-006 · COMP-010 · SAST-009 (related)

Specialists: red-teamer, compliance-auditor, static-analyzer

The red-teamer confirmed that <script>alert(1)</script> and <img onerror=alert(1)> payloads in title and description fields are stored verbatim without sanitization. While the React frontend JSX auto-escapes, any non-React consumer (admin tool, CSV export, future mobile client) will execute these payloads.

Remediation: Strip/escape HTML at write time using isomorphic-dompurify or validator.js escape(). Add Content-Security-Policy (via Helmet — see MED-005) as defence-in-depth. Enforce max-length on all free-text fields.

HIGH-004 Unauthenticated /metrics Endpoint — Internal Telemetry Exposed High Confirmed

Merged from: SAST-004 · PEN-011 · RED-002 · COMP-007

Specialists: static-analyzer, pen-tester, red-teamer, compliance-auditor

GET /metrics returns full Prometheus operational data (item counts, route labels, Node.js process stats, team names) to any unauthenticated caller. Confirmed live by red-teamer. Aids reconnaissance — attacker can identify high-value state transitions and internal routing labels.

Remediation: Restrict to Prometheus scraper IP via allowlist, or add HTTP Basic auth middleware before the route. Must not be publicly accessible.

🟠 High — Theoretical (Unconfirmed by Red Team)

HIGH-005 Webhook Intake Lacks HMAC Signature Verification High Theoretical

Merged from: SAST-002 · PEN-006

Specialists: static-analyzer, pen-tester

Source/Backend/src/routes/intake.ts (lines 12–32) accepts Zendesk and automated webhook payloads with no X-Hub-Signature-256 or shared-secret verification. Any party with network access can inject arbitrary work items, forge Zendesk tickets, or flood the in-memory store. CWE-345.

Remediation: Verify X-Hub-Signature-256 HMAC-SHA256 against a ZENDESK_WEBHOOK_SECRET and INTAKE_WEBHOOK_SECRET env var before processing any intake payload.

HIGH-006 Assessment Pod Bypassed via overrideRoute Parameter High Theoretical

Source: PEN-002 · PEN-008

Specialists: pen-tester

Sending { "overrideRoute": "fast-track" } in a routing request bypasses the assessment pod and directly approves the item. No RBAC check gates this parameter. Any arbitrary string is accepted and stored without an enum guard (PEN-008).

Remediation: Validate overrideRoute against a strict enum; require admin privilege. Reject unknown values with HTTP 400.

HIGH-007 Intake Routes Accept Unvalidated Enum Values High Theoretical

Source: PEN-005

Specialists: pen-tester

type and priority fields in intake routes accept arbitrary strings and are stored without enum validation. This can corrupt the routing state machine by injecting unknown states.

Remediation: Add Zod/Joi schema validation on all intake payloads. Reject with HTTP 422 if type or priority is not in the defined enum.

HIGH-008 No TLS/HTTPS Enforcement High Theoretical

Source: COMP-002

Specialists: compliance-auditor

Backend listens on plain HTTP (http://localhost:3001). No TLS termination, no HTTP→HTTPS redirect, no HSTS. In any production deployment all traffic travels unencrypted. Violates GDPR Art. 32(1)(a), OWASP-ASVS V9.1.1.

Remediation: Terminate TLS at a reverse proxy (nginx/Caddy). Add HSTS header via Helmet once added. Redirect all HTTP to HTTPS.

HIGH-009 Missing Required Audit Log Events (SOC2 CC7.1) High Theoretical

Source: COMP-005

Specialists: compliance-auditor

The four mandatory audit events in security.config.yml — login_attempt, permission_denied, state_transition, data_export — are not emitted. The first two are impossible without an auth layer. state_transition is written to the data model but never emitted as a structured log event. No immutable audit trail exists.

Remediation: Create an auditLogger in utils/logger.ts with structured event fields. Emit events from auth middleware and all workflow handlers. Establish a separate log channel for security-relevant events.
