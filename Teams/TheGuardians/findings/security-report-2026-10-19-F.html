🔴 CRITICAL — Confirmed Live Exploit

CRIT-001 Critical Confirmed (Live Exploit) Authentication Entirely Absent — State Machine Bypass Confirmed

Sources: SAST-001 / PEN-001 / PEN-002 / PEN-003 / COMP-001 / RED-001  |  CWE-306

No authentication middleware exists anywhere in the Express application. Every endpoint — CRUD, state transitions, approvals, dispatch — is reachable without credentials. Red team confirmed a 3-request unauthenticated chain:

POST /api/work-items                                        → create item
POST /api/work-items/:id/route {"overrideRoute":"fast-track"} → approved (no assessment)
POST /api/work-items/:id/dispatch                             → in-progress

Also confirmed via force-approve: item FR-0001 reached approved with votes: [] — zero AI votes cast, assessment pod never invoked.

Remediation: Add JWT/API-key middleware globally to all /api/* routes in app.ts before route registration. Privilege-gate approve, dispatch, reject, force-approve, and route endpoints with role checks. Remove or admin-gate direct PATCH /status capability.

CRIT-002 Critical Confirmed (Live Exploit) Cascade Auto-Dispatch via Duplicate/Terminal Status

Sources: RED-005 / PEN-007 / PEN-003  |  CWE-284

STATUS_TRANSITIONS allows any item to be set to duplicate or deprecated from any status — unauthenticated, no justification required. This triggers onItemCompleted(), which auto-promotes all dependent items from pending_dependencies → approved bypassing all assessment and voting. Red team confirmed: FR-0009 jumped from pending_dependencies → approved immediately after FR-0010 was set to duplicate. Novel finding — not in pen-tester map.

Remediation: Restrict duplicate/deprecated transitions to authenticated admin users. Trigger cascade only from privileged-action terminal states, not freely-settable ones.

🟠 HIGH — Confirmed Live Exploit

HIGH-001 High Confirmed (Live Exploit) Ghost Blocker Permanent Denial of Service

Sources: PEN-006 / RED-002

Deleting a blocker item leaves its dependency link in the dependent's blocked_by array. findById returns undefined for deleted items; computeHasUnresolvedBlockers treats undefined as an unresolved blocker. Dependent permanently stuck. Additionally, denied is absent from RESOLVED_STATUSES — denying a blocker also permanently blocks all its dependents.

Remediation: Cascade-delete dependency links on item deletion. Add denied to RESOLVED_STATUSES. Add cleanup API for orphaned references.

HIGH-002 High Confirmed (Live Exploit — storage confirmed) Stored XSS in Title Fields

Sources: RED-003 / PEN-010 / PEN-004

HTML payloads (<script>alert(document.cookie)</script>, <svg onload=alert(1)>) accepted and stored verbatim in feature_requests and bugs tables. Payloads appear in all GET and search responses. Browser execution risk if frontend renders without sanitization → session hijack.

Remediation: Sanitize free-text input server-side on ingestion. Add CSP header blocking inline scripts. Verify frontend renders via React JSX (auto-escapes) and never via dangerouslySetInnerHTML.

HIGH-003 High Confirmed (Live Exploit) Pagination Entirely Unenforced — Full Dataset Enumeration

Sources: SAST-004 / PEN-005 / COMP-012 / RED-004

limit=999999, limit=0, and limit=abc (NaN) all return the complete dataset in a single unauthenticated response. Red team confirmed with 4 DB items: every limit variant returned all 4.

Remediation:

const rawLimit = parseInt(req.query.limit as string, 10);
const limit = (!isNaN(rawLimit) && rawLimit > 0) ? Math.min(rawLimit, 100) : 20;

🟠 HIGH — Theoretical

HIGH-004 High Theoretical Webhook Intake — No Authentication or Signature Verification

Sources: SAST-002 / PEN-004 / COMP-002  |  CWE-345

POST /api/intake/zendesk and POST /api/intake/automated accept work item creation from any unauthenticated caller. No HMAC-SHA256 signature validation. type and priority fields pass through without enum validation.

Remediation: Validate X-Zendesk-Webhook-Signature against a HMAC-SHA256 HMAC over the raw body using a pre-shared secret from process.env. Add enum guards identical to those in workItems.ts.

HIGH-005 High Theoretical Three of Four Required Audit Events Missing

Sources: COMP-003 (SOC2 CC7.1 failure)

Required events: login_attempt, permission_denied, state_transition, data_export. Only state_transition present. The first two cannot exist without authentication.

Remediation: After CRIT-001 is fixed, wire audit log entries for auth attempts, authorization denials, and data exports.

HIGH-006 High Theoretical No TLS/HTTPS Enforcement

Sources: COMP-007

Server runs plain HTTP. All API traffic transmitted in cleartext.

Remediation: TLS termination at reverse proxy (nginx/Caddy). HSTS once Helmet applied.

HIGH-007 High Theoretical No Multi-Factor Authentication Support

Sources: COMP-010 (cascades from CRIT-001)

MFA cannot exist without authentication. Required by OWASP-ASVS L2 and SOC2 CC6.1 for privileged accounts.

Remediation: Implement TOTP or WebAuthn after CRIT-001 is resolved.

🟡 MEDIUM — Confirmed Live Exploit

MED-001 Medium Confirmed (Live Exploit) Prometheus /metrics Endpoint Unauthenticated

Sources: SAST-007 / PEN-008 / COMP-008 / RED-006  |  CWE-200

Red team confirmed: GET /metrics returns full Prometheus text including route paths, HTTP methods, status codes, response times, team names (TheATeam, TheFixer), and runtime memory/CPU. An invalid Authorization: Bearer header is silently ignored.

Remediation: Separate internal port or IP allowlist. Never expose to public internet.
