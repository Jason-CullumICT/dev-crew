🛡 Executive Summary

The dev-crew Source App has zero authentication on any API endpoint. Every workflow transition — approval, rejection, dispatch, force-approve — is reachable by any unauthenticated network client. The red team confirmed all 4 pentest objectives in a live ephemeral environment using 13 attack chains, achieving 6 confirmed breaches including two Critical exploits.

Top 3 Risks:

  1. 🔴 Complete Authentication Bypass (Confirmed) — Anonymous callers can read, create, approve, and dispatch any work item. The entire API surface is open.
  2. 🔴 Full Pipeline Bypass via Force-Approve Chain (Confirmed) — 4 HTTP requests with zero credentials bypass all human review gates and push items into production pipelines.
  3. 🟠 Stored XSS via Description Field (Confirmed) — Script payloads stored verbatim and returned unescaped; any non-JSX rendering path executes attacker code.

🔴 Critical Findings

F-001 · SAST-001 · PEN-001 · RED-001
No Authentication on Any API Endpoint
Confirmed (Live Exploit)

CWE-306 · Source/Backend/src/app.ts:12–44

No authentication middleware is registered. All 10+ endpoints — including approve, reject, dispatch, force-approve — are callable by any unauthenticated network client. Red team confirmed anonymous GET/POST/PATCH/DELETE succeeded on every endpoint.

Remediation: Add JWT Bearer middleware globally before all route registrations. Create POST /api/auth/login. Install bcrypt.

F-002 · PEN-002 · RED-002
Full Pipeline Bypass via Force-Approve Chain
Confirmed (Live Exploit)

CWE-284 · Source/Backend/src/routes/workflow.ts

4 HTTP requests, zero credentials → item dispatched to production. Steps: (1) POST create, (2) POST vote, (3) POST force-approve bypassing all review gates, (4) PATCH status to in_development. Objective "Bypass work item state machine" achieved.

Remediation: Gate force-approve behind authentication AND approver role. Re-validate item status server-side before accepting any transition.

🟠 High Findings

F-003 · PEN-007 · RED-003
Soft-Delete Creates Permanent Dependency Deadlock
Confirmed (Live Exploit)

CWE-672 · Source/Backend/src/store/workItemStore.ts

Soft-deleting a blocker leaves dependents permanently stuck (has_unresolved_blockers: true). Dependency links are never cleaned up. Red team confirmed: deleted FR-0002, FR-0003 immediately stuck and confirmed un-dispatchable via /ready endpoint.

Remediation: On soft-delete, cascade-resolve dependency links. Distinguish "not found" from "soft-deleted" in findById.

F-004 · RED-004
Stored XSS via Unsanitized Description Field
Confirmed (Live Exploit)

CWE-79 · Source/Backend/src/routes/workItems.ts

PATCH with {"description":"<script>alert(1)</script>"} stores payload verbatim and returns it unescaped in all subsequent GETs. Any non-JSX frontend rendering path will execute attacker JavaScript. Not caught by SAST — discovered by red team.

Remediation: Server-side strip HTML from all free-text fields using sanitize-html. Add CSP headers. Audit frontend for dangerouslySetInnerHTML.

F-005 · SAST-002 · PEN-003 · COMP-009
Missing Webhook Signature Validation + Enum Field Injection
Theoretical

CWE-345 + CWE-20 · Source/Backend/src/routes/intake.ts:11–54

Zendesk and automated intake endpoints accept arbitrary POST requests with no HMAC verification. type/priority fields bypass enum validation, allowing injection of invalid state values into the workflow engine.

Remediation: Validate X-Zendesk-Webhook-Signature HMAC-SHA256. Add enum guards matching workItems.ts. Require bearer token for /automated.

F-006 · PEN-004
Reject Triggers Unintended Auto-Dispatch Cascade
Theoretical

CWE-841 · Source/Backend/src/routes/workflow.ts

Rejecting a blocker item auto-dispatches all previously approved dependents without operator confirmation. Remediation: Gate cascade behind explicit confirmation flag; add dry-run preview endpoint.

F-007 · PEN-005
Approve Reachable from routing Transient Status
Theoretical

CWE-284 · Source/Shared/src/types.ts (VALID_STATUS_TRANSITIONS)

routing → approved is permitted via the external approve endpoint. routing is a transient machine-managed state; it should not accept external approvals. Remediation: Remove approved as a valid target from routing status.

F-008 · COMP-002
No Role-Based Access Control (RBAC)
Theoretical

CWE-285 · Source/Backend/src/routes/workItems.ts, workflow.ts

Even after authentication is added, any authenticated user can approve, reject, or dispatch. manual-override in audit entries is hardcoded, not from identity. Remediation: Define roles in JWT claims; add RBAC middleware per route.

F-009 · COMP-007
No TLS / HTTPS Enforcement
Theoretical

CWE-311 · Source/Backend/src/app.ts, docker-compose.test.yml

Application binds to plain http://localhost:3001. No TLS configured. Remediation: TLS-terminating reverse proxy; HTTP→HTTPS redirect; HSTS header.
