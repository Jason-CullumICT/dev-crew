1. Executive Summary

The dev-crew application (Source/Backend workflow engine + portal/Backend portal) has no authentication or authorization layer whatsoever. Every API endpoint is fully open to anonymous callers over the network. The red-teamer achieved 3 of 4 primary pentest objectives — bypassing the state machine, bypassing the AI assessment pod, and enumerating the full dataset — without a single credential. Data corruption of any record is confirmed in one unauthenticated HTTP request. The compliance pass rate is 29% (5 of 17 assessed controls). The application must not be deployed to any shared environment until at minimum the authentication/authorization layer is in place.

Top 3 Risks
  1. Complete authentication absence — any network actor can read, write, or delete every record and bypass all workflow gates.
  2. State machine fully bypassable via unauthenticated PATCH — items can be force-approved to approved status with zero AI votes and no human identity in under 2 requests.
  3. No pagination enforcement — the entire dataset is returned in a single unauthenticated GET request with no limit whatsoever on the portal backend.

2. Consolidated Findings

PEN-IDs confirmed by RED-IDs are merged. Status: Confirmed (Live Exploit) indicates active exploitation in the ephemeral test environment. Theoretical indicates static/logical analysis without live confirmation.

🔴 Critical

MERGED-001 Zero Authentication / Authorization — All Endpoints Fully Open Critical Confirmed (Live Exploit)
The Express application registers zero authentication or authorization middleware. Every endpoint — including state transitions (/approve, /reject, /dispatch), data writes (POST /api/work-items, PATCH /api/feature-requests/:id), and deletes — is fully open to anonymous callers. No JWT, no session, no API key, no RBAC. Red-teamer confirmed: all 10+ discovered endpoints return 200/201/204 with no Authorization header. Full record corruption (description, priority, status) achieved unauthenticated in a single PATCH.
Sources: SAST-001 · COMP-001 · COMP-002 · PEN-001 → RED-001 · RED-006  |  Specialists: static-analyzer · compliance-auditor · pen-tester · red-teamer
CWE: CWE-306 · CWE-862  |  OWASP: A01:2021 (Broken Access Control) · A07:2021 (Auth Failures)
Remediation:
  1. Add JWT authentication middleware globally before all /api/* routes in app.ts.
  2. Implement POST /api/auth/login that validates credentials and issues a signed JWT (use jsonwebtoken).
  3. Add RBAC middleware: define roles (submitter, reviewer, approver, admin) and restrict state-transition endpoints accordingly.
  4. Propagate authenticated identity (userId, role) into request context for audit logs.
  5. Rotate the plaintext password in CLAUDE.md and never store credentials in documentation.
MERGED-002 State Machine Bypass — Approved with Zero Votes, No Auth, No Assessment Critical Confirmed (Live Exploit)
Two independent bypass paths reach approved status without any legitimate assessment:

Path A — PATCH bypass (portal/Backend): Unauthenticated PATCH {"status":"voting"} followed by PATCH {"status":"approved"} moves any item to approved with votes=[] and human_approval_approved_at=null — zero votes, no identity. Confirmed by RED-002.

Path B — overrideRoute fast-track (Source/Backend): POST /api/work-items/:id/route with body {"overrideRoute":"fast-track"} skips the entire assessment pod and immediately sets status to approved in 1 request. Confirmed conceptually; portal equivalent confirmed by RED-003 (force-approve endpoint requires no credentials).

Combined with MERGED-001, any anonymous actor can bypass the entire AI voting workflow in 2–3 HTTP requests.
Sources: PEN-003 · PEN-004 → RED-002 · RED-003  |  Specialists: pen-tester · red-teamer
CWE: CWE-284 · CWE-269  |  Objective: ✅ ACHIEVED — "Bypass state machine" + "Submit malformed verdict bypassing routing"
Remediation:
  1. Remove status from PATCH-updateable fields. Status transitions must only occur via dedicated workflow action endpoints.
  2. Restrict /force-approve and /approve to authenticated users with an approver or admin role.
  3. Restrict overrideRoute to administrators only; validate it against the WorkItemRoute enum.
  4. Audit-log approver identity on every state transition.

🟠 High

MERGED-003 No Pagination Enforcement — Full Dataset Enumeration in One Request High Confirmed (Live Exploit)
The portal backend (portal/Backend) has no pagination whatsoever — every GET /api/feature-requests, GET /api/bugs, GET /api/cycles returns the full dataset without limit. The workflow backend (Source/Backend) accepts an unbounded ?limit=999999 parameter (no max cap; parseInt of non-numeric returns NaN causing unbounded slices). Red-teamer confirmed 16 items returned in a single unauthenticated GET with no limit parameter needed.
Sources: SAST-006 · PEN-002 → RED-004  |  Objective: ✅ ACHIEVED — "Enumerate all work items without pagination limit enforcement"
Remediation: Implement server-side pagination with a default limit (20) and enforced maximum (100). Cap in Source/Backend: Math.min(Math.max(1, parsedLimit || 20), 100). Add NaN guard. Return {data, total, page, limit, totalPages} structure. Reject limit above max with HTTP 400.
MERGED-004 Webhook Endpoints Accept Payloads Without Signature Verification High Theoretical
POST /api/intake/zendesk and POST /api/intake/automated accept arbitrary POST bodies with no HMAC signature check, no shared secret, no IP allowlist. An attacker can inject fabricated work items into the pipeline. Additionally, the type and priority fields are passed to the store without enum validation — unlike the main work-items POST — allowing corrupt enum values to be stored (e.g., type="xss-payload"), which silently bypass routing classification logic.
Sources: SAST-002 · SAST-003 · COMP-003 · PEN-005  |  CWE: CWE-345 · CWE-20
Remediation: Validate the Zendesk HMAC signature (X-Zendesk-Webhook-Signature). Require an API key on automated intake. Add IP allowlisting. Mirror enum validation from workItems.ts lines 29–42 into both intake handlers.
COMP-004 Required Audit Events Not Logged (3 of 4 Missing) High Theoretical
Security config mandates four audit events. Only state_transition is partially implemented (without a structured event: field). Missing: login_attempt (no login endpoint), permission_denied (no access control → no 403s), data_export (not implemented). This directly fails SOC2 CC7.1.
Sources: COMP-004  |  Framework: SOC2 CC7.1 · CC7.2
Remediation: After implementing auth (MERGED-001): emit structured {event:"login_attempt",success,userId,ip} on every login; {event:"permission_denied",userId,action,resource} on every 403; add event:"state_transition" field to all existing transition logs.
COMP-005 No TLS / HTTPS Enforcement — All Data in Cleartext High Theoretical
The backend binds to plain HTTP with no HTTPS redirect middleware, no HSTS header, and no TLS configuration. All data — including future auth tokens — would travel in cleartext. Directly fails SOC2 CC6.7 and OWASP-ASVS 9.1.1/9.1.2.
Sources: COMP-005  |  Framework: SOC2 CC6.7 · ASVS 9.1.1
Remediation: In production, terminate TLS at a reverse proxy (nginx/Caddy). Add HTTP→HTTPS redirect middleware for NODE_ENV=production. Add helmet.hsts() for Strict-Transport-Security headers.
PEN-006 Cascade Auto-Dispatch Chain via Dependency + Rejection Manipulation High Theoretical
An attacker can manufacture an unauthorized cascade auto-dispatch: create two items, approve both unauthenticated, add item A as a blocker for item B, then reject A. The onItemResolved callback triggers and auto-dispatches B to a team — completing the full backlog → proposed → approved → in-progress pipeline traversal without any legitimate workflow, using only the cascade trigger. Root cause: combines PEN-001 (no auth), PEN-004 (unauthenticated approve), and unprotected dependency management endpoint.
Sources: PEN-006  |  CWE: CWE-284
Remediation: Authentication on all endpoints (MERGED-001) neutralizes this chain. Additionally, restrict dependency management to authenticated users with write permission on both items.

MERGED-005 Unauthenticated /metrics Endpoint — Operational Intelligence Leak Medium Confirmed (Live Exploit)
GET /metrics requires no credentials and returns 527+ Prometheus metric entries including HTTP route/status labels (revealing all valid and probed routes), request volumes, latencies, item counts by type/team, and process internals (CPU, memory, heap). Red-teamer observed 404 red-team probes visible in the metrics, confirming that an attacker's reconnaissance activity is itself reflected back to the attacker.
Sources: SAST-007 · PEN-009 → RED-005  |  CWE: CWE-200
Remediation: Restrict /metrics to internal networks via network policy, or require a scrape secret token (Authorization: Bearer <METRICS_TOKEN> from an env var).
MERGED-006 Orphaned Dependency DoS After Item Deletion (Recoverable) Medium Confirmed (Live Exploit)
Soft-deleting a blocker item causes computeHasUnresolvedBlockers to return true (treats !blocker as unresolved), permanently blocking a dependent item from dispatch in Source/Backend. In the portal, hard-delete creates an orphaned dependency link with status:"unknown" — confirmed by RED-007 — though recovery is possible via POST /dependencies {"action":"remove",...}. The Source/Backend version has no recovery path.
Sources: PEN-007 → RED-007  |  CWE: CWE-400
Remediation: Implement cascade delete — when an item is deleted, automatically remove it from all blocked_by lists. For Source/Backend: treat undefined blocker as resolved (not unresolved).
SAST-004 Error Messages Expose Internal Details to API Clients Medium Theoretical
Every catch block in workflow.ts (5 locations) sends the raw err.message to clients on HTTP 500, bypassing the global errorHandler. Internal exception messages can expose file paths, service internals, or logic details useful for reconnaissance.
Sources: SAST-004  |  CWE: CWE-209  |  File: Source/Backend/src/routes/workflow.ts:59,86,137,204,291
Remediation: Replace res.status(500).json({ error: message }) with res.status(500).json({ error: 'Internal server error' }). Continue logging full message server-side.
MERGED-007 Missing HTTP Security Headers (No helmet, No CSP, No HSTS) Medium Theoretical
No security headers are set on any response: missing Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, Strict-Transport-Security. The helmet package is not installed. Leaves browser clients exposed to clickjacking, MIME sniffing, and XSS injection.
Sources: SAST-005 · COMP-006  |  CWE: CWE-693  |  Framework: ASVS 14.4.x
Remediation: npm install helmet; add app.use(helmet()) as first middleware in app.ts. Configure restrictive CSP: defaultSrc: ["'self'"].
COMP-007 No CORS Policy Configured Medium Theoretical
No CORS middleware is registered. Once auth tokens are added, an open CORS posture would allow any authenticated browser session to be used cross-origin by a malicious page.
Sources: COMP-007  |  Framework: ASVS 14.5.x
Remediation: npm install cors @types/cors; configure cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') }); never use origin:'*' with credentials.
COMP-008 No Rate Limiting on Any Endpoint Medium Theoretical
No rate-limiting middleware exists. Intake webhook endpoints are particularly exposed: they create work items on each request and can be used for resource exhaustion or data poisoning (unlimited creation). Fails SOC2 CC6.6 and OWASP-ASVS 4.4.2.
Sources: COMP-008  |  Framework: ASVS 4.4.2 · SOC2 CC6.6
Remediation: npm install express-rate-limit; global limiter (200 req/min/IP); tighter limit on intake routes (10 req/min).
PEN-008 NaN and Negative Pagination Parameters Cause Unexpected Data Slices Medium Theoretical
page=-1 returns items from the end of the sorted array; limit=0 returns totalPages:Infinity in JSON; page=NaN returns empty array silently with no error. These produce unexpected data windows and malformed responses.
Sources: PEN-008  |  CWE: CWE-400
Remediation: Add guards: const page = Math.max(1, parseInt(...) || 1); const limit = Math.min(Math.max(1, parseInt(...) || 20), 100). Reject non-numeric with HTTP 400.
PEN-010 Arbitrary overrideRoute String Stored Verbatim — Data Integrity Violation Medium Theoretical
The overrideRoute body field bypasses TypeScript type safety at runtime: any truthy string is accepted and stored verbatim as the item's route field (e.g., route:"__proto__" or route:123), violating the WorkItemRoute enum contract. Downstream logic using item.route for routing decisions receives unexpected values.
Sources: PEN-010  |  CWE: CWE-20
Remediation: Validate overrideRoute against the WorkItemRoute enum values at runtime before use. Reject with HTTP 400 if not a valid enum member.
COMP-009 No MFA Support for High-Privilege Actions Medium Theoretical
OWASP-ASVS Level 2 requires MFA for high-value actions. Dependent on MERGED-001 remediation; listed separately as it requires explicit design once auth is in place.
Sources: COMP-009  |  Framework: ASVS 2.8.1 · SOC2 CC6.2
Remediation: After core auth: add TOTP-based MFA using speakeasy or otplib; enforce for approve, reject, dispatch actions.
