## CRITICAL FINDINGS (P1)

### DEP-001: Handlebars.js JavaScript Injection via AST Type Confusion

- **Severity:** P1 (Critical)
- **Category:** CVE (Code Injection)
- **Package:** `handlebars` ≤4.7.8
- **Affected Workspace:** Backend
- **Type:** Transitive (dep of a test/build dependency)
- **CVEs:**
  - GHSA-2w6w-674q-4c4q (CVSS 9.8 - Remote Code Execution)
  - GHSA-3mfm-83xf-c92r (CVSS 8.1 - Code Injection)
  - GHSA-xhpv-hc6g-r9c6 (CVSS 8.1 - Code Injection)
  - GHSA-9cx6-37pm-9jff (CVSS 7.5 - DoS)
  - GHSA-xjpj-3mr7-gcpf (CVSS 8.2 - Code Injection via CLI)
  - GHSA-2qvq-rjwj-gvw9 (CVSS 4.7 - XSS via Prototype Pollution)
  - GHSA-7rx3-28cr-v5wh (CVSS 4.8 - Prototype Bypass)

- **Detail:** Multiple critical JavaScript injection vulnerabilities in Handlebars template engine. Arbitrary code execution possible via AST manipulation, prototype pollution, and partial template injection. An attacker can inject malicious templates to execute arbitrary JavaScript.

- **Risk Assessment:**
  - If Backend uses Handlebars for template rendering with untrusted user input → **CRITICAL EXPLOIT RISK**
  - If Handlebars is only in build/test toolchain → **LOWER IMMEDIATE RISK** but still vulnerable to supply-chain attacks
  - **Current scope:** Unknown (need to grep for `handlebars` usage in Backend code)

- **Fix:**
  - Upgrade Handlebars to **≥4.7.9** (or latest 5.x if compatible)
  - Run: `npm update handlebars`
  - **If upgrade blocked:** Remove Handlebars dependency or isolate template rendering to sandbox

- **Verification:** After update, re-run `npm audit` to confirm no GHSA-2w6w-674q or GHSA-3mfm-83xf CVEs remain

- **Cross-ref:** [ESCALATE → TheGuardians] — Code injection + RCE risk. If templates accept user input, this is exploitable.

- **Timeline:** Fix within **24-48 hours**

### DEP-002: Vitest Critical File Read & Execution

- **Severity:** P1 (Critical)
- **Category:** CVE (Information Disclosure + RCE)
- **Package:** `vitest` <3.2.6 (Direct dependency in Frontend)
- **Affected Workspace:** Frontend
- **CVE:** GHSA-5xrq-8626-4rwp (CVSS 9.8 - Remote Code Execution)
- **Also depends on:** vite, @vitest/mocker, vite-node (all vulnerable)

- **Detail:** When Vitest UI server is listening (`vitest --ui`), **any remote attacker can read arbitrary files and execute code** on the machine running the test server. No authentication required. This is a critical local development vulnerability if the UI is exposed.

- **Attack Vector:**
  - Developer runs `npm test` with vitest UI exposed on localhost:5173
  - Attacker sends HTTP requests to read `/etc/passwd`, source code, `.env` files, etc.
  - Attacker can execute arbitrary code in the test runner's context

- **Risk Assessment:**
  - **If Vitest UI is used in development:** HIGH RISK (especially if machine is on a shared network)
  - **If Vitest UI is never exposed to network:** LOWER RISK but still vulnerable to malicious commits
  - **CI/CD risk:** If CI runs Vitest UI and logs expose it, critical

- **Fix:**
  - Upgrade Vitest to **≥3.2.6**
  - Upgrade Vite to **≥5.5.10** (peer dependency)
  - Run: `npm update vitest vite`
  - **Workaround:** Never expose Vitest UI outside localhost; never run UI in shared/CI environments

- **Verification:** `npm audit` should clear GHSA-5xrq-8626 and vite vulnerabilities

- **Cross-ref:** [ESCALATE → TheGuardians] — File read + RCE vulnerability in dev tooling. Affects all developers and CI.

- **Timeline:** Fix within **24-48 hours**

### DEP-003: Protobufjs Arbitrary Code Execution

- **Severity:** P1 (Critical)
- **Category:** CVE (Code Injection + RCE)
- **Package:** `protobufjs` <7.5.5 (Transitive in Orchestrator)
- **Affected Workspace:** Orchestrator (indirectly, via gRPC)
- **CVE:** GHSA-xq3m-2v4x-88gg (CVSS 9.8 - RCE)
- **Also includes:** 11 other HIGH/MODERATE CVEs (prototype pollution, DoS, code generation gadgets)

- **Detail:** Arbitrary code execution in protobufjs library used for Protocol Buffers serialization. An attacker can craft a malicious `.proto` file or JSON descriptor that, when loaded, executes arbitrary JavaScript. Multiple attack vectors: prototype pollution, recursive expansion, unsafe option parsing.

- **Attack Vector:**
  - Attacker provides a crafted protobuf message or schema
  - Orchestrator deserializes it without validation
  - Code generation step executes injected code in Node.js context
  - Full RCE with privileges of the Node process

- **Risk Assessment:**
  - If Orchestrator accepts proto files from untrusted sources → **CRITICAL**
  - If Orchestrator only uses bundled/trusted proto files → **LOWER IMMEDIATE RISK** but still vulnerability surface
  - **Scope:** Check if protobufjs is actively used or legacy dependency

- **Fix:**
  - Upgrade protobufjs to **≥7.5.5** (or ≥7.6.x for additional patches)
  - Run: `cd platform/orchestrator && npm update protobufjs`
  - **If outdated:** Remove dependency if no longer used

- **Verification:** `npm audit` should clear GHSA-xq3m-2v4x and related CVEs

- **Cross-ref:** [ESCALATE → TheGuardians] — Code injection + RCE in serialization library. Check for untrusted input paths.

- **Timeline:** Fix within **24-48 hours**

### DEP-004: form-data CRLF Injection

- **Severity:** P2 (High)
- **Category:** CVE (HTTP Header Injection)
- **Package:** `form-data` 4.0.0-4.0.5
- **Affected Workspaces:** Backend, Frontend, Orchestrator (transitive)
- **CVE:** GHSA-hmw2-7cc7-3qxx (CVSS 7.5 - HTTP Response Splitting)

- **Detail:** CRLF injection in multipart form field names and filenames. An attacker can craft form data with embedded `\r\n` sequences to inject arbitrary HTTP headers or split responses.

- **Attack Vector:**
  - Application accepts file upload with attacker-controlled filename
  - Filename embedded in form data contains `\r\nSet-Cookie: admin=true`
  - Server sends HTTP response, attacker injects session cookies or other headers

- **Risk Assessment:**
  - **If app handles file uploads:** MEDIUM-HIGH RISK
  - **If only internal form generation:** LOWER RISK
  - **Depends on:** Whether user input flows to form-data multipart generation

- **Fix:**
  - Upgrade form-data to **≥4.0.6**
  - Run: `npm update form-data` (in all workspaces)

- **Verification:** Re-run `npm audit` to confirm GHSA-hmw2-7cc7 is gone

- **Cross-ref:** [ESCALATE → TheGuardians] if file uploads are present

### DEP-006: brace-expansion DoS

- **Severity:** P2 (High)
- **Category:** CVE (Denial of Service)
- **Package:** `brace-expansion` <1.1.16 (Transitive)
- **Affected Workspace:** Backend
- **CVE:** GHSA-3jxr-9vmj-r5cp (CVSS 5.3 - DoS via exponential expansion)

- **Detail:** brace-expansion processes patterns with pathological nesting (e.g., `{}{}{}{...}`) that cause exponential-time expansion, exhausting CPU and memory. Can be triggered via glob patterns in build tools.

- **Attack Vector:**
  - Attacker crafts a build file or glob pattern with nested braces
  - Build process attempts to expand it
  - CPU hangs due to exponential expansion

- **Risk Assessment:**
  - **If build accepts user input:** MEDIUM RISK
  - **If only internal patterns:** LOWER RISK

- **Fix:**
  - Upgrade brace-expansion to **≥1.1.16**
  - This is a transitive dep; upgrade the tool that depends on it (e.g., npm, jest)

### DEP-007: js-yaml Quadratic Complexity DoS

- **Severity:** P2 (High)
- **Category:** CVE (Denial of Service)
- **Package:** `js-yaml` ≤3.14.2 (Transitive in Backend)
- **CVE:** GHSA-h67p-54hq-rp68 (CVSS 7.5) + GHSA-52cp-r559-cp3m
- **Also:** path-to-regexp GHSA-37ch-88jc-xwx2 (ReDoS)

- **Detail:** js-yaml has multiple YAML merge-key DoS vulnerabilities that cause quadratic CPU consumption. A crafted YAML file with repeated aliases can cause the parser to hang.

- **Attack Vector:**
  - Attacker uploads a malicious YAML configuration file
  - Application parses it with js-yaml
  - Parser spins in quadratic-time merge-key expansion
  - Service hangs

- **Risk Assessment:**
  - **If app parses user-uploaded YAML:** HIGH RISK
  - **If only internal configs:** LOWER RISK

- **Fix:**
  - Upgrade js-yaml to **≥3.14.3** or latest 4.x
  - Run: `npm update js-yaml`
