## Critical Findings (P1)

### DEP-001: Handlebars.js JavaScript Injection via AST Type Confusion
- **Severity:** P1 (Critical)
- **Category:** CVE / Code Injection
- **Package:** handlebars (4.0.0 - 4.7.8)
- **File:** Source/Backend/package-lock.json (transitive via jest → babel-jest)
- **CVEs:**
  - GHSA-2w6w-674q-4c4q: Remote Code Injection (CVSS 9.8)
  - GHSA-3mfm-83xf-c92r: AST Type Confusion (CVSS 8.1)
  - GHSA-xhpv-hc6g-r9c6: Dynamic Partial Injection (CVSS 8.1)
  - GHSA-9cx6-37pm-9jff: Denial of Service (CVSS 7.5)
  - GHSA-xjpj-3mr7-gcpf: CLI Precompiler Injection (CVSS 8.2)
- **Detail:** Handlebars template engine contains multiple JavaScript injection vulnerabilities allowing attackers to execute arbitrary code via malformed template syntax. Five distinct CVEs affect template compilation.
- **Exploit:** Craft templates with @partial-block or decorator syntax to break AST validation and inject code.
- **Fix:** Upgrade jest to v30.0.0+ (requires major version bump) or remove babel-jest from dependency tree. Handlebars should be >4.7.8.
- **Cross-ref:** [ESCALATE → TheGuardians] — RCE via test framework transitive dep

### DEP-002: protobufjs Arbitrary Code Execution
- **Severity:** P1 (Critical)
- **Category:** CVE / Code Injection
- **Package:** protobufjs (≤7.6.2)
- **File:** portal/Backend/package-lock.json, platform/orchestrator/package-lock.json (transitive via @opentelemetry/*, @grpc/*)
- **CVEs:**
  - GHSA-xq3m-2v4x-88gg: Arbitrary Code Execution (CVSS 9.8) — direct vector
  - GHSA-75px-5xx7-5xc7: Prototype Pollution → Code Generation (CVSS 8.1)
  - GHSA-wcpc-wj8m-hjx6: Unbounded Any Expansion DoS (CVSS 7.5)
  - GHSA-685m-2w69-288q: Unbounded Recursion DoS (CVSS 7.5)
  - + 6 more moderate issues (prototype pollution, field name crafting, etc.)
- **Detail:** protobufjs allows arbitrary code execution through prototype pollution and unsafe code generation. Message field names can shadow runtime properties, leading to code injection during serialization.
- **Exploit:** Craft protobuf schema with field names like `__proto__` or `constructor.prototype` to pollute the prototype chain; then trigger code generation.
- **Fix:** Upgrade to protobufjs ≥7.7.0. **URGENT:** This affects tracing infrastructure (OpenTelemetry).
- **Cross-ref:** [ESCALATE → TheGuardians] — Critical RCE in observability stack (portal/Backend, platform/orchestrator)

---

### DEP-003: Vitest UI Server Arbitrary File Read/Execute
- **Severity:** P1 (Critical)
- **Category:** CVE / Unauthorized File Access
- **Package:** vitest (<3.2.6)
- **File:** Source/Frontend/package-lock.json
- **CVE:** GHSA-5xrq-8626-4rwp (CVSS 9.8)
- **Detail:** When Vitest UI server is listening (default in `vitest` command), any attacker on the network can read and execute arbitrary files on the developer's machine.
- **Exploit:** `POST /api/execute?code=<payload>` to the UI server (port 51204 by default).
- **Fix:** Upgrade vitest ≥3.2.6 or disable UI server in production.
- **Cross-ref:** [ESCALATE → TheGuardians] — RCE on developer machines during test runs

## High CVE Findings (P2)

### DEP-004: Vite `server.fs.deny` Bypass on Windows
- **Severity:** P2 (High)
- **Category:** CVE / Path Traversal
- **Package:** vite (≤6.4.2)
- **File:** Source/Frontend/package-lock.json (direct dep), portal/Frontend/package-lock.json
- **CVEs:**
  - GHSA-fx2h-pf6j-xcff: `server.fs.deny` Bypass (Windows) (CVSS 7.5)
  - GHSA-4w7w-66w2-5vf9: Path Traversal in `.map` Handling (≤6.4.1)
  - GHSA-v6wh-96g9-6wx3: NTLMv2 Hash Disclosure (launch-editor)
- **Detail:** On Windows, alternate path forms (`\\?\` UNC paths) bypass `server.fs.deny` controls, allowing read of restricted files.
- **Impact:** Developers on Windows can have source code and env files read through dev server.
- **Fix:** Upgrade vite ≥5.5.0 or ≥6.5.0 depending on version branch.
- **Cross-ref:** Affects dev environment only; not production-deployed

### DEP-005: form-data CRLF Injection
- **Severity:** P2 (High)
- **Category:** CVE / Injection
- **Package:** form-data (4.0.0 - 4.0.5)
- **File:** Source/Backend, Source/Frontend, portal/Frontend, portal/Backend (all transitive via node-fetch, axios, etc.)
- **CVE:** GHSA-hmw2-7cc7-3qxx (CVSS 7.5)
- **Detail:** Multipart form field names and filenames are not escaped for CRLF, allowing header injection attacks.
- **Exploit:** Craft field name like `"name\r\nContent-Type: text/plain\r\nContent-Disposition"` to inject headers into multipart requests.
- **Impact:** Can inject arbitrary headers in file uploads, potentially bypassing security controls.
- **Fix:** Upgrade form-data ≥4.0.6.
- **Note:** Affects all packages using form-data as transitive (very common).
- **Cross-ref:** [SEE TheGuardians static-analyzer] — Depends on whether app actually uses form-data functionality

### DEP-008: React Router Open Redirect via Protocol-Relative URLs
- **Severity:** P2 (High)
- **Category:** CVE / Open Redirect
- **Package:** react-router-dom (6.7.0 - 6.30.3)
- **File:** Source/Frontend/package-lock.json (direct dep)
- **CVE:** GHSA-2j2x-hqr9-3h42 (unscored)
- **Detail:** React Router's same-origin redirect logic fails on paths starting with `//`, allowing protocol-relative URLs to redirect to arbitrary external sites.
- **Exploit:** Link like `/redirect?to=//attacker.com` appears same-origin but becomes `//attacker.com` → attacker.com.
- **Impact:** Phishing / account takeover via app-provided redirect.
- **Fix:** Upgrade react-router-dom ≥6.30.4.
- **Cross-ref:** Frontend security — affects user navigation

### DEP-011: path-to-regexp ReDoS
- **Severity:** P2 (High)
- **Category:** CVE / Denial of Service
- **Package:** path-to-regexp (<0.1.13)

## Recommendations for Prevention

1. **Automated Dependency Scanning:** Enable GitHub Dependabot or Snyk for real-time CVE alerts
2. **Semantic Versioning Discipline:** Use exact versions for direct dependencies in lock files, not caret/tilde ranges
3. **Regular Audit Cadence:** `npm audit` weekly, `npm outdated` monthly
4. **Test Environment Isolation:** Disable vitest UI server in CI/CD; only enable locally with VPN
5. **Observability Stack Freeze:** Pin @opentelemetry/* to tested versions; automatic upgrades can break tracing pipeline
6. **Jest Modernization:** Plan migration from jest to vitest or similar to reduce transitive bloat
