[DEP-001] Vitest 2.0.5 — UI Server Arbitrary File Read/Execute
├─ Package: vitest@2.0.5 (Frontend, dev dependency)
├─ Vulnerability: GHSA-5xrq-8626-4rwp
├─ CVSS Score: 9.8 (Critical)
├─ Affected Versions: <3.2.6
├─ Description: When Vitest UI server is listening, attacker can read ANY file
│               on the filesystem and potentially execute code without auth.
├─ Risk Context: During development or CI, if UI server is accessible from
│                untrusted network, this is exploitable.
├─ Fix: npm install vitest@^3.2.6 --save-dev (major version bump)
├─ Testing: Run full test suite; verify UI server behavior if used
└─ Timeline: IMMEDIATE — before merging any code

[DEP-003] Vite — server.fs.deny Bypass on Windows
├─ Package: vite@5.4.0 (Frontend, dev dependency)
├─ Vulnerability: GHSA-fx2h-pf6j-xcff
├─ CVSS Score: Not specified (High severity assigned)
├─ Affected Versions: <=6.4.2
├─ Description: Alternate path formats (UNC paths, short names) bypass
│               server.fs.deny configuration on Windows dev servers.
├─ Risk Context: Only affects Windows developers where fs.deny is configured.
│                CI/Linux environments are unaffected.
├─ Fix: npm install vite@^6.4.3 --save-dev (or latest 5.x patch)
├─ Testing: Test dev server fs.deny if configured
└─ Timeline: This sprint (medium priority for CI)

[DEP-004] Vite — Path Traversal in `.map` Handling
├─ Package: vite@5.4.0 (Frontend, dev dependency)
├─ Vulnerability: GHSA-4w7w-66w2-5vf9
├─ CVSS Score: Not specified (High severity assigned)
├─ Affected Versions: <=6.4.1
├─ Description: Optimized deps `.map` file handling allows directory
│               traversal to access files outside intended scope.
├─ Risk Context: Affects both dev and build artifacts.
├─ Fix: npm install vite@^6.4.3 --save-dev
├─ Testing: Verify build artifact paths are not traversed
└─ Timeline: Bundle with DEP-003

[DEP-005] form-data — CRLF Injection in Multipart Fields
├─ Package: form-data@4.0.0-4.0.5 (transitive, both Backend & Frontend)
├─ Vulnerability: GHSA-hmw2-7cc7-3qxx
├─ CVSS Score: 7.5 (High)
├─ Affected Versions: >=4.0.0 <4.0.6
├─ Description: Unescaped multipart field names/filenames allow CRLF injection.
│               Can be exploited to inject HTTP headers or split requests.
├─ Risk Context: If app handles multipart file uploads with user-controlled
│                filenames, this is exploitable.
├─ Fix: npm install form-data@^4.0.6 (or auto via npm audit fix)
├─ Testing: Test multipart file uploads with special characters in filenames
└─ Timeline: This sprint

[DEP-006] ws — Memory Exhaustion DoS (Tiny Fragments)
├─ Package: ws@8.0.0-8.20.1 (transitive, likely Frontend via Vite/test tools)
├─ Vulnerability: GHSA-96hv-2xvq-fx4p
├─ CVSS Score: 7.5 (High)
├─ Affected Versions: >=8.0.0 <8.21.0
├─ Description: WebSocket library accepts tiny fragments without aggregating.
│               Attacker sends many small fragments → memory exhaustion → DoS.
├─ Risk Context: If app uses WebSockets OR if dev server uses ws, exploitable.
├─ Fix: npm install ws@^8.21.0 or ^9.x (auto via npm audit fix)
├─ Testing: If WebSockets are used, test under load with fragment attacks
└─ Timeline: This sprint (lower priority than DEP-003/004/005)

[DEP-010] react-router-dom — Open Redirect via Protocol-Relative URL
├─ Package: react-router-dom@6.26.0 (Frontend, direct dependency)
├─ Vulnerability: GHSA-2j2x-hqr9-3h42
├─ CVSS Score: Not specified (High severity assigned)
├─ Affected Versions: 6.6.3-pre.0 to 6.30.3
├─ Description: Same-origin redirect with path starting "//" is reinterpreted
│               as protocol-relative URL, allowing attacker to redirect to
│               attacker.com while appearing to be same-origin.
├─ Risk Context: If app uses <Navigate to="//..."/> or similar, exploitable.
├─ Fix: npm install react-router-dom@^6.30.4
├─ Testing: Test all redirect flows; look for paths starting with "//"
└─ Timeline: This sprint (includes security fix)
