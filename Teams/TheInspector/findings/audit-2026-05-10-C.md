## Findings

### QO-001: Main Specification Entirely Unimplemented and Untraced
- **Severity:** P1
- **Category:** spec-drift
- **File:** `Specifications/dev-workflow-platform.md` (FR-001 through FR-069 + FR-dependency-seed)
- **Detail:** The primary domain spec (`Specifications/dev-workflow-platform.md`) defines 74 formal requirements covering Feature Requests, Bug Reports, Development Cycles, Pipeline Orchestration, Learnings, and Features APIs (FR-001–FR-069). Not a single source file in `Source/` contains a `// Verifies: FR-0XX` comment. The codebase instead implements the **self-judging workflow engine** described in `Specifications/workflow-engine.md` and formally specified in `Plans/self-judging-workflow/requirements.md` (FR-WF-XXX). This creates a 0% traceability gap against the primary spec. It is unclear whether `Specifications/dev-workflow-platform.md` was formally superseded — it contains no deprecation notice, no pointer to the replacement, and is still the first spec listed in the directory. CLAUDE.md states: *"Specifications/ — Domain truth. The most critical documents."*
- **Recommendation:** Either (a) add a deprecation notice at the top of `dev-workflow-platform.md` pointing to `workflow-engine.md` and the active plan requirements, OR (b) formally retire the file to an `_archived/` subfolder. The `Specifications/workflow-engine.md` narrative spec should also be extended with formal FR-IDs so all three specification layers (Specifications/, Plans/, Source/) are properly linked.
- **Cross-ref:** Blocks traceability-enforcer from ever surfacing these gaps.

### QO-002: Traceability Enforcer Targets Wrong Specification
- **Severity:** P1
- **Category:** spec-drift / architecture-violation
- **File:** `tools/traceability-enforcer.py`
- **Detail:** The enforcer uses a "most recently modified `requirements.md`" heuristic (line ~34 of enforcer) to pick its target. Currently it selects `Plans/self-judging-workflow/requirements.md` and reports PASS — but never checks `Specifications/dev-workflow-platform.md` which has 74 untraced FR IDs. This means `python3 tools/traceability-enforcer.py` (the mandated verification gate in CLAUDE.md) gives a false green light. Any agent running the verification gate will believe traceability is complete when it is not. The enforcer's own docstring says it targets "a plan" not the full Specifications directory.
- **Recommendation:** Add a second enforcer mode that scans `Specifications/` for FR-IDs and cross-references source. Alternatively, wire the `--file Specifications/dev-workflow-platform.md` invocation into the gate (or retire the spec as per QO-001 first). Either path must be done before the gate can be trusted.
- **Cross-ref:** QO-001.

### QO-003: Business Logic in Route Handlers — Service Layer Bypassed
- **Severity:** P2
- **Category:** architecture-violation
- **File:** `Source/Backend/src/routes/workflow.ts:113-141` (approve), `:155-208` (reject), `:212-290` (dispatch)
- **Detail:** The `approve`, `reject`, and `dispatch` route handlers each contain domain business logic that should live in a service layer:
  1. **Transition validation** (`isValidTransition(item.status, ...)`) — guard logic for the state machine
  2. **Change history construction** (`buildChangeEntry(...)` + `item.changeHistory.push(...)`) — domain mutation
  3. **Direct store writes** (`store.updateWorkItem(id, {...})`) — data layer access from HTTP layer
  
  By contrast, the `route` and `assess` endpoints correctly delegate to `routeWorkItem()` and `assessWorkItem()` service functions. The `workItems.ts` CRUD router uses `trackUpdates` from `changeHistory` service. Only the three workflow-action handlers are inconsistent. Architecture rule violated: *"No direct DB calls from route handlers — use the service layer"* and *"Business logic has no framework imports"*.
- **Recommendation:** Extract `approveWorkItem(id, reason)`, `rejectWorkItem(id, reason)`, and `dispatchWorkItem(id, team)` service functions into `Source/Backend/src/services/workflow.ts` (or extend `router.ts`). Move transition validation, change history construction, and store writes into those functions. Route handlers become thin: validate input → call service → return result.
- **Cross-ref:** TheFixer for implementation.

### QO-004: Search Endpoint Missing — Tests Pass Despite Missing Route
- **Severity:** P2
- **Category:** untested / spec-drift
- **File:** `Source/Backend/tests/routes/search.test.ts:1-10`, `Source/Backend/src/app.ts`
- **Detail:** `FR-dependency-search` requires `GET /api/search?q=` for cross-entity typeahead search. The test file at `search.test.ts` explicitly documents (lines 3-6): *"NOTE: As of this review cycle the GET /api/search endpoint is NOT wired into Source/Backend/src/app.ts. These tests document the expected contract and will FAIL until the route is implemented."* Despite this, the traceability enforcer reports PASS for `FR-dependency-search` because the requirement ID appears as a comment in the test file. The endpoint is genuinely absent from `app.ts` — running the tests against the real app will return 404 on all `GET /api/search` calls. The `api/client.ts` frontend also declares a `searchItems()` function (`// Verifies: FR-dependency-api-client`) that calls this missing route.
- **Recommendation:** Either implement `GET /api/search` and wire it into `app.ts`, or explicitly mark `FR-dependency-search` as deferred with a tracking issue. Do not allow a test that documents an intentional gap to silently satisfy traceability.
- **Cross-ref:** TheFixer for implementation.

### QO-007: `eslint-disable` in Production Frontend Source
- **Severity:** P3
- **Category:** pattern-violation
- **Files:**
  - `Source/Frontend/src/components/DependencyPicker.tsx:82` — `eslint-disable-next-line react-hooks/exhaustive-deps`
  - `Source/Frontend/src/hooks/useWorkItems.ts:63` — same
- **Detail:** Two `react-hooks/exhaustive-deps` suppressions exist in production source. The architecture rule prohibits disabled linting rules without documented justification. These suppressions typically hide stale closure bugs where `useEffect` or `useCallback` runs with outdated dependencies, leading to subtle correctness issues (e.g., search not re-fetching when a dependency changes).
- **Recommendation:** Review each suppression. If the deps genuinely don't need to be in the array (e.g., stable refs), document why in an inline comment. If they should be included, add them and remove the suppression.

### QO-008: Hardcoded `localhost` URL in Production Frontend
- **Severity:** P3
- **Category:** pattern-violation
- **File:** `Source/Frontend/src/pages/DebugPortalPage.tsx:5`
- **Detail:** `const portalUrl = import.meta.env.VITE_PORTAL_URL || 'http://localhost:4200';` — the hardcoded fallback URL `http://localhost:4200` will silently point to localhost in any deployment environment where the env var is not set (e.g., staging, production, CI). Architecture rule: *"No hardcoded secrets -- use environment variables via `.env`"*. URLs are environment-specific configuration and belong in the env file, not as string literals in source.
- **Recommendation:** Remove the hardcoded fallback. Throw a configuration error on startup if `VITE_PORTAL_URL` is not set, or document in `.env.example` that this variable is required. Alternatively, disable the DebugPortalPage entirely in non-development builds.

### QO-009: Domain Type `BlockerRef` Defined Inline in UI Component
- **Severity:** P3
- **Category:** architecture-violation
- **File:** `Source/Frontend/src/components/DependencyPicker.tsx:7-11`
- **Detail:** `interface BlockerRef { id: string; type: 'feature' | 'bug' | 'issue' | 'improvement' }` is a domain concept (a reference to a blocking work item) defined inline in a UI component file. Architecture rule: *"Shared types are single source of truth — no inline type re-definitions across layers."* If the backend ever adds a new `WorkItemType`, this inline type must be manually updated to match.
- **Recommendation:** Move `BlockerRef` to `Source/Shared/types/workflow.ts` and import it in `DependencyPicker.tsx`. It should reference the existing `WorkItemType` enum rather than a string union literal.
