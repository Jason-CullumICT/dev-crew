### QO-001: Traceability Enforcer Scope Gap — 96 Requirements Invisible to Gate
- **Severity:** P1
- **Category:** architecture-violation
- **File:** `tools/traceability-enforcer.py:48-57`
- **Detail:** The enforcer auto-selects the most-recently-modified `requirements.md` inside `Plans/`. It scans only 13 FR-WF-* requirements. It **never reads** `Specifications/dev-workflow-platform.md` (86 requirements), `Specifications/tiered-merge-pipeline.md` (10 requirements), or implementation in `portal/` or `platform/`. The verification gate passes green against a 12% sample of total spec scope.
- **Recommendation:** Extend the enforcer to accept a `--specs-dir` flag that reads FR IDs from all `Specifications/*.md` files, and extend `--scan-dirs` to include `portal/` and `platform/`. Alternatively add a `Plans/dev-workflow-platform/requirements.md` that mirrors the spec requirements.
- **Cross-ref:** Affects all teams' traceability reporting. Route fix to TheFixer.

### QO-002: Ghost Requirements — FR-070..095 and FR-DUP-* Referenced But Never Specified
- **Severity:** P1
- **Category:** spec-drift
- **File:** `portal/Frontend/src/components/` (multiple files)
- **Detail:** Portal source code contains `// Verifies:` comments citing FR-070 through FR-095 and FR-DUP-01 through FR-DUP-13 (e.g., `portal/Frontend/src/components/feature-requests/FeatureRequestDetail.tsx:4`, `portal/Frontend/src/components/orchestrator/types.ts:26`). None of these requirement IDs appear in any file under `Specifications/`. They are **inverted traceability** — implementation claims to verify requirements that do not exist in the spec. This violates the core architecture rule: *implementation traces to specs, never the other way around.*
- **Recommendation:** Either (a) write specs for FR-070..095 and FR-DUP-* in `Specifications/dev-workflow-platform.md`, or (b) change the Verifies comments to reference the nearest existing spec ID. Option (a) is correct per the spec-first mandate.
- **Cross-ref:** Route spec authoring to requirements-reviewer; code comment updates to portal frontend-coder.

Instrument it in `Source/Backend/src/services/dependency.ts` around `hasUnresolvedBlockers` and `isReady` calls. ### QO-005: `pending_dependencies` Status Not in WorkItemStatus Enum
- **Severity:** P2
- **Category:** spec-drift
- **File:** `Source/Shared/types/workflow.ts:213`
- **Detail:** `Source/Shared/api-contracts.md:181-182` documents `pending_dependencies` as a required status for dispatch gating: "If transitioning to `approved` and `blockedBy` contains unresolved items → set status to `pending_dependencies` instead." The `WorkItemStatus` enum (line 5-15) has no `PendingDependencies` value. The VALID_STATUS_TRANSITIONS map (line 214) has no entry for this status. The comment on line 213 says "Support for pending_dependencies blocking" but the enum doesn't back it up — `setDependencies` in the service layer would need to set a status value that doesn't compile.
- **Recommendation:** Add `PendingDependencies = 'pending_dependencies'` to `WorkItemStatus`. Add transitions: `[WorkItemStatus.Approved]: [WorkItemStatus.InProgress, WorkItemStatus.PendingDependencies]` and `[WorkItemStatus.PendingDependencies]: [WorkItemStatus.Approved, WorkItemStatus.Backlog]`. Update `FR-dependency-dispatch-gating` tests. This is a shared-type change — coordinate backend and frontend layers.
- **Cross-ref:** Affects `Source/Backend/src/services/dependency.ts` and `Source/Frontend/`. Route to api-contract agent.

### QO-008: E2E Test Package Has No Runnable Test Command
- **Severity:** P3
- **Category:** untested
- **File:** `Source/E2E/package.json:10`
- **Detail:** `Source/E2E/package.json` defines `"test": "echo \"Error: no test specified\" && exit 1"`. The directory has `playwright.config.ts` and `playwright.pipeline.config.ts` with Playwright installed, but the npm test script is the Node.js default stub. Running `npm test --workspaces --if-present` (the verification gate from CLAUDE.md) silently skips this workspace or exits with an error. E2E tests exist at `Source/E2E/tests/` (generated by QA agents per FR-TMP-002) but are never run via the standard gate.
- **Recommendation:** Replace the test script with `playwright test --config playwright.config.ts`. Or, if E2E tests are intended as pipeline-only (run by `platform/`), add a comment and use `"test": "echo 'E2E tests run via pipeline only'"` so the gate doesn't fail.
- **Cross-ref:** Relates to FR-TMP-003 (Playwright E2E runner phase). Route fix to solo-session or TheFixer.
