## Findings

### QO-001: `GET /api/search` not registered in app.ts
- **Severity:** P1
- **Category:** spec-drift / untested
- **File:** `Source/Backend/src/app.ts` (no search route), `Source/Backend/tests/routes/search.test.ts:6`
- **Detail:** `FR-dependency-search` requires a `GET /api/search?q=` cross-entity typeahead endpoint. The test file explicitly self-documents the gap: _"As of this review cycle the GET /api/search endpoint is NOT wired into Source/Backend/src/app.ts. These tests document the expected contract and will FAIL until the route is implemented."_ There is no search route handler in any file under `Source/Backend/src/routes/`. The `DependencyPicker` component depends on this endpoint for typeahead search.
- **Recommendation:** Create `Source/Backend/src/routes/search.ts` implementing `GET /api/search?q=` that queries the in-memory store by title/description, returns `{data: WorkItem[]}`, and excludes soft-deleted items. Register it in `app.ts`: `app.use('/api/search', searchRouter)`.
- **Cross-ref:** TheFixer (implementation); frontend `DependencyPicker.tsx` is broken without this endpoint.

### QO-002: Route handlers call store directly (architecture violation)
- **Severity:** P2
- **Category:** architecture-violation
- **Files:**
  - `Source/Backend/src/routes/workItems.ts:12` — `import * as store from '../store/workItemStore'`
  - `Source/Backend/src/routes/workflow.ts:15` — `import * as store from '../store/workItemStore'`
  - `Source/Backend/src/routes/intake.ts:4` — `import * as store from '../store/workItemStore'`
- **Detail:** CLAUDE.md architecture rule: _"No direct DB calls from route handlers — use the service layer."_ Three route files bypass the service layer and call the in-memory store directly. The store is functionally equivalent to the DB layer. Domain logic is leaking into route handlers (e.g., change history tracking, dependency updates in `workItems.ts`).
- **Recommendation:** Extract CRUD operations into a `workItemService.ts`. Routes should call `workItemService.create()`, `workItemService.findById()`, etc. The store becomes an internal implementation detail of the service.
- **Cross-ref:** TheFixer (refactor); coordinate with backend-coder on the store interface.

### QO-004: Traceability enforcer regex blind to FR-dependency-* IDs
- **Severity:** P2
- **Category:** pattern-violation / tooling
- **File:** `tools/traceability-enforcer.py:64`
- **Detail:** The enforcer uses `pattern = re.compile(r"FR-[A-Z0-9-]+")`. This only matches uppercase letters, digits, and hyphens after `FR-`. All `FR-dependency-*` IDs use lowercase (e.g., `FR-dependency-search`) and are silently skipped. Running the enforcer against `Plans/dependency-linking/requirements.md` scans only **7** requirements (incidental numeric FR refs) and misses all 16 actual `FR-dependency-*` IDs. The enforcer falsely reports PASS on unimplemented requirements.
- **Recommendation:** Change regex to case-insensitive: `pattern = re.compile(r"FR-[A-Za-z0-9-]+")`. Also add a guard to exclude FR IDs that appear only in range citations (e.g., `FR-070 — FR-085`) or seed data examples.
- **Cross-ref:** Fix before next pipeline run to restore enforcer integrity.

### QO-005: Logger lacks NODE_ENV-based format switching
- **Severity:** P2
- **Category:** spec-drift
- **File:** `Source/Backend/src/utils/logger.ts:17-25`
- **Detail:** FR-WF-013 / CLAUDE.md logging rule: _"structured JSON in production, pretty-printing in development."_ The `emit()` function always calls `process.stdout.write(JSON.stringify(entry) + '\n')` regardless of `NODE_ENV`. There is no pretty-print branch.
- **Recommendation:**
  ```typescript
  function emit(level: LogLevel, message: string, context?: Record<string, unknown>): void {
    const entry: LogEntry = { timestamp: new Date().toISOString(), level, message,
      ...(context ? { context } : {}) };
    if (process.env.NODE_ENV === 'development') {
      console.log(`[${level.toUpperCase()}] ${message}`, context ?? '');
    } else {
      process.stdout.write(JSON.stringify(entry) + '\n');
    }
  }
  ```
- **Cross-ref:** TheFixer.

### QO-006: In-memory store has no file persistence (FR-WF-001 gap)
- **Severity:** P3
- **Category:** spec-drift
- **File:** `Source/Backend/src/store/workItemStore.ts`
- **Detail:** FR-WF-001 acceptance criteria explicitly includes _"CRUD operations on in-memory store with **file persistence**."_ The store is a `Map<string, WorkItem>` with no serialization to disk. All data is lost on server restart. For a development/demo platform this is a significant operability issue.
- **Recommendation:** Add JSON file persistence: serialize the Map to a `.data/workItems.json` file on every write, and hydrate from it on startup. Use synchronous writes to keep the store simple. Alternatively, document this as a known intentional gap in CLAUDE.md.
- **Cross-ref:** TheFixer.

### QO-011: Dual logger abstraction adds indirection
- **Severity:** P4
- **Category:** pattern-violation
- **Files:** `Source/Backend/src/logger.ts`, `Source/Backend/src/utils/logger.ts`
- **Detail:** Two logger files exist: `utils/logger.ts` is the real logger; `logger.ts` is a compatibility shim wrapping it with a different calling convention. Route files and services use both inconsistently (store uses `utils/logger`, routes use the shim). The shim was created to bridge different calling conventions between teams.
- **Recommendation:** Standardize on one calling convention (object-style `{msg, ...ctx}` or positional `(msg, ctx)`) and eliminate the wrapper. Update all callers uniformly.
- **Cross-ref:** TheFixer.
