## 🔴 CRITICAL Vulnerabilities (P1)

### DEP-001: Handlebars.js JavaScript Injection via AST Type Confusion
- **Severity:** P1 (CRITICAL)
- **Category:** cve / injection
- **Package:** handlebars@4.0.0-4.7.8
- **File:** Source/Backend/package-lock.json
- **CVE IDs:** 
  - GHSA-2w6w-674q-4c4q (CVSS 9.8)
  - GHSA-3mfm-83xf-c92r (CVSS 8.1)
  - GHSA-2qvq-rjwj-gvw9 (CVSS 4.7)
  - GHSA-7rx3-28cr-v5wh (CVSS 4.8)
  - GHSA-442j-39wm-28r2
  - GHSA-xhpv-hc6g-r9c6
  - GHSA-9cx6-37pm-9jff
  - GHSA-xjpj-3mr7-gcpf
- **Detail:** Multiple JavaScript injection vulnerabilities in Handlebars.js that allow arbitrary code execution via malformed templates, prototype pollution, and unescaped partial templates. Direct impact on template compilation and evaluation.
- **Threat:** If templates are user-controlled or sourced from untrusted input, attackers can execute arbitrary JavaScript in the backend.
- **Fix:** `npm audit fix` (upgrade to 4.7.9+)
- **Cross-ref:** [ESCALATE → TheGuardians] — RCE risk if templates are dynamic

---

### DEP-002: Vite High-Severity Development Server Vulnerability
- **Severity:** P1 (HIGH → CRITICAL in dev environment)
- **Category:** cve
- **Package:** vite@<=6.4.2
- **File:** Source/Frontend/package-lock.json
- **CVE ID:** GHSA-2x3c-gvch-v27w (via vite-node, cross-origin request enablement)
- **Detail:** Vite's development server fails to properly validate origins in HMR and module loading, allowing any website to read HMR responses and potentially inject modules. Affects development builds.
- **Threat:** Man-in-the-middle attack on dev server; attacker can read sensitive responses and inject malicious modules during development.
- **Fix:** `npm audit fix --force` (requires vite@>=7.x, breaking change)
- **Cross-ref:** [ESCALATE → TheGuardians] — dev-time code injection

## 🟠 HIGH Severity Vulnerabilities (P2)

### DEP-003: form-data CRLF Injection
- **Severity:** P2 (HIGH)
- **Category:** cve / injection
- **Package:** form-data@4.0.0-4.0.5
- **File:** Source/Backend/package-lock.json, Source/Frontend/package-lock.json
- **CVE ID:** GHSA-hmw2-7cc7-3qxx (CVSS 7.5)
- **Detail:** form-data fails to escape multipart field names and filenames, allowing CRLF injection. Attacker can inject arbitrary HTTP headers via form submission.
- **Threat:** Header injection attacks; can bypass CSRF tokens, inject Set-Cookie, or manipulate Content-Type.
- **Fix:** `npm audit fix` (upgrade to 4.0.6+)
- **Cross-ref:** [ESCALATE → TheGuardians] — header injection risk

---

### DEP-004: ws WebSocket Memory Exhaustion DoS
- **Severity:** P2 (HIGH)
- **Category:** cve / denial-of-service
- **Package:** ws@8.0.0-8.20.1
- **File:** Source/Frontend/package-lock.json
- **CVE IDs:** 
  - GHSA-58qx-3vcg-4xpx (uninitialized memory disclosure)
  - GHSA-96hv-2xvq-fx4p (memory exhaustion from tiny fragments)
- **Detail:** Two distinct vulnerabilities in ws: (1) uninitialized memory can be returned to callers; (2) tiny fragmented WebSocket frames cause unbounded memory accumulation, leading to DoS.
- **Threat:** Memory leak → OOM crashes; information disclosure via uninitialized memory.
- **Fix:** `npm audit fix` (upgrade to 8.20.2+)
- **Cross-ref:** [ESCALATE → TheGuardians] — DoS + info disclosure

## 🚨 Cross-Functional Escalations
