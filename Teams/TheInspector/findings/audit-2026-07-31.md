## CRITICAL FINDINGS (P1) — Must Fix Immediately

### DEP-001: Vitest UI Server Arbitrary File Read & Execution (Frontend)
- **Severity:** P1 (CRITICAL)
- **Category:** CVE / Code Injection
- **Package:** `vitest@<=3.2.5` (Direct dependency)
- **File:** `Source/Frontend/package.json`
- **CVE:** GHSA-5xrq-8626-4rwp  
- **CVSS Score:** 9.8 (Network, Low Complexity, Unauthenticated)
- **CWE:** CWE-862 (Missing Authorization)

**Detail:**  
When Vitest UI server is running, any attacker on the network can:
1. Read arbitrary files from the filesystem via the UI server endpoint
2. Execute arbitrary code on the development machine

**Attack Vector:** Network-based, no authentication required. Exploitable during development if Vitest UI runs on an exposed port (default `51204`).

**Impact:** Code injection, data exfiltration, system compromise during development.

**Current Version:** `2.0.5`  
**Fixed Version:** `3.2.6` (major upgrade) or `4.1.10` (even more recommended)

**Recommended Fix:**  
```bash
cd Source/Frontend && npm update vitest @vitest/mocker
```

**Cross-ref:** [ESCALATE → TheGuardians] — This is a code injection vulnerability in development tooling. Red-teamer should assess feasibility of weaponizing this during dev cycles.

### DEP-002: Handlebars.js Multiple JavaScript Injection Vulnerabilities (Backend)
- **Severity:** P1 (CRITICAL)
- **Category:** CVE / Code Injection / XSS
- **Package:** `handlebars@4.0.0-4.7.8` (Transitive)
- **File:** `Source/Backend/package-lock.json`
- **Primary CVE:** GHSA-2w6w-674q-4c4q (CVSS 9.8)
- **Additional CVEs:** GHSA-3mfm-83xf-c92r, GHSA-xhpv-hc6g-r9c6, GHSA-9cx6-37pm-9jff (all High)
- **CWE:** CWE-94 (Code Injection), CWE-843 (Access of Resource Using Incompatible Type), CWE-79 (XSS)

**Detail:**  
Multiple critical vulnerabilities in Handlebars template engine:
1. **AST Type Confusion (GHSA-2w6w-674q-4c4q):** Attacker can inject arbitrary JavaScript by tampering AST nodes. Achievable via @partial-block, dynamic partials, or template options.
2. **Prototype Pollution + XSS (GHSA-2qvq-rjwj-gvw9):** Partial template injection leads to prototype pollution and subsequent XSS.
3. **Decorator Syntax DoS (GHSA-9cx6-37pm-9jff):** Malformed decorator syntax crashes the template compiler → DoS.

**Attack Vector:** 
- If handlebars templates are user-controlled or come from untrusted sources → full RCE.
- Even if only compiled by trusted code, prototype pollution chains can reach sensitive operations.

**Impact:** Remote Code Execution, prototype pollution, template-based XSS.

**Current Version Found:** 4.7.8 (indirectly via some build/test dependency)  
**Fixed Version:** 4.7.9+ or upgrade to 4.8.0+

**Recommended Fix:**  
```bash
cd Source/Backend && npm audit fix --force
# OR explicitly:
npm update handlebars --depth 20
```

**Cross-ref:** [ESCALATE → TheGuardians] — Code injection vulnerability. Check if any user-supplied data touches template compilation.

### DEP-003: Protobufjs Arbitrary Code Execution (Orchestrator)
- **Severity:** P1 (CRITICAL)
- **Category:** CVE / Code Injection
- **Package:** `protobufjs@<=7.6.4` (Transitive, via dockerode → grpc)
- **File:** `platform/orchestrator/package-lock.json`
- **Primary CVE:** GHSA-xq3m-2v4x-88gg (CVSS 9.8)
- **Secondary CVEs:** 
  - GHSA-75px-5xx7-5xc7 (Code generation gadget, CVSS 8.1)
  - GHSA-jvwf-75h9-cwgg (Process-wide DoS, CVSS 7.5)
  - GHSA-685m-2w69-288q (Unbounded recursion DoS, CVSS 7.5)
  - GHSA-wcpc-wj8m-hjx6 (Unbounded Any expansion, CVSS 7.5)
- **CWE:** CWE-94 (Code Injection), CWE-1321 (Prototype Pollution)

**Detail:**  
Arbitrary code execution via malicious `.proto` files or protobuf payloads. The vulnerability chain:
1. Prototype injection in generated message constructors
2. Code generation gadgets triggered during `toObject()` operations
3. Unbounded recursion in option parsing → process crash (DoS)

**Attack Vector:**
- If protobufjs processes untrusted `.proto` schemas → RCE
- If gRPC services accept untrusted message types → RCE via prototype pollution
- Crafted protobuf messages with nested Any types → DoS via infinite expansion

**Impact:** Remote code execution, denial of service, prototype pollution.

**Current Range:** <=7.6.4  
**Fixed Version:** 7.6.5+

**Recommended Fix:**  
```bash
cd platform/orchestrator && npm update protobufjs --depth 20
# OR force major upgrade via dockerode
npm update dockerode --depth 20
```

**Cross-ref:** [ESCALATE → TheGuardians] — Critical in any system that processes untrusted gRPC schemas or messages.

### DEP-004: form-data CRLF Injection (All packages)
- **Severity:** P2 (HIGH)
- **Category:** CVE / Header Injection

- **CVE:** GHSA-hmw2-7cc7-3qxx (CVSS 7.5)
- **CWE:** CWE-93 (CRLF Injection)

Multipart field names and filenames in form-data are not escaped. Attacker can inject CRLF (`\r\n`) sequences to:
1. Inject arbitrary HTTP headers
2. Bypass CORS restrictions
3. Perform header-based injection attacks

**Attack Vector:** Network-based. If application constructs multipart forms with user-controlled field names → HTTP response splitting possible.

**Impact:** HTTP response splitting, header injection, CORS bypass.

**Current Range:** 4.0.0 - 4.0.5  
**Fixed Version:** 4.0.6+

**Recommended Fix:**  
```bash
npm update form-data --depth 20
```

### DEP-005: PostCSS Multiple Path Traversal & XSS (Frontend)
- **Severity:** P2 (HIGH)
- **Category:** CVE / Path Traversal / XSS
- **Package:** `postcss@<=8.5.17` (Transitive)
- **Files:** `Source/Frontend/package-lock.json`
- **CVEs:**
  - GHSA-6g55-p6wh-862q (Arbitrary file read via sourceMappingURL, CVSS 7.5)
  - GHSA-r28c-9q8g-f849 (Path traversal via source maps, CVSS 7.5)
  - GHSA-qx2v-qp2m-jg93 (XSS via </style> tag, CVSS 6.1)
- **CWE:** CWE-22 (Path Traversal), CWE-200 (Information Disclosure), CWE-79 (XSS)

**Detail:**  
PostCSS processes CSS with embedded source map references (`sourceMappingURL`). Attacker can:
1. Specify a source map URL pointing to sensitive files (e.g., `/../../../.env`) → read arbitrary files
2. Specify UNC paths on Windows to trigger SMB hash disclosure
3. Inject unescaped `</style>` in CSS output → browser interprets it as tag close → XSS in HTML

**Attack Vector:**
- If user can control CSS being processed → path traversal
- If CSS is rendered in HTML context → XSS
- Primarily a development/build-time risk, but can affect users if CSS is dynamically processed

**Impact:** Arbitrary file disclosure, information leakage, XSS.

**Current Range:** <=8.5.17  
**Fixed Version:** 8.5.18+ (or 9.0.0+)

**Recommended Fix:**  
```bash
cd Source/Frontend && npm update postcss --depth 20
```

### DEP-007: React Router Open Redirect & SSR Injection (Frontend)
- **Severity:** P2 (HIGH)
- **Category:** CVE / Open Redirect / Argument Injection
- **Package:** `react-router-dom@6.0.0-6.30.4` (Direct dependency)
- **Files:** `Source/Frontend/package.json`
- **CVEs:**
  - GHSA-jjmj-jmhj-qwj2 (Open redirect to XSS, CVSS 6.9)
  - GHSA-2j2x-hqr9-3h42 (Protocol-relative URL open redirect)
  - GHSA-wrjc-x8rr-h8h6 (Backslash in Link bypass)
  - GHSA-337j-9hxr-rhxg (SSR hydration gadget injection)
- **CWE:** CWE-601 (Open Redirect), CWE-470 (Use of Externally-Controlled Input), CWE-79 (XSS)

**Detail:**  
Multiple open redirect and injection vulnerabilities:
1. `//` prefix in URLs treated as same-origin but protocol-relative → open redirect

**Attack Vector:**
- Attacker crafts malicious link: `<Link to="//attacker.com">` or `<Link to="\attacker.com">`
- User clicks → redirected off-site
- If SSR enabled, malicious error objects in hydration → constructor injection

**Impact:** Open redirect leading to phishing/credential theft, SSR-based code injection.

**Current Version:** 6.26.0  
**Fixed Version:** 7.18.0+

**Recommended Fix:**  
```bash
cd Source/Frontend && npm update react-router-dom --depth 10
# This is a major version bump (6->7)
```

### DEP-008: brace-expansion DoS (Backend & Frontend)
- **Severity:** P2 (HIGH)
- **Category:** CVE / Denial of Service
- **Package:** `brace-expansion@<=5.0.7` (Transitive)
- **Files:** Backend, Frontend (via various build tools)
- **CVEs:**
  - GHSA-mh99-v99m-4gvg (OOM from unbounded expansion, CVSS 7.5)
  - GHSA-3jxr-9vmj-r5cp (Exponential-time expansion, CVSS 5.3)
  - GHSA-f886-m6hf-6m8v (Zero-step sequence hang, CVSS 6.5)
- **CWE:** CWE-400 (Uncontrolled Resource Consumption), CWE-770 (Allocation of Resources)

**Detail:**  
brace-expansion (used by glob pattern matching) can be forced to expand patterns into exponentially-many results:
1. `{1..9999999}` expands to 9 million strings → OOM
2. `{a,b}{c,d}{e,f}...` repeated → exponential explosion
3. Patterns like `{}` or `{0..0}` cause process hangs

**Attack Vector:** If application accepts user input that gets passed to glob/brace-expansion → easy DoS.

**Impact:** Denial of service, process crash, resource exhaustion.

**Current Range:** <=5.0.7  
**Fixed Version:** 5.0.8+ or 6.x+

**Recommended Fix:**  
```bash
npm update brace-expansion --depth 20
```

### DEP-010: ws WebSocket Memory Exhaustion (Orchestrator)
- **Severity:** P2 (HIGH)
- **Category:** CVE / Denial of Service
- **Package:** `ws@8.0.0-8.20.1` (Transitive)
- **Files:** `platform/orchestrator/package-lock.json`
- **Primary CVE:** GHSA-96hv-2xvq-fx4p (Memory exhaustion DoS, CVSS 7.5)
- **Secondary CVE:** GHSA-58qx-3vcg-4xpx (Uninitialized memory disclosure, CVSS 4.4)
- **CWE:** CWE-400 (Uncontrolled Resource Consumption), CWE-770 (Allocation), CWE-908 (Use of Uninitialized Variable)

**Detail:**  
WebSocket library doesn't limit fragment buffer size. Attacker can:
1. Send many tiny fragments → accumulate in memory without limit
2. Send data chunks designed to bypass backpressure → memory exhaustion
3. Trigger uninitialized memory access in message decompression → info disclosure

**Attack Vector:** Network-based. Any WebSocket endpoint using ws library.

**Impact:** Denial of service, memory exhaustion, information leakage.

**Current Range:** 8.0.0 - 8.20.1  
**Fixed Version:** 8.21.0+

**Recommended Fix:**  
```bash
cd platform/orchestrator && npm update ws --depth 20
```
