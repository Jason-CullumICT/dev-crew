## Critical Issues (P1)

### DEP-001: Handlebars.js JavaScript Injection (Source/Backend)
- **Severity:** P1 (Critical)
- **Category:** CVE / Remote Code Execution
- **Package:** handlebars (transitive, ≤4.7.8)
- **File:** Source/Backend/package-lock.json
- **CVE ID:** GHSA-2w6w-674q-4c4q
- **CVSS Score:** 9.8 (Network, Low Complexity, No Privileges)
- **Detail:** Handlebars.js allows arbitrary JavaScript injection via AST type confusion. An attacker can execute arbitrary code by submitting malformed template data. Multiple related CVEs also present (prototype pollution, decorator DoS, CLI injection).
- **Fix:** `npm audit fix` (requires updating transitive dependencies) or pin handlebars to ≥4.7.9
- **Impact:** Build-time template injection attacks possible
- **Cross-ref:** [ESCALATE → TheGuardians] — JavaScript injection in template engine

---

### DEP-002: Vitest UI Arbitrary File Read & Execution (Source/Frontend, portal/Frontend)
- **Severity:** P1 (Critical)
- **Category:** CVE / Information Disclosure + Code Execution
- **Package:** vitest (direct dependency, ≤3.2.5)
- **Files:** Source/Frontend/package.json, portal/Frontend/package.json
- **CVE ID:** GHSA-5xrq-8626-4rwp
- **CVSS Score:** 9.8 (Network, Low Complexity, No Authentication)
- **Detail:** When the Vitest UI server is listening (default in dev mode), an unauthenticated attacker can read arbitrary files from the project directory and potentially execute code. The UI server has no access controls.
- **Current Version:** vitest ^2.0.5 (Source/Frontend), ^1.4.0 (portal/Frontend)
- **Required Fix:** Upgrade vitest ≥4.1.10 for Source/Frontend; ≥1.6.0 for portal/Frontend. **Requires major version bump for Source/Frontend.**
- **Workaround (dev only):** Do not expose Vitest UI to untrusted networks; use `--ui=false` in CI
- **Impact:** 🔴 **HIGH** — Dev environments are vulnerable; CI must disable UI server
- **Cross-ref:** [ESCALATE → TheGuardians] — File disclosure + RCE vulnerability

## High-Severity Issues (P2)

### DEP-004: brace-expansion DoS (Source/Backend)
- **Severity:** P2 (High)
- **Category:** Denial of Service
- **Package:** brace-expansion (transitive, <=1.1.17)
- **CVE IDs:** GHSA-3jxr-9vmj-r5cp, GHSA-mh99-v99m-4gvg, GHSA-rgw5-rvv9-x895
- **Detail:** Multiple DoS vulnerabilities allowing exponential-time expansion, unbounded memory allocation, and process hang. Attack vector: malformed glob patterns or file input.
- **Fix:** `npm audit fix` or update to brace-expansion ≥1.1.18
- **Impact:** 🟡 **Medium** — Only exploitable if application processes untrusted glob patterns

---

### DEP-005: form-data CRLF Injection (Source/Backend)
- **Severity:** P2 (High)
- **Category:** CRLF Injection
- **Package:** form-data (≥4.0.0 <4.0.6)
- **CVE ID:** GHSA-hmw2-7cc7-3qxx
- **CVSS Score:** 7.5
- **Detail:** CRLF injection in multipart form field names and filenames. Allows HTTP header injection.
- **Fix:** Upgrade form-data ≥4.0.6
- **Impact:** 🟡 **Medium** — Only if application uses form-data for multipart uploads with user-controlled filenames

---

### DEP-006: React Router Open Redirect (Source/Frontend)
- **Severity:** P2 (Moderate→High)
- **Category:** Open Redirect
- **Package:** @remix-run/router (1.3.0 - 1.23.2, transitive via react-router-dom)
- **CVE ID:** GHSA-2j2x-hqr9-3h42
- **Detail:** Same-origin redirect with path starting `//` causes open redirect via protocol-relative URL reinterpretation. An attacker can redirect users to external sites.
- **Fix:** Upgrade react-router-dom to latest (currently 7.18.2); current is 6.30.4
- **Impact:** 🟠 **Medium** — Phishing/redirect attacks possible

---

### DEP-007: body-parser DoS (Source/Backend)
