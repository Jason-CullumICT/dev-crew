## Critical Findings (P1)

### DEP-001: Vitest UI Server Arbitrary Code Execution
- **Severity:** P1 (Critical)
- **Category:** CVE / Remote Code Execution
- **Package:** `vitest` (direct in Frontend, E2E)
- **Version:** < 3.2.6
- **File:** `Source/Frontend/package.json`, `Source/E2E/package.json`
- **CVE:** GHSA-5xrq-8626-4rwp (CVSS 9.8)
- **Detail:** When Vitest UI server is listening, arbitrary files can be read and executed. This is **critical in development** but mitigated in production (UI server should not be exposed).
- **Fix:** `npm install vitest@>=3.2.6` (breaking: major version jump to 4.x recommended for long-term support)
- **Risk:** High in development environments; negligible in production if UI not exposed
- **Cross-ref:** [CROSS-REF: red-teamer] — Exploitable if Vitest UI server runs on exposed port

### DEP-002: protobufjs Arbitrary Code Execution
- **Severity:** P1 (Critical)
- **Category:** CVE / Remote Code Execution
- **Package:** `protobufjs` (transitive via `@opentelemetry` and platform/orchestrator)
- **Version:** ≤ 7.6.4
- **File:** `platform/orchestrator/package-lock.json`
- **CVE:** GHSA-3hhx-5wg5-98hq (CVSS 8.6)
- **Detail:** Arbitrary code execution via `.proto` loading with `unsafe.parse()`. Affects protobufjs <= 7.6.4. Input validation critical.
- **Fix:** `npm install protobufjs@>=8.0.0` (or use `protobufjs@^7.6.5+`)
- **Attestation:** The orchestrator loads `.proto` files from local platform directory (controlled input), reducing exploit surface, but still critical.
- **Cross-ref:** [CROSS-REF: red-teamer] — RCE if untrusted proto files processed

### DEP-003: @grpc/grpc-js Server Crash (DoS)
- **Severity:** P1 (Critical)
- **Category:** CVE / Denial of Service
- **Package:** `@grpc/grpc-js`
- **Version:** 1.14.0 - 1.14.3
- **File:** `platform/orchestrator/package-lock.json`
- **CVE:** GHSA-5375-pq7m-f5r2 & GHSA-99f4-grh7-6pcq (CVSS 7.5)
- **Detail:** Malformed gRPC request causes server crash; malformed compressed message causes client/server crash. Directly exposable if gRPC endpoint is public.
- **Fix:** `npm install @grpc/grpc-js@>=1.14.4`
- **Cross-ref:** [CROSS-REF: red-teamer] — DoS via crafted requests to gRPC endpoints

## High Severity Findings (P2)

### DEP-004: brace-expansion DoS (Memory Exhaustion)
- **Severity:** P2
- **Category:** CVE / Denial of Service
- **Package:** `brace-expansion` (transitive, build-time dependency)
- **Version:** ≤ 1.1.17
- **File:** `Source/Backend/package-lock.json`
- **CVE:** GHSA-3jxr-9vmj-r5cp & GHSA-mh99-v99m-4gvg & GHSA-rgw5-rvv9-x895 (CVSS 7.5, 5.3, 7.5)
- **Detail:** Multiple DoS vectors: exponential expansion, memory exhaustion, unbounded intermediate arrays. Affects build-time tools (glob patterns).
- **Fix:** Upgrade build tools; usually fixed transitively by updating build dependencies
- **Impact:** Low in production (build-time only), medium in build pipelines

### DEP-005: form-data CRLF Injection
- **Severity:** P2
- **Category:** CVE / Header Injection
- **Package:** `form-data` (transitive)
- **Version:** < 4.0.6 (Source/Frontend), ≥ 4.0.0
- **File:** `Source/Frontend/package-lock.json`
- **CVE:** GHSA-hmw2-7cc7-3qxx (CVSS 7.5)
- **Detail:** CRLF injection via unescaped multipart field names/filenames. Can inject HTTP headers in form uploads.
- **Fix:** `npm install form-data@>=4.0.6`
- **Cross-ref:** [CROSS-REF: red-teamer] — CRLF injection in file uploads

### DEP-006: handlebars Code Injection in CLI Precompiler
- **Severity:** P2
- **Category:** CVE / Code Injection
- **Package:** `handlebars` (transitive via build tools)
- **Version:** 4.0.0 - 4.7.8
- **File:** `Source/Backend/package-lock.json` and other build contexts
- **CVE:** GHSA-xjpj-3mr7-gcpf (CVSS 8.2)
- **Detail:** JavaScript injection in CLI precompiler via unescaped template names. High risk if precompiler runs on untrusted input.
- **Fix:** `npm install handlebars@>=4.7.9`
- **Impact:** High if build pipeline accepts untrusted Handlebars templates

### DEP-007: js-yaml Quadratic DoS (YAML Merge Keys)
- **Severity:** P2
- **Category:** CVE / Denial of Service
- **Package:** `js-yaml` (transitive via config loaders)
- **Version:** ≤ 3.15.0
- **File:** `Source/Backend/package-lock.json`
- **CVE:** GHSA-52cp-r559-cp3m & GHSA-5p4m-2wfm-xmqj (CVSS 7.5, 7.5)
- **Detail:** Quadratic CPU consumption via YAML merge-key chains and !!omap resolution. Exploitable if API accepts YAML input.
- **Fix:** `npm install js-yaml@>=3.15.1`
- **Cross-ref:** [CROSS-REF: red-teamer] — DoS if API accepts YAML config uploads

### DEP-008: React Router Open Redirect
- **Severity:** P2
- **Category:** CVE / Open Redirect
- **Package:** `@remix-run/router` (transitive via react-router-dom)
- **Version:** 1.3.0 - 1.23.2
- **File:** `Source/Frontend/package-lock.json`, `portal/Frontend/package-lock.json`
- **CVE:** GHSA-2j2x-hqr9-3h42
- **Detail:** Same-origin redirect with path starting `//` causes open redirect via protocol-relative URL reinterpretation.
- **Fix:** `npm install react-router-dom@>=6.30.4` (likely already fixed; verify with direct inspection)
- **Cross-ref:** [CROSS-REF: red-teamer] — Open redirect in client-side routing

### DEP-009: Vite Path Traversal & fs.deny Bypass
- **Severity:** P2
- **Category:** CVE / Path Traversal / Access Control Bypass
- **Package:** `vite` (direct in Source/Frontend)
- **Version:** ≤ 6.4.2
- **File:** `Source/Frontend/package.json`
- **CVE:** GHSA-4w7w-66w2-5vf9, GHSA-v6wh-96g9-6wx3, GHSA-fx2h-pf6j-xcff (CVSS varies)

- **Risk:** Medium in dev; low in production (build artifact)

## Cross-Team Escalations

### [ESCALATE → TheGuardians]
- **DEP-001 (Vitest RCE):** If Vitest UI server is exposed on network, this is an immediate RCE vector. Recommend disabling UI server in production builds.
- **DEP-002 (protobufjs RCE):** If untrusted `.proto` files are loaded, RCE is possible. Verify all `.proto` inputs are from trusted, version-controlled sources.
- **DEP-007 (js-yaml DoS):** If YAML config is accepted from users, crafted payloads can cause DoS. Recommend input validation.

### [CROSS-REF → Performance Profiler]
- **DEP-007 (js-yaml):** Quadratic complexity may cause CPU spikes on malformed YAML. Consider moving to faster YAML library (e.g., `js-yaml-fork`) if YAML parsing is in critical path.
- **DEP-010 (ws):** Memory exhaustion in WebSocket fragments; monitor for unexpected memory growth under load testing.
