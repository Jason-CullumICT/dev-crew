## Findings

### QO-001: `GET /api/search` — Route Not Wired in app.ts
- **Severity:** P1
- **Category:** spec-drift / untested
- **File:** `Source/Backend/src/app.ts` (missing import/use) / `Source/Backend/tests/routes/search.test.ts:1`
- **Detail:** `FR-dependency-search` requires a `GET /api/search?q=` cross-entity typeahead endpoint. The service logic is present (dependency service, work item store support filtering), the test file has 5 fully-written test cases, and the `// Verifies: FR-dependency-search` comment exists in test code — but the route is **not registered in `app.ts`**. The test file's own header explicitly warns: _"NOTE: As of this review cycle the GET /api/search endpoint is NOT wired into Source/Backend/src/app.ts. These tests document the expected contract and will FAIL until the route is implemented."_ This means `npm test` will produce known failures that are not being surfaced as build-breaking.
- **Recommendation:** Either (a) implement the `GET /api/search` route and wire it in `app.ts`, or (b) if intentionally deferred, add a `test.skip` with a tracking comment to prevent silent CI failure. The clean path is (a) — implement the 10-20 line route handler that queries the store by title/description and returns `{data: [...]}`.
- **Cross-ref:** [ESCALATE → TheFixer]

### QO-002: Traceability Enforcer Blind to 84+ Specification Requirements
- **Severity:** P1
- **Category:** spec-drift / pattern-violation
- **File:** `tools/traceability-enforcer.py:45` (`get_active_requirements` function)
- **Detail:** The enforcer selects the **most-recently-modified `Plans/*/requirements.md`** and only checks those IDs. This means:
  - `Specifications/dev-workflow-platform.md` — 74 FRs (FR-001 to FR-074) — **never checked**
  - `Specifications/tiered-merge-pipeline.md` — 10 FR-TMP-* IDs — **never checked**
  - `Plans/dependency-linking/requirements.md` — 16 FR-dependency-* IDs — **only checked if it's the most-recently-modified plan**
  
  The architecture rule states _"Every FR needs a test with `// Verifies: FR-XXX` traceability comments"_ — but the verification gate only enforces this for 13 of the 113 total requirements. The gate gives a false "PASSED" signal.
- **Recommendation:** Extend `traceability-enforcer.py` to scan **all** `Plans/*/requirements.md` files (not just the most-recent one). Optionally add a `--specs` flag to also scan `Specifications/*.md`. Add a config entry in `inspector.config.yml` to specify which requirement files are active.
- **Cross-ref:** [ESCALATE → TheFixer for enforcer fix]

### QO-007: Silent JSON Parse Error in `client.ts`
- **Severity:** P3
- **Category:** pattern-violation
- **File:** `Source/Frontend/src/api/client.ts:26`
- **Detail:** `const body = await response.json().catch(() => ({}));` silently discards JSON parse errors. Architecture rule: _"Never swallow errors silently — every `catch` block must either re-throw, log with full context, or explicitly document why the error is intentionally suppressed."_ If the server returns malformed JSON on an error response, the client sees `{}` with no indication of the parse failure, making debugging harder.
- **Recommendation:** Add a comment documenting intent, or replace with:
  ```ts
  const body = await response.json().catch(() => {
    // JSON parse failure — server sent non-JSON error body; treat as empty
    return {} as Record<string, unknown>;
  });
  ```
  The explicit comment satisfies the architecture rule's "explicitly document" escape hatch.

### QO-008: Two `eslint-disable` Suppressions in Production Code
- **Severity:** P3
- **Category:** pattern-violation
- **File:** `Source/Frontend/src/hooks/useWorkItems.ts:63`, `Source/Frontend/src/components/DependencyPicker.tsx:82`
- **Detail:** Both files suppress `react-hooks/exhaustive-deps`. This lint rule exists to prevent stale closure bugs — suppressing it without a comment explaining why is an architecture rule violation (`// eslint-disable-next-line` with no rationale). Stale closures can cause subtle state bugs that are hard to reproduce.
- **Recommendation:** For each suppression: (a) investigate whether the dep can be added safely, or (b) add a comment explaining the deliberate omission (e.g., `// Intentional: adding X would cause infinite re-render because...`).
