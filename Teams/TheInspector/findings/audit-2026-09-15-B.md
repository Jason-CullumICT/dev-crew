## Findings

### QO-001: `GET /api/search` route is documented but not implemented
- **Severity:** P1
- **Category:** correctness / spec-drift
- **File:** `Source/Backend/src/app.ts` (line 44 — route never registered)
- **Tests affected:** `Source/Backend/tests/routes/search.test.ts` — all 5 tests fail
- **Detail:** The `FR-dependency-search` requirement specifies a cross-entity typeahead search endpoint
  used by the `DependencyPicker` modal.  The test file exists and annotates the gap:
  *"GET /api/search endpoint is NOT wired into src/app.ts"*.
  In production, `DependencyPicker.tsx` calls `/api/search?q=…` and will receive a 404 on every
  keystroke — the dependency picker typeahead is completely broken.
- **Recommendation:** Create `Source/Backend/src/routes/search.ts` with a handler that scans
  `workItemStore.findAll()` for title/description matches and filters soft-deleted items.
  Register it in `app.ts` as `app.use('/api', searchRouter)`. The test file is already written and
  will turn green immediately after.
- **Verification gate impact:** Backend test gate is broken (`npm test` → 5 failures). This must be
  fixed before any agent can claim a clean gate.
- **Cross-ref:** [ESCALATE → TheFixer] for implementation of the missing route.

### QO-002: OpenTelemetry tracing (FR-021 / architecture rule) not implemented
- **Severity:** P2
- **Category:** spec-drift / architecture-violation
- **File:** `Source/Backend/src/` — no `@opentelemetry` imports anywhere
- **Detail:** The architecture rules in `CLAUDE.md` are unambiguous:
  *"Use OpenTelemetry for distributed tracing. Auto-instrument HTTP, database, and framework calls.
  Add custom spans for critical paths. Propagate W3C traceparent header across service boundaries."*
  `Specifications/dev-workflow-platform.md` formalises this as FR-021 (backend) and FR-043 (pipeline).
  The implementation has structured JSON logging and Prometheus metrics (FR-WF-013 ✅) but zero
  OTel instrumentation. There are no `@opentelemetry/sdk-node`, `@opentelemetry/api`, or
  `traceparent` references in any Source/Backend file.
- **Recommendation:** Add `@opentelemetry/sdk-node` + `@opentelemetry/auto-instrumentations-node`
  to backend deps. Bootstrap the SDK in a `tracing.ts` entry point loaded before `app.ts`. Add a
  custom span wrapper around the assessment pod and workflow dispatch paths (critical paths per spec).
  Propagate `traceparent` header in all outbound calls.
- **Cross-ref:** [ESCALATE → TheFixer] for implementation.

### QO-003: Traceability enforcer is blind to multi-subsystem specs
- **Severity:** P2
- **Category:** pattern-violation / doc-stale
- **File:** `tools/traceability-enforcer.py` (line 44 — picks most-recently-modified requirements.md)
- **Detail:** Running `python3 tools/traceability-enforcer.py` (the documented verification gate in
  `CLAUDE.md`) auto-selects `Plans/self-judging-workflow/requirements.md` and reports PASS. This
  hides two important gaps:
  1. `Specifications/dev-workflow-platform.md` has 76 FR-XXX IDs — zero traced in `Source/`.
     (These belong to `portal/`, which the enforcer never scans.)
  2. `Specifications/tiered-merge-pipeline.md` has 10 FR-TMP-* IDs — zero traced in `Source/`
     or `platform/`.
  3. The enforcer regex `FR-[A-Z0-9-]+` also false-positives on seed data references like
     `FR-0004 blocked_by FR-0003` in `Plans/dependency-linking/requirements.md`, flagging
     portal data IDs as "missing requirements".
- **Recommendation:**
  - Add explicit scan targets to `inspector.config.yml` under `specs.enforcer_files`:
    ```yaml
    enforcer_files:
      - Plans/self-judging-workflow/requirements.md   # Source/
      - Plans/dependency-linking/requirements.md      # Source/ + portal/
      - Specifications/tiered-merge-pipeline.md       # platform/
    ```
  - Update `traceability-enforcer.py` to accept a `--dirs` flag so portal/ can be scanned separately.
  - Consider adding `portal/` to the scan directories in `inspector.config.yml`.
- **Cross-ref:** QO-004.

### QO-004: `workflow-engine.md` spec has no FR identifiers — traceability unenforced
- **Severity:** P2
- **Category:** spec-drift / doc-stale
- **File:** `Specifications/workflow-engine.md`
- **Detail:** `workflow-engine.md` is the primary domain spec for `Source/` (it defines work items,
  status lifecycle, routing rules, assessment pod, APIs). It contains rich prose but **zero FR-XXX
  IDs**. The traceability enforcer reports "No FR IDs found" when pointed at it.
  Implementation uses `FR-WF-*` IDs from `Plans/self-judging-workflow/requirements.md` — a derived
  plan file. If the domain spec changes, there is no automated way to detect that implementation
  diverged. The spec and the enforcer are decoupled.
- **Recommendation:** Add FR-WF-001 through FR-WF-013 identifiers to `workflow-engine.md` in the
  relevant sections (matching the plan). OR add a comment block at the top of `workflow-engine.md`
  mapping sections to plan IDs. Either way the traceability enforcer must be able to target the
  canonical domain spec, not a derivative plan.
- **Cross-ref:** QO-003.

### QO-005: `eslint-disable-next-line react-hooks/exhaustive-deps` in two production hooks
- **Severity:** P3
- **Category:** pattern-violation
- **Files:**
  - `Source/Frontend/src/hooks/useWorkItems.ts:63`
  - `Source/Frontend/src/components/DependencyPicker.tsx:82`
- **Detail:** Both suppressions hide React Hook exhaustive-deps warnings. Stale closure bugs from
  missing deps are a class of hard-to-reproduce UI bugs. Per CLAUDE.md architecture rules:
  *"No disabled linting rules"*.
  `useWorkItems.ts` likely has a `useCallback`/`useEffect` that intentionally omits a dep (e.g., a
  stable fetch function). `DependencyPicker.tsx:82` is in a search debounce `useCallback`.
- **Recommendation:** Audit both locations. If the dep is genuinely stable, wrap it with
  `useCallback` at a higher scope and include it in the deps array. If the dep changes every render,
  use a ref to hold the latest value. Remove the suppress comments once resolved.
- **Cross-ref:** [ESCALATE → TheFixer] for targeted review of the two hook callsites.

### QO-006: CRUD route handlers directly access the store — no service layer
- **Severity:** P3
- **Category:** architecture-violation
- **Files:**
  - `Source/Backend/src/routes/workItems.ts` (all 5 CRUD handlers)
  - `Source/Backend/src/routes/intake.ts` (POST /zendesk, POST /automated)
- **Detail:** CLAUDE.md states: *"No direct DB calls from route handlers — use the service layer."*
  `workItems.ts` imports `workItemStore` directly and calls `createWorkItem`, `findAll`, `findById`,
  `updateWorkItem`, `softDelete` from route handlers with no service intermediary.
  `workflow.ts` correctly delegates to `routeWorkItem`, `assessWorkItem`, `assignTeam` in services.
  The CRUD path has no equivalent service layer — business logic (e.g., validation, metric emission,
  change tracking) is inline in the route file.
- **Recommendation:** Create `Source/Backend/src/services/workItemService.ts` wrapping the store
  operations, and update `workItems.ts` and `intake.ts` to import from the service. This unifies the
  pattern already established by `workflow.ts`.
- **Cross-ref:** [ESCALATE → TheFixer].

### QO-007: Duplicate logger abstraction — two files, one canonical
- **Severity:** P3
- **Category:** simplification
- **Files:**
  - `Source/Backend/src/utils/logger.ts` — canonical structured logger
  - `Source/Backend/src/logger.ts` — compatibility re-export wrapper
- **Detail:** `src/logger.ts` exists solely because "backend-coder-2's workflow routes import logger
  as default from this module." It wraps `utils/logger.ts` with a slightly different call signature.
  This means any new file that imports from `src/logger.ts` gets the compat wrapper; any file that
  imports from `src/utils/logger.ts` gets the raw logger. Two interfaces for the same thing.
- **Recommendation:** Migrate all imports to a single canonical path. Either:
  - Make `src/utils/logger.ts` the default export canonical source, and delete `src/logger.ts`, or
  - Move the canonical logger to `src/logger.ts` and remove `src/utils/logger.ts`.
  After migration, update all import paths and ensure tests still pass.
- **Cross-ref:** [ESCALATE → TheFixer] for cleanup.
