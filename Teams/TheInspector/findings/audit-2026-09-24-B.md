## Findings

### QO-001: dev-workflow-platform.md Describes an Unimplemented System
- **Severity:** P2
- **Category:** spec-drift
- **File:** `Specifications/dev-workflow-platform.md`
- **Detail:** This specification contains 85 functional requirements (FR-001 – FR-069) describing a full web application with SQLite, feature request voting, development cycles, pipeline runs, and cycle traceability. None of these have been implemented. The active codebase implements `Specifications/workflow-engine.md` / `Plans/self-judging-workflow/requirements.md` (FR-WF-001 – FR-WF-013) — a completely different in-memory workflow engine. The traceability enforcer does NOT check `dev-workflow-platform.md`, so this drift is invisible to automated gates.

  Risk: New agents or developers reading `Specifications/dev-workflow-platform.md` may believe it is the active spec and build against it, or may conclude the codebase has massive regressions. The document needs a clear status header.

- **Recommendation:** Add a status header to `dev-workflow-platform.md`:
  ```markdown
  > **Status: PLANNED / NOT YET IMPLEMENTED**
  > This specification describes a future system. The current implementation follows
  > `Plans/self-judging-workflow/requirements.md` (FR-WF-001–013).
  ```
  Alternatively, move `dev-workflow-platform.md` to `docs/planned/` or `Specifications/archive/` to prevent confusion.
- **Cross-ref:** requirements-reviewer should confirm whether this spec is active, planned, or superseded.

### QO-002: Duplicate Frontend Test Files — Ambiguous Canonical Version
- **Severity:** P3
- **Category:** test-coverage
- **Files:**
  - `Source/Frontend/tests/WorkItemDetailPage.test.tsx` (368 lines)
  - `Source/Frontend/tests/pages/WorkItemDetailPage.test.tsx` (393 lines)
  - `Source/Frontend/tests/WorkItemListPage.test.tsx` (286 lines)
  - `Source/Frontend/tests/pages/WorkItemListPage.test.tsx` (262 lines)
- **Detail:** The same components are covered by two parallel sets of test files in different subdirectories. The root-level files (e.g., `tests/WorkItemDetailPage.test.tsx`) mock `../src/api/client` using a simple flat mock, while the `tests/pages/` versions import types directly from `Shared/types/workflow` and use richer mock setups. Both run as part of the test suite, causing duplicated execution and ambiguity about which version is authoritative. If the root-level version falls out of sync it may mask failures.
- **Recommendation:** Delete the older root-level files (`tests/WorkItemDetailPage.test.tsx`, `tests/WorkItemListPage.test.tsx`) and keep the richer `tests/pages/` versions as the canonical set. Confirm both run under vitest configuration.

### QO-004: E2E Pipeline Config References Non-Existent Test Directory
- **Severity:** P3
- **Category:** pattern-violation
- **File:** `Source/E2E/playwright.pipeline.config.ts:3`
- **Detail:** `testDir: "./tests/cycle-run-1774659927912-8dd3ac77"` points to a dynamically-generated directory that does not exist on disk. This config was generated by a pipeline run and committed to source. Running `playwright test --config playwright.pipeline.config.ts` would fail immediately with a directory-not-found error. ### QO-005: `eslint-disable` Suppressions in Recently-Modified Production Files
- **Severity:** P3
- **Category:** pattern-violation
- **Files:**
  - `Source/Frontend/src/components/DependencyPicker.tsx:82`
  - `Source/Frontend/src/hooks/useWorkItems.ts:63`
- **Detail:** Both files suppress `react-hooks/exhaustive-deps` with `// eslint-disable-next-line`. The rule exists to prevent stale closure bugs. These files were modified in the last 14 days. While each suppression may be intentional (avoiding infinite effect loops), they represent technical debt and should be documented.
- **Recommendation:** Add an inline comment explaining *why* the dependency is intentionally excluded from the array, e.g.:
  ```ts
  // eslint-disable-next-line react-hooks/exhaustive-deps
  // filters.page intentionally omitted — changing page triggers abort/retry via separate effect
  ```
  This converts a silent suppression into documented intent.
