## QO-001: Routes Call Store Layer Directly (Architecture Violation)
- **Severity:** P1
- **Category:** architecture-violation
- **Files:**
  - `Source/Backend/src/routes/workflow.ts` — 10 direct `store.*` calls (including `store.updateWorkItem` on lines 119, 175, 269)
  - `Source/Backend/src/routes/workItems.ts` — 6 direct `store.*` calls
  - `Source/Backend/src/routes/intake.ts` — 2 direct `store.createWorkItem` calls
- **Detail:** The CLAUDE.md architecture rule is explicit: *"No direct DB calls from route handlers — use the service layer."* The in-memory store is the data access layer. Route handlers in `workflow.ts` import `* as store` directly and call `store.findById`, `store.updateWorkItem`, and `store.softDelete` inline — bypassing any service abstraction. The approve, reject, and dispatch handlers all mutate state in the route handler itself without delegating to a service.
- **Recommendation:** Extract approve/reject/dispatch state mutations into `Source/Backend/src/services/workflowActions.ts` (or similar). Route handlers should only: (1) validate input, (2) call the service, (3) return the response.
- **Cross-ref:** TheFixer for implementation; QA-specialist for regression risk.

- **Severity:** P2
- **Category:** spec-drift

This violates the project's core principle: *"Every decision and line of code must trace back to a specification. If the spec doesn't cover it, write the spec first."* These IDs trace to the orchestrator runs dashboard feature.
- **Recommendation:** Add `FR-090..095` definitions to `Specifications/dev-workflow-platform.md` (or a dedicated orchestrator spec). Alternatively, create `Plans/orchestrator-runs-dashboard/requirements.md` and document the FR table there.
- **Cross-ref:** requirements-reviewer to author the spec.

- **Severity:** P2

- **Detail:** The enforcer selects the most recently modified `Plans/*/requirements.md` — currently `Plans/self-judging-workflow/requirements.md` (FR-WF-001..013). It is silent on: FR-dependency-* (16 IDs), FR-TMP-001..010 (10 IDs), portal FR-001..095 (95 IDs), and the orphan FR-090..095.
