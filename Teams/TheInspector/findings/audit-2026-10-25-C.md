## QO-001: GET /api/search route is unregistered — tests will fail
- **Severity:** P1
- **Category:** spec-drift / untested
- **File:** `Source/Backend/src/app.ts`
- **Detail:** `FR-dependency-search` requires `GET /api/search?q=` for cross-entity typeahead. Tests in `Source/Backend/tests/routes/search.test.ts` explicitly document the gap: *"the GET /api/search endpoint is NOT wired into Source/Backend/src/app.ts … These tests will FAIL until the route is implemented."* No `search.ts` route file exists, and no router import for search is present in `app.ts`. The `DependencyPicker` component depends on this endpoint at runtime.
- **Recommendation:** Create `Source/Backend/src/routes/search.ts` implementing `GET /api/search?q=` (cross-entity WorkItem search) and register it in `app.ts` with `// Verifies: FR-dependency-search`.
- **Cross-ref:** TheFixer

## QO-002: Traceability enforcer scope gap — 94 FRs invisible to the gate
- **Severity:** P2
- **Category:** spec-drift / architecture-violation
- **File:** `tools/traceability-enforcer.py`
- **Detail:** The enforcer picks the most-recently-modified `Plans/*/requirements.md` and stops there. - **Cross-ref:** solo-session (tools/ is solo-session territory)

## QO-005: `WorkItemStatus` enum missing `pending_dependencies` value
- **Severity:** P2
- **Category:** spec-drift / architecture-violation
- **File:** `Source/Shared/types/workflow.ts:5`
- **Detail:** `FR-dependency-types` specifies that `pending_dependencies` must be added to the status enum (equivalent to `WorkItemStatus` in the workflow-engine). The current `WorkItemStatus` enum has nine values (backlog…failed) with no `pending_dependencies`. The dispatch-gating logic in `Source/Backend/src/routes/workflow.ts` references this concept via comments but cannot express the state in the type system. Items that are blocked cannot be typed correctly; the state machine transition table (`VALID_STATUS_TRANSITIONS`) does not include transitions to/from `pending_dependencies`.
- **Recommendation:** Add `PendingDependencies = 'pending-dependencies'` to `WorkItemStatus` and update `VALID_STATUS_TRANSITIONS` to allow `Approved → PendingDependencies` and `PendingDependencies → InProgress` (when blockers resolve). Add `// Verifies: FR-dependency-types`.
- **Cross-ref:** TheFixer (api-contract, backend-coder, frontend-coder — shared type change cascades)

## QO-006: `eslint-disable` suppression in production frontend hook
- **Severity:** P3
- **Category:** pattern-violation
- **File:** `Source/Frontend/src/hooks/useWorkItems.ts:63`
- **Detail:** `// eslint-disable-next-line react-hooks/exhaustive-deps` silences a lint rule rather than fixing the dependency array. The CLAUDE.md architecture rules require not suppressing linting rules except with explicit documented justification. A missing hook dependency can cause stale closure bugs where the hook holds a stale reference.
- **Recommendation:** Fix the dependency array to include all referenced values, or add an explicit comment explaining why the omission is intentional (e.g., "intentionally omitted to prevent infinite refetch loop — stable ref").
- **Cross-ref:** TheFixer (frontend-coder)
