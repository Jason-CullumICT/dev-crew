## Findings

### QO-001: Traceability Gate Has a Fatal Blind Spot — Picks One Plan Arbitrarily
- **Severity:** P1
- **Category:** spec-drift / tooling-defect
- **File:** `tools/traceability-enforcer.py:54` (`max(req_files, key=os.path.getmtime)`)
- **Detail:**  
  The enforcer resolves the "active" requirements file by picking the single most-recently-modified `requirements.md` under `Plans/`. In this repo all 8 requirements files share the same `mtime` (`Nov 2 09:15`), so `max()` picks one arbitrarily — currently `Plans/self-judging-workflow/requirements.md` (13 FRs, all traced). This means:
  - `Plans/dev-workflow-platform/requirements.md` (34 FRs) is **never checked** — all 34 are missing.
  - `Specifications/` is **never scanned** at all.
  - The verification gate reports `TRACEABILITY PASSED` while major specification areas are completely untraced.
  
  Running the enforcer manually against the dev-workflow-platform plan confirms the damage:
  ```
  TRACEABILITY FAILURE: 34 requirements lack implementation!
  [MISSING] FR-001 … FR-034
  ```
  
  The CLAUDE.md verification gate command is `python3 tools/traceability-enforcer.py` with no arguments, which hits this flaw every time.

- **Recommendation:**  
  Option A (preferred): Accept an optional `--all-plans` flag and iterate over every `requirements.md` under `Plans/`, failing if *any* has missing FRs. Mark superseded plans explicitly (e.g. `status: archived` in frontmatter) so they are skipped.  
  Option B: Accept a `--spec` flag to also scan `Specifications/*.md` for FR IDs and report those separately.  
  Option C: Change CLAUDE.md's verification gate command to always explicitly name the active plan (`--plan self-judging-workflow`).

- **Cross-ref:** QO-002 (the spec drift this gate fails to catch)

### QO-002: `Specifications/dev-workflow-platform.md` Describes an Unimplemented Application
- **Severity:** P1
- **Category:** spec-drift
- **File:** `Specifications/dev-workflow-platform.md` (69 FR IDs across lines 341–452)
- **Detail:**  
  `Specifications/dev-workflow-platform.md` defines 69 functional requirements (FR-001 through FR-069) for a **feature-request management platform** with entities `FeatureRequest`, `BugReport`, `DevelopmentCycle`, `Ticket`, `Vote`, `Learning`, `Feature`, backed by SQLite. The source code in `Source/` implements a completely different domain: a **self-judging WorkItem workflow engine** with an in-memory store.  

  Zero of the 69 FR IDs (`FR-001` … `FR-069`) appear anywhere in `Source/`. CLAUDE.md says "Specifications/ contains Domain truth" — either:
  - (A) The Specifications are stale and should be updated/archived to reflect the actual implementation, or

  There is no note in the spec, CLAUDE.md, or Plans/ indicating this spec was intentionally abandoned or deferred.

- **Recommendation:**  
  Determine canonical product direction with the team. If the WorkItem workflow is the product: archive or update `Specifications/dev-workflow-platform.md` (add `> Status: SUPERSEDED — see Specifications/workflow-engine.md` at the top). If both specs represent planned future work: create separate Plans for each and track them distinctly. Either way, the Specifications/ directory must not silently diverge from Source/.

### QO-003: Silent Error Swallow in Frontend API Client
- **Severity:** P2
- **Category:** pattern-violation
- **File:** `Source/Frontend/src/api/client.ts:26`
- **Detail:**  
  ```ts
  const body = await response.json().catch(() => ({}));
  ```  
  When a non-2xx response body cannot be parsed as JSON, the `.catch()` silently returns `{}`. The subsequent `body.message ?? ...` access produces `undefined`, and the thrown error falls back to `"Request failed: {status}"` — dropping the actual parse error with no log entry, no rethrow, and no documented suppression reason.  
  
  This violates CLAUDE.md: _"Never swallow errors silently — every catch block must either re-throw, log with full context, or explicitly document why the error is intentionally suppressed."_

- **Recommendation:**  
  ```ts
  let body: Record<string, unknown> = {};
  try {
    body = await response.json();
  } catch {
    // Non-JSON error body; fall back to status code message
  }
  ```  
  Or add a log call inside the catch so the parse failure is observable: `logger.warn('Failed to parse error response body', { status: response.status })`.

### QO-004: `eslint-disable` Suppressions Without Documented Rationale
- **Severity:** P2
- **Category:** pattern-violation
- **Files:**
  - `Source/Frontend/src/hooks/useWorkItems.ts:63`
  - `Source/Frontend/src/components/DependencyPicker.tsx:82`
- **Detail:**  
  Both files suppress `react-hooks/exhaustive-deps` with a bare `// eslint-disable-next-line` with no explanation. This is a lint bypass that hides potential stale-closure bugs. The CLAUDE.md does not explicitly list "no eslint-disable" but suppressing lint checks without rationale creates invisible technical debt and can mask subtle reactivity bugs.

- **Recommendation:**  
  Replace bare disable comments with a rationale:
  ```ts
  // eslint-disable-next-line react-hooks/exhaustive-deps
  // Intentional: filters are enumerated individually below to avoid
  // reference equality churn from the filters object identity.
  ```

### QO-005: Hardcoded `localhost` URL as Production Fallback
- **Severity:** P3
- **Category:** pattern-violation
- **File:** `Source/Frontend/src/pages/DebugPortalPage.tsx:5`
- **Detail:**  
  ```ts
  const portalUrl = import.meta.env.VITE_PORTAL_URL || 'http://localhost:4200';
  ```  
  The `|| 'http://localhost:4200'` fallback silently points to localhost in any environment where `VITE_PORTAL_URL` is not set (staging, CI, demo environments). No warning is emitted when the fallback is used.  
  
  `Source/Frontend/vite.config.ts:14` also has a hardcoded proxy target (`'http://localhost:3001'`) but that is a dev-server-only config and is acceptable.

- **Recommendation:**  
  Either fail loudly when the env var is missing in non-dev builds, or add a developer-facing comment:
  ```ts
  // VITE_PORTAL_URL must be set in non-local environments
  const portalUrl = import.meta.env.VITE_PORTAL_URL ?? 'http://localhost:4200';
  if (!import.meta.env.VITE_PORTAL_URL && import.meta.env.MODE !== 'development') {
    console.warn('[DebugPortalPage] VITE_PORTAL_URL not set; using localhost fallback');
  }
  ```
