## Critical Findings (P1 - P2)

### DEP-001: protobufjs — 12 Critical Code Injection & DoS Vulnerabilities
- **Severity:** P1 (Critical × 12)
- **Category:** CVE / Code Injection / RCE
- **Package:** `protobufjs` (affected: ≤7.6.4)
- **Location:** `portal/Backend/` (transitive via `@grpc/grpc-js` → OpenTelemetry exporters)
- **Direct Impact:** portal/Backend pulls in OpenTelemetry which depends on grpc-js which depends on protobufjs

**CVE List:**
- Code injection through bytes field defaults in generated toObject code
- Denial of service from crafted field names in generated code
- Prototype injection in generated message constructors
- Code generation gadget after prototype pollution
- Process-wide denial of service through unsafe option paths
- Denial of service through unbounded protobuf recursion
- Overlong UTF-8 decoding vulnerability
- Denial of Service via unbounded recursive JSON descriptor expansion
- Denial of service through unbounded Any expansion during JSON conversion
- Schema-derived names can shadow runtime-significant properties
- Denial of Service via infinite loop in .proto option parsing
- Arbitrary code execution issue

**Attack Vector:** Network — a malformed protobuf message or JSON descriptor can crash the process, trigger RCE, or cause unbounded memory exhaustion.

**Fix:** Update `@grpc/grpc-js` to ≥1.14.5, which uses a patched protobufjs. Verify OpenTelemetry exporter chain.

**Cross-ref:** [ESCALATE → TheGuardians] — Code injection is a critical security boundary violation.

### DEP-002: Handlebars.js — Multiple Template Injection & Prototype Pollution
- **Severity:** P1 (Critical × 8)
- **Category:** CVE / Template Injection / Prototype Pollution
- **Package:** `handlebars` (transitive via test tools)
- **Location:** `Source/Backend/` (transitive — likely via `create-jest` or similar)
- **Affected Versions:** All versions in current dependency chain

**CVE List:**
- JavaScript Injection via AST Type Confusion (bypass of @partial-block)
- JavaScript Injection via AST Type Confusion (general)
- Prototype Pollution Leading to XSS through Partial Template Injection
- Prototype Method Access Control Gap via Missing __lookupSetter__ Blocklist Entry
- Property Access Validation Bypass in container.lookup
- JavaScript Injection via AST Type Confusion when passing an object as dynamic partial
- Denial of Service via Malformed Decorator Syntax in Template Compilation

**Fix:** Update Handlebars to the latest version (likely ≥4.7.x). Check if it can be removed entirely if only used at build time.

**Cross-ref:** [ESCALATE → TheGuardians] if runtime processing exists.

### DEP-003: Tinypool — Prototype Pollution RCE (Via Vitest)
- **Severity:** P1 (Critical × 2)
- **Category:** CVE / Prototype Pollution / RCE
- **Package:** `tinypool` (transitive via vitest)
- **Location:** `Source/Frontend/` (via vitest dev dependency), `portal/Backend/` (via vitest)
- **Affected Versions:** tinypool used by vitest <4.1.11

**CVE Details:**

2. **Prototype Pollution Gadget to RCE in run() options** — The run() method is vulnerable to similar pollution leading to RCE.

**Attack Vector:** If Vitest is exposed to untrusted test input or if vitest UI server is running (see DEP-004), this allows code execution.

**Status:** This is a test-time dependency. Risk is reduced if vitest is only run in CI/developer environments with trusted inputs. **RISK ESCALATED if vitest UI is running in production or exposed to users.**

**Fix:** Update vitest to ≥2.1.0+, which uses a patched tinypool.

### DEP-005: proxy-addr — IPv4-Mapped IPv6 IP Spoofing
- **Severity:** P1 (Critical)
- **Category:** CVE / Access Control Bypass
- **Package:** `proxy-addr` (transitive via express + body-parser)
- **Location:** `Source/Backend/`, `platform/orchestrator/`, `portal/Backend/`
- **Affected Versions:** 1.1.0 - 2.0.7

**CVE Detail:** proxy-addr trusts the origin of requests based on IP address matching, but does not properly validate IPv4-mapped IPv6 addresses. This allows an attacker to spoof the X-Forwarded-For header and bypass IP-based access controls.

**Attack Vector:** If your backend relies on IP-based access control (e.g., trusting internal IPs for metrics endpoints, admin routes), an attacker can spoof the X-Forwarded-For header using IPv4-mapped IPv6 syntax (e.g., `::ffff:127.0.0.1`) to bypass authentication.

**Status:** **CRITICAL FOR THIS PROJECT** — The `/api/metrics` endpoint and admin routes must not rely solely on IP-based access control.

**Fix:** Update express and body-parser to latest versions where proxy-addr ≥2.0.8 is used. **Additionally, implement credential-based auth (API keys, JWT) for sensitive endpoints instead of IP whitelisting.**

**Cross-ref:** [CROSS-REF: red-teamer] — Verify metrics endpoint does not leak sensitive data when accessed via spoofed IPs.

## High-Severity Findings (P2)

### DEP-006: body-parser — Denial of Service via Invalid Limit Bypass
- **Severity:** P2 (High)
- **Category:** CVE / Denial of Service
- **Package:** `body-parser` (transitive via express)
- **Location:** `Source/Backend/` + all express-based projects
- **Affected Versions:** Various ranges in current dependency chain

**CVE Detail:** When an invalid limit value is passed to body-parser, it silently disables size enforcement, allowing unbounded request payloads that exhaust server memory.

**Attack Vector:** Attacker sends a request with an invalid Content-Length or other body size parameter, causing the server to accept unbounded payloads, leading to DoS.

**Status:** This affects all projects using express. Likely already mitigated by express defaults, but should be verified.

**Fix:** Ensure body-parser is configured with explicit, valid limits (e.g., `express.json({ limit: '10mb' })`). Update to latest version.

### DEP-010: js-yaml — Quadratic Complexity DoS in Merge Key Handling
- **Severity:** P2 (High)
- **Category:** CVE / Denial of Service
- **Package:** `js-yaml` (transitive)
- **Location:** `Source/Backend/`

**CVE Detail:** YAML merge key handling has quadratic complexity when processing repeated aliases, allowing an attacker to craft a YAML payload that causes exponential processing time.

**Attack Vector:** If YAML configuration is accepted from untrusted sources, a malicious YAML file with repeated merge keys causes CPU exhaustion (DoS).

**Status:** Used for config parsing. **VERIFY: Does the app accept YAML from untrusted sources?** If configs are static/admin-only, risk is lower.

**Fix:** Update to latest version. Validate YAML structure and size limits before parsing. Consider switching to JSON for untrusted input.

### DEP-011: @remix-run/router — Open Redirect via Protocol-Relative URLs
- **Severity:** P2 (Moderate, escalated to P2 due to direct impact)
- **Category:** CVE / Open Redirect
- **Package:** `@remix-run/router` (transitive via react-router-dom)
- **Location:** `Source/Frontend/`
- **Affected Versions:** 1.3.0 - 1.23.2

**CVE Detail:** React Router redirects to same-origin paths but does not block protocol-relative URLs (starting with `//`), allowing open redirects to external sites.

**Attack Vector:** Attacker crafts a malicious link like `//attacker.com/steal-token`, which redirects users to attacker's site while maintaining the same origin in the user's browser.

**Status:** Frontend-only issue. Impacts user authentication/session hijacking scenarios.

**Fix:** Update react-router-dom to ≥6.26.0+. Review all redirect() calls in routes to ensure user-supplied redirect targets are validated.

### DEP-014: uuid — Cryptographically Weak Random Number Generation
- **Severity:** P3 (Moderate)
- **Category:** CVE / Weak Randomness
- **Package:** `uuid` (direct dependency in Backend, Frontend, orchestrator)
- **Location:** Multiple projects

**CVE Detail:** uuid's Math.random()-based generation in certain configurations can produce predictable IDs due to weak PRNG seeding.

**Attack Vector:** If UUIDs are used for security tokens or secrets (rather than just identifiers), predictable UUIDs allow token forgery or session hijacking.

**Status:** **VERIFY: Are UUIDs used for security-sensitive purposes?** If only for work item IDs or request tracing, risk is low. If used for session tokens or secrets, risk is high.

**Fix:** Update uuid to latest. For security tokens, use `crypto.randomUUID()` or a CSPRNG library instead.

**Cross-ref:** [CROSS-REF: red-teamer] — Verify UUID usage is not for authentication/authorization.

## Learnings & Recommendations

### 1. Dependency Governance

- **Establish a policy:** No new dependencies without security review
- **Quarterly audits:** Run npm audit in CI/CD, fail on critical/high CVEs
- **Lock files:** Commit package-lock.json to ensure reproducible builds

### 2. Test Tool Isolation

- **Never expose vitest UI in production** or CI logs
- **Separate test dependencies** into devDependencies (already done, but enforce)
- **Consider lightweight testing:** The Vitest/Vitest mocker/tinypool chain is pulling in many CVEs; could simpler test runners suffice?

### 3. Express Configuration Hardening

- **Implement credential-based auth** (API keys, JWT) for sensitive routes (`/metrics`, admin endpoints)
- **Never rely solely on IP whitelisting** in front of proxy
- **Use middleware:** `express.json({ limit: '10mb' })` to enforce size limits

### 4. OpenTelemetry Cost-Benefit Analysis

- **portal/Backend's 577 dependencies are largely due to OpenTelemetry instrumentation**
- **Consider:** Is full auto-instrumentation worth the supply chain risk? Could you use a simpler tracer (e.g., Jaeger client) or remove instrumentation for non-critical components?

### 5. License Compliance

- **No GPL/AGPL dependencies detected** (good)
- **MIT, Apache 2.0 dominate** (safe)
- **One or two UNLICENSED packages detected** — verify these are internal or low-risk
