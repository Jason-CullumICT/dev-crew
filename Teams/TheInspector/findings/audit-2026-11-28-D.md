## Findings

### QO-001: Canonical specifications describe a completely different system than what is implemented
- **Severity:** P1
- **Category:** spec-drift
- **File:** `Specifications/dev-workflow-platform.md`
- **Detail:** `Specifications/dev-workflow-platform.md` defines 69 functional requirements (FR-001–FR-069) for a SQLite-backed platform with Feature Requests, Bug Reports, Development Cycles, Voting, Approvals, Learnings, Pipeline Orchestration, and a 9-page React frontend. The actual codebase implements a **Work Item workflow system** with an in-memory store — a completely different domain. Not a single one of FR-001–FR-069 is referenced anywhere in `Source/`. The implementation corresponds to `Plans/self-judging-workflow/requirements.md` (FR-WF-001..013), which is a plan-level document, not a canonical spec. CLAUDE.md says "Specifications are the most critical documents" and "implementation traces to specs, never the other way around."
- **Recommendation:** Either (a) update `Specifications/dev-workflow-platform.md` to describe the Work Item workflow system actually built, or (b) add a new canonical spec (`Specifications/work-item-workflow.md`) that formally replaces the old spec and cross-references the plan. Mark replaced specs as superseded. Do NOT leave orphaned specs with 69 FRs pointing at unbuilt systems.
- **Cross-ref:** TheFixer (spec authoring), requirements-reviewer

### QO-002: Traceability enforcer does not cover canonical Specifications/ — false green
- **Severity:** P2
- **Category:** spec-drift
- **File:** `tools/traceability-enforcer.py`
- **Detail:** The enforcer selects only the most recently modified `Plans/*/requirements.md` file (currently `Plans/self-judging-workflow/requirements.md`). It does NOT scan `Specifications/`. When run, it reports "TRACEABILITY PASSED" despite 69 canonical spec FRs having zero source coverage. CLAUDE.md lists `python3 tools/traceability-enforcer.py` as a mandatory verification gate — agents trust this gate and believe traceability is complete.
- **Recommendation:** Extend the enforcer to also scan all `Specifications/*.md` files for FR IDs, then verify each has a `// Verifies: FR-XXX` comment in `Source/`. Add a `--specs` flag or run both passes. Until `Specifications/dev-workflow-platform.md` is updated per QO-001, suppress or exclude it explicitly (not silently) so the gate remains honest.
- **Cross-ref:** QO-001

### QO-008: `eslint-disable` suppressing hook dependency warnings in production source
- **Severity:** P3
- **Category:** pattern-violation
- **Files:**
  - `Source/Frontend/src/components/DependencyPicker.tsx:82`
  - `Source/Frontend/src/hooks/useWorkItems.ts:63`
- **Detail:** Both suppress `react-hooks/exhaustive-deps`. Missing exhaustive deps in `useEffect` / `useCallback` can cause stale closure bugs where component logic reads outdated state. The correct fix is to stabilize the dependency (e.g., `useCallback` on callbacks, `useMemo` on derived values) rather than suppressing the lint rule.
- **Recommendation:** Audit each suppression — verify whether the omitted dep is intentional (stable ref) or a latent stale-closure bug. If intentional, add a one-line comment explaining why. If not intentional, fix the dep array.

### QO-009: Hardcoded fallback `localhost:4200` in production source
- **Severity:** P3
- **Category:** pattern-violation
- **File:** `Source/Frontend/src/pages/DebugPortalPage.tsx:5`
- **Detail:** `const portalUrl = import.meta.env.VITE_PORTAL_URL || 'http://localhost:4200';` — Architecture rule: *"No hardcoded secrets — use environment variables via `.env`."* While this is a URL not a secret, hardcoded localhost fallbacks in production source will silently point at nothing in non-dev environments and are an architecture rule violation. The env var is correct; the fallback is the problem.
- **Recommendation:** Remove the hardcoded fallback or move it to `.env.development` only. If the portal is dev-only, guard the route with `if (import.meta.env.DEV)`.
