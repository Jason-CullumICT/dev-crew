## Critical Findings (P1)

### DEP-001: Handlebars.js JavaScript Injection Vulnerabilities
- **Severity:** P1 (Critical)
- **Category:** CVE / RCE Risk
- **Affected Package:** `handlebars` @ 4.0.0 - 4.7.8
- **Location:** Source/Backend (transitive via ts-jest)
- **CVE IDs:** 
  - GHSA-2w6w-674q-4c4q (CVSS 9.8 - Critical)
  - GHSA-3mfm-83xf-c92r (CVSS 8.1 - High)
  - GHSA-xhpv-hc6g-r9c6 (CVSS 8.1 - High)
  - GHSA-9cx6-37pm-9jff (CVSS 7.5 - High)
  - GHSA-xjpj-3mr7-gcpf (CVSS 8.2 - High)
  - Plus 3 additional moderate/low severity issues

**Technical Details:**
Handlebars.js versions 4.0.0-4.7.8 are vulnerable to multiple JavaScript injection attacks:
1. **AST Type Confusion** - Attackers can exploit type confusion to inject and execute arbitrary JavaScript code via template compilation
2. **Prototype Pollution via Partial Injection** - Malformed partial templates can pollute object prototypes, leading to XSS
3. **Property Access Bypass** - `__lookupSetter__` and `container.lookup` methods not properly blocked
4. **DoS via Malformed Decorators** - Specially crafted decorator syntax causes template compilation to hang indefinitely

**Dependency Chain:**
```
Backend (package.json)
  ├─ ts-jest@^29.1.2 [test runner]
      └─ handlebars@^4.7.8 [vulnerable]
```

**Impact:** If handlebars templates are compiled from user-controlled input, attackers can execute arbitrary code. **Even in test-only contexts**, if templates are processed from external sources or untrusted data, RCE is possible.

**Remediation:**
```bash
cd Source/Backend
npm update ts-jest handlebars
# Expected: ts-jest >= 29.1.3+, handlebars >= 4.7.9
```

**Additional Notes:**
- This is a transitive dependency but carries critical risk
- Handlebars is only used in testing (ts-jest), but should be upgraded anyway for supply chain hygiene
- [CROSS-REF: red-teamer] - If any dynamic template compilation occurs in tests or tooling, this is exploitable

## High-Priority Findings (P2)

### DEP-002: brace-expansion DoS Vulnerability
- **Severity:** P2 (Medium/High Impact)
- **Category:** CVE / DoS
- **Affected Package:** `brace-expansion` < 1.1.13
- **Location:** Source/Backend (transitive via glob/jest)
- **CVE ID:** GHSA-f886-m6hf-6m8v
- **CVSS Score:** 6.5 (Moderate)

**Technical Details:**
Zero-step sequences in brace expansion (e.g., `{1..0}`) cause the parser to enter an infinite loop, exhausting memory and hanging the process.

**Example Attack:**
```javascript
// Input: '{1..0}' or similar
// Result: Process hangs, memory grows unbounded
```

**Dependency Chain:**
```
Backend
  ├─ jest@^29.7.0
      └─ glob (or similar path resolution)
          └─ brace-expansion [vulnerable]
```

**Impact:** Test runner could hang indefinitely if processing file paths with malformed glob patterns.

**Remediation:**
```bash
cd Source/Backend
npm update brace-expansion
# Expected: brace-expansion >= 1.1.13
```

## Medium-Priority Findings (P3)

### DEP-003: Vite & Vitest Build Tool Vulnerabilities
- **Severity:** P3 (Moderate - Dev-only, not shipped)
- **Category:** CVE / Multiple
- **Affected Packages:** 
  - `vite` <= 6.4.1 (Path Traversal)
  - `vitest` <= 3.0.0-beta.4 (via vite, esbuild)
  - `esbuild` <= 0.24.2 (CORS bypass)
  - `postcss` < 8.5.10 (XSS via style tag)
  - `@vitest/mocker`, `vite-node` (transitive)

**Location:** Source/Frontend (dev dependencies)

**Details:**
| Package | CVE | Severity | Description |
|---------|-----|----------|-------------|
| vite | GHSA-4w7w-66w2-5vf9 | Moderate | Path traversal in .map file handling |
| esbuild | GHSA-67mh-4wv8-2f99 | Moderate | Dev server CORS allows reading response from arbitrary requests |
| postcss | GHSA-qx2v-qp2m-jg93 | Moderate | Unescaped `</style>` in CSS output can break out of style context |

**Impact:** These affect the **development/build process only** and are not shipped to production. However, they could be exploited if:
- An attacker compromises the build server
- A developer uses a malicious dependency in their project
- Source maps are exposed and contain sensitive paths

**Remediation:**
```bash
cd Source/Frontend
npm update vite vitest
# Expected: vite >= 8.0.11, vitest >= 4.1.5 (major version bump required)
```

**Note:** Vitest update requires vite major version bump (5.x → 8.x) — test compatibility before upgrading.
