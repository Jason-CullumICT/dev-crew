## Critical Findings (P1)

### DEP-001: Handlebars.js Multiple RCE/Injection Vulnerabilities
- **Severity:** P1 (CRITICAL)
- **Category:** cve, code-injection, template-injection
- **Package:** `handlebars` (transitive, in `Source/Backend`)
- **Affected Versions:** `4.0.0 - 4.7.8`
- **Location:** `Source/Backend/package.json` (indirect dependency)
- **CVEs:**
  - **GHSA-2w6w-674q-4c4q** — JavaScript Injection via AST Type Confusion (CVSS 9.8)
  - **GHSA-3mfm-83xf-c92r** — JavaScript Injection via AST Type Confusion by tampering @partial-block (CVSS 8.1)
  - **GHSA-xhpv-hc6g-r9c6** — JavaScript Injection via dynamic partial (CVSS 8.1)
  - **GHSA-9cx6-37pm-9jff** — DoS via Malformed Decorator Syntax (CVSS 7.5)
  - **GHSA-xjpj-3mr7-gcpf** — JavaScript Injection in CLI Precompiler (CVSS 8.2)
  - **GHSA-2qvq-rjwj-gvw9** — Prototype Pollution → XSS (CVSS 4.7)
  - **GHSA-7rx3-28cr-v5wh** — Prototype Method Access Control Gap (CVSS 4.8)
  - **GHSA-442j-39wm-28r2** — Property Access Validation Bypass (CVSS 3.7)

**Attack Vector:** Attacker-controlled template input can execute arbitrary code on the server.

**Impact:** Remote Code Execution. An unauthenticated attacker can execute arbitrary code by submitting a malicious Handlebars template.

**Root Cause:** Handlebars does not properly sanitize the `@partial-block` directive and other AST nodes, allowing injection of arbitrary JavaScript during template compilation.

**Fix:** 
```bash
cd Source/Backend && npm update handlebars
# This should bump to 4.7.9+
```

**Verification:** After upgrade, confirm version is >=4.7.9:
```bash
npm ls handlebars
```

**Cross-ref:** [ESCALATE → TheGuardians] — This is a critical RCE. If Backend templates accept untrusted input (e.g., from external systems or user uploads), this is **actively exploitable**.

### DEP-002: protobufjs Arbitrary Code Execution
- **Severity:** P1 (CRITICAL)
- **Category:** cve, code-injection, prototype-pollution
- **Package:** `protobufjs` (transitive, in `platform/orchestrator`)
- **Affected Versions:** `<= 7.5.7`
- **Location:** `platform/orchestrator/package.json` (indirect, pulled in via dependencies)
- **Primary CVE:**
  - **GHSA-xq3m-2v4x-88gg** — Arbitrary code execution in protobufjs (CVSS 9.8)

**Secondary CVEs:**
  - **GHSA-75px-5xx7-5xc7** — Code generation gadget after prototype pollution (CVSS 8.1)
  - **GHSA-685m-2w69-288q** — Unbounded protobuf recursion DoS (CVSS 7.5)
  - **GHSA-jvwf-75h9-cwgg** — Process-wide DoS via unsafe option paths (CVSS 7.5)
  - **GHSA-66ff-xgx4-vchm** — Code injection via bytes field defaults (CVSS unknown)
  - **GHSA-2pr8-phx7-x9h3** — DoS from crafted field names (CVSS 5.3)
  - **GHSA-fx83-v9x8-x52w** — Prototype injection in constructors (CVSS 5.3)
  - **GHSA-jggg-4jg4-v7c6** — Unbounded recursive JSON descriptor expansion (CVSS 5.3)
  - **GHSA-q6x5-8v7m-xcrf** — Overlong UTF-8 decoding (CVSS 5.3)

**Attack Vector:** Attacker sends crafted protobuf message or JSON descriptor that triggers prototype pollution, allowing arbitrary code generation and execution.

**Impact:** Remote Code Execution. Any service accepting protobuf or JSON schema input is vulnerable.

**Root Cause:** protobufjs does not validate prototype keys during deserialization or code generation, allowing pollution of `Object.prototype` and gadget chaining to RCE.

**Fix:**
```bash
cd platform/orchestrator && npm update protobufjs
# This should bump to >=7.5.8 or later
```

**Verification:** After upgrade, confirm version is >=7.5.8:
```bash
npm ls protobufjs
```

**Cross-ref:** [ESCALATE → TheGuardians] — CRITICAL: The orchestrator likely processes messages from external systems (work items, assessments). Any untrusted input triggers this RCE.

- **CVE:** **GHSA-37ch-88jc-xwx2** (CVSS 7.5)
