## Detailed Findings

### DEP-001: Handlebars JavaScript Injection (CRITICAL)
- **Severity**: P1 / CRITICAL
- **Category**: CVE / Production Risk
- **Package**: `handlebars@4.7.8`
- **File**: `Source/Backend/package-lock.json`
- **CVSS**: 9.8 (Network, Low Complexity, No User Interaction)
- **CVE IDs**: 
  - GHSA-2w6w-674q-4c4q — JS injection via AST type confusion
  - GHSA-3mfm-83xf-c92r — JS injection via @partial-block tampering
  - GHSA-xhpv-hc6g-r9c6 — JS injection via dynamic partial
  - GHSA-9cx6-37pm-9jff — DoS via malformed decorator syntax
  - GHSA-2qvq-rjwj-gvw9 — Prototype pollution leading to XSS
  - GHSA-7rx3-28cr-v5wh — Prototype method access gap
  - GHSA-442j-39wm-28r2 — Property access validation bypass
  - GHSA-xjpj-3mr7-gcpf — JS injection in CLI precompiler

**Root Cause**:  
`jest` → `ts-jest` → `handlebars@4.0.0-4.7.8` (template engine for test output/snapshots)

**Impact**:  
Arbitrary JavaScript execution during test compilation if test data contains crafted templates. Affects all test execution pipelines.

**Fix**:
```bash
# Option 1: Upgrade jest (includes newer handlebars)
cd Source/Backend
npm install jest@30+ ts-jest@latest --save-dev

# Option 2: Switch to vitest (already used in Source/Frontend — recommended for consistency)
# Replace jest with vitest across the backend
```

**Timeline**: Immediate (this sprint)

**Cross-Ref**: [ESCALATE → TheGuardians] if tests process untrusted template data

### DEP-002: Protobufjs Arbitrary Code Execution (CRITICAL)
- **Severity**: P1 / CRITICAL
- **Category**: CVE / Production Risk
- **Package**: `protobufjs@7.5.5`
- **Files**: 
  - `portal/Backend/package-lock.json`
  - `platform/orchestrator/package-lock.json`
- **CVSS**: 9.8 (Network, Low Complexity, No User Interaction)
- **CVE IDs**:
  - GHSA-xq3m-2v4x-88gg — Arbitrary code execution
  - GHSA-66ff-xgx4-vchm — Code injection via bytes field defaults
  - GHSA-75px-5xx7-5xc7 — Code generation gadget post-prototype-pollution
  - GHSA-685m-2w69-288q — Unbounded recursion DoS
  - GHSA-jvwf-75h9-cwgg — Process-wide DoS via option paths
  - GHSA-2pr8-phx7-x9h3 — DoS from crafted field names
  - GHSA-fx83-v9x8-x52w — Prototype injection
  - GHSA-q6x5-8v7m-xcrf — Overlong UTF-8 decoding

**Root Cause**:  
`@opentelemetry/exporter-trace-otlp-http@0.47.0` → `protobufjs@<=7.5.5`

The OpenTelemetry tracing pipeline uses protobuf serialization. Crafted OTLP trace data could trigger code execution in the exporter.

**Current Versions**:
- `@opentelemetry/auto-instrumentations-node@0.40.0` (need: 0.75.0+)
- `@opentelemetry/sdk-node@0.47.0` (need: 0.217.0+)
- `@opentelemetry/exporter-trace-otlp-http@0.47.0` (need: 0.218.0+)

**Impact**:  
Remote code execution if any telemetry endpoint is exposed or accepts crafted protobuf payloads. Affects Portal backend observability infrastructure.

**Fix**:
```bash
cd portal/Backend
npm install @opentelemetry/auto-instrumentations-node@0.75.0+ \
            @opentelemetry/sdk-node@0.217.0+ \
            @opentelemetry/exporter-trace-otlp-http@0.218.0+ --save
```

**Verification**: After update, confirm `npm audit` shows zero protobufjs vulnerabilities.

**Timeline**: Immediate (this sprint) — blocks any production deployment

**Cross-Ref**: [ESCALATE → TheGuardians] for exploitability assessment in telemetry pipeline

### DEP-004: path-to-regexp ReDoS (HIGH)
- **Severity**: P2 / HIGH
- **Category**: CVE / DoS
- **Package**: `path-to-regexp@<0.1.13`
- **Files**: 
  - `portal/Backend/package-lock.json`
  - `platform/orchestrator/package-lock.json`
- **CVSS**: 7.5 (Network, Low Complexity, No Auth)
- **CVE ID**: GHSA-37ch-88jc-xwx2 — ReDoS via multiple route parameters

**Detail**:  
Express routing uses path-to-regexp to match URL patterns. A malicious URL with many parameters can cause catastrophic backtracking (ReDoS), consuming CPU and blocking other requests.

**Example Attack**:
```
GET /api/users/:id/:name/:email/:phone/:address/:city/:state/:zip?x=a;x=b;x=c;...
```

**Impact**:  
Application DoS via URL-based ReDoS. Affects any Express-based service (backend, orchestrator).

**Fix**:
```bash
# Upgrade express (pins path-to-regexp internally)
npm install express@4.22.2+ --save
```

**Timeline**: Sprint 2 (less urgent than protobufjs/handlebars, but before production)

### DEP-008: brace-expansion Memory Exhaustion (MODERATE)
- **Severity**: P3 / MODERATE
- **Category**: CVE / DoS
- **Package**: `brace-expansion@<1.1.13`
- **File**: `Source/Backend/package-lock.json`
- **CVSS**: 6.5 (Network, Low Complexity, User Interaction)
- **CVE ID**: GHSA-f886-m6hf-6m8v — Zero-step sequence causes hang

**Detail**:  
Brace expansion (e.g., `{1..1000000}`) with invalid ranges causes unbounded memory allocation. If app processes user-supplied glob patterns, attacker can crash it.

**Impact**:  
Low in this codebase (backend doesn't parse user globs). Transitive via jest internals.

**Fix**: Bundled with jest upgrade (DEP-001)
