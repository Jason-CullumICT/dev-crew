## Audit: 2026-08-12 (First Run)

### Spec Coverage Trend
- **Self-judging-workflow plan** (Plans/self-judging-workflow/requirements.md): **100%** — all 13 FR-WF-* IDs traced in Source/
- **Domain spec** (Specifications/dev-workflow-platform.md, FR-001 to FR-069): **0%** in Source/ — implemented in `portal/`, not `Source/`
- **Tiered-merge-pipeline spec** (Specifications/tiered-merge-pipeline.md, FR-TMP-001 to FR-TMP-010): **0%** in Source/ — implemented in `platform/`, not `Source/`
- **Overall Source/ coverage against ALL canonical specs**: essentially 0% unless scoped to plan-level requirements

### Key Structural Discovery
The repo contains THREE separate codebases with different requirement ID namespaces:
1. `platform/` — implements FR-TMP-* (tiered merge pipeline, orchestrator)
2. `portal/` — implements FR-001...FR-069 (old product: feature requests, bugs, cycles via SQLite)  
3. `Source/` — implements FR-WF-* (new product: self-judging workflow engine, in-memory store)

The traceability enforcer (`tools/traceability-enforcer.py`) only checks `Source/` and `E2E/`, and only against one plan at a time. It has no awareness of `platform/` or `portal/`.

### Critical Enforcer Limitation (P1)
The enforcer picks the **most recently modified** `requirements.md` automatically. With 8 plan requirements files, only the self-judging-workflow plan (13 IDs) gets checked at a given run. The dev-workflow-platform plan has 103 FRs — all silently unchecked. Fix: enforce all plans with active requirements, or use `--plan` flag explicitly for each active plan.

### Architecture Violations Found
- **Direct store access from route handlers**: `workItems.ts`, `intake.ts`, `workflow.ts` all call `store.*` directly. Architecture rule requires a service layer. Affects 3 route files.
- **Logger not environment-aware**: `utils/logger.ts` always emits JSON; CLAUDE.md requires pretty-printing in development.
- **No OpenTelemetry**: FR-WF-013 and CLAUDE.md require OTel tracing; no `@opentelemetry` packages exist in package.json.

### False Positives to Watch For
- `grep -rn "\.skip\|xit"` matches the word "complexity" (xit substring) — use `xtest(\|xit(\|xdescribe\|\.skip` with word boundaries
- `Plans/dependency-linking/requirements.md` references `FR-0002`, `FR-0003` etc. as work item IDs in acceptance criteria — not requirement IDs; enforcer picks these up as false MISSING requirements
