### QO-001: Route Handlers Import Store Directly — Architecture Violation

- **Severity:** P2
- **Category:** architecture-violation
- **Files:**
  - `Source/Backend/src/routes/workItems.ts:12` — `import * as store from '../store/workItemStore'`
  - `Source/Backend/src/routes/intake.ts:4` — `import * as store from '../store/workItemStore'`
  - `Source/Backend/src/routes/workflow.ts:15` — `import * as store from '../store/workItemStore'`
- **Detail:** CLAUDE.md states: _"No direct DB calls from route handlers — use the service layer."_ All three route handlers bypass this rule by importing the store directly. While the store is in-memory (not a DB), the architectural principle is identical: route handlers should only talk to service functions, not the persistence layer. This makes it impossible to add cross-cutting concerns (caching, auth checks, event emission) to the service layer without also changing routes, and makes unit testing harder.
- **Recommendation:** Create a `workItemService.ts` that wraps store calls (similar to how `routeWorkItem`, `assessWorkItem`, etc. are already in `services/`). Have routes import from the service, not the store.
- **Cross-ref:** TheFixer — straightforward refactor

### QO-002: Missing `dependencyCheckDuration` Histogram — Incomplete FR-dependency-metrics

- **Severity:** P2
- **Category:** spec-drift
- **File:** `Source/Backend/src/metrics.ts`
- **Detail:** `FR-dependency-metrics` specifies 4 metrics:
  - `dependencyOperations` counter ✅
  - `dispatchGatingEvents` counter ✅
  - **`dependencyCheckDuration` histogram** ❌ — not implemented
  - `cycleDetectionEvents` counter ✅

  The histogram is missing entirely. Without it there is no latency visibility on dependency readiness checks, which the config flags as a critical-path operation (`/api/{type}/:id/ready`).
- **Recommendation:** Add a `prom-client` `Histogram` named `dependency_check_duration_seconds` with a label for `operation` (e.g., `cycle_detection`, `ready_check`). Instrument `detectCycle()` and `isReady()` in `services/dependency.ts`.

### QO-005: Fast-Track Criteria — Improvement Heuristic Deviates from Spec

- **Severity:** P2
- **Category:** spec-drift
- **File:** `Source/Backend/src/services/router.ts:24-32`
- **Detail:** `Specifications/workflow-engine.md` defines fast-track criterion: _"Type is `improvement` AND estimated change is < 3 files."_ The implementation uses complexity as a proxy (`trivial` or `small` complexity → fast-track), with an inline comment acknowledging "heuristic: trivial/small complexity." No file-count estimation is performed. While pragmatic, this is an undocumented deviation from the domain spec — the spec says < 3 files, the code says trivial/small complexity. These are not equivalent: a trivial-complexity improvement could touch 5 files; a 1-file improvement could have medium complexity.
- **Recommendation:** Either update `workflow-engine.md` to formally document the complexity-based heuristic as the accepted interpretation, or implement an optional `estimatedFiles` field on `WorkItem` to honor the spec literally. The spec change is lower cost.
- **Cross-ref:** requirements-reviewer to update spec if heuristic is intentional

### QO-006: Duplicate Logger Implementation — Technical Debt

- **Severity:** P3
- **Category:** pattern-violation
- **Files:**
  - `Source/Backend/src/logger.ts` — compatibility shim (`default export`)
  - `Source/Backend/src/utils/logger.ts` — actual logger implementation
- **Detail:** Two logger files exist with overlapping function. `logger.ts` is a compat shim wrapping `utils/logger.ts` to provide a `default export` because different pipeline agents wrote imports differently. This double-wrapping adds unnecessary complexity: `normalize()` adapts the interface on every call, and `structuredLogger.debug` is called through two layers. The comment reveals this was a workaround for agent import-path divergence, not intentional design.
- **Recommendation:** Canonicalize on one export shape in `utils/logger.ts` (add `export default logger`) and delete `logger.ts`. Update all imports to `'../utils/logger'`.
- **Cross-ref:** TheFixer
